flx is the command-line interface for working with FLX projects and individual runtime runs. The CLI operates on the project; its execution options do not redefine the persistent configuration of the manifest, Machine or compiled file.

Syntax and implicit execution

General form
flx [command] [options...] [target]

flx
flx .
flx project.flx

The default command is run and the default target is ., the current directory. The first two forms run the project in the current directory; the third uses the specified manifest. A first argument that exists as a path or ends in .flx is interpreted as the target of run, unless it is a recognized command name.

The examples place options before the target. Use = for the values of the long options shown here; --output also accepts a separate argument. Paths containing spaces must be quoted. Only one target is supported, and execution, output or format options cannot be repeated.

Project resolution

Targets for run, validate and compile
target
├── .flx file → use it
└── directory
    ├── project.flx → use it with priority
    └── no project.flx
        ├── a single *.flx → use it
        ├── none → error
        └── multiple → ambiguity error

The candidate search only scans the directory's first level. The .flx extension is compared case-insensitively. A nonexistent target, a file of another type or an ambiguous directory produces a resolution error; a candidate is not chosen arbitrarily. Priority goes to the name project.flx looked up in the filesystem.

v0.3.0 commands

Available operations
CommandResult
runCompiles the project and runs it with Engine.
validateValidates through compilation, without running or writing a .flxc.
compileWrites the project's compiled representation.
run-compiledLoads and runs a .flxc.
versionDisplays the version.
helpDisplays general or command-specific help.

build is reserved for future work and is not an operational command in v0.3.0.

run

Running from sources
flx run --frames=120 --scale=2 .

Resolves the manifest and compiles the project. Runs it with Engine only if compilation succeeds. The following options also apply to run-compiled.

Execution options
OptionValues / defaultEffect
--frames=<positive-integer>Positive integer. Omitted: no CLI frame limit.Limits frames for this run. Zero, negative numbers, text and values outside the supported integer range are invalid.
--window-mode=<window|fullscreen>Omitted: runtime's default window mode.Selects windowed or fullscreen mode for this run.
--scale=<positive-integer>Positive integer. Omitted: Machine scale.Overrides video.output.scale for this run. Does not modify Machine or the .flxc.
--debug-logs[=<true|false>]false by default.Controls generation of internal debug logs.
--debug-console[=<true|false>]false by default.Controls console output of runtime logs.
--debug-collisions[=<true|false>]false by default.Controls debug collision drawing.

The three booleans without a value are equivalent to true; explicit values are exactly true or false. --debug-logs and --debug-console control different aspects: generating logs and sending them to the console. See Machine · Video for persistent output configuration.

validate

Validation without execution
flx validate .
flx validate --format=json project.flx

Resolves the project and performs the compilation/validation available in v0.3.0. Does not start the runtime or generate .flxc. Supports --format=text and --format=json. Successful validation returns 0 and may include warnings; it does not guarantee that every subsequent run will succeed.

compile

Explicit output required
flx compile --output=game.flxc .
flx compile -o game.flxc project.flx
flx compile --format=json --output=game.flxc .

Generates the compiled representation of the FLX project. Output is required: use --output=<path>, --output <path> or -o <path>. There is no automatic output name. The CLI writes to the specified path; use the .flxc extension so it can be run with run-compiled.

Supports the text or json format. A .flxc is a compiled project; the future distributable product from build is outside this operation's scope.

run-compiled

Compiled execution
flx run-compiled --frames=120 game.flxc

Reads an already compiled project and runs it with Engine. The target must have the .flxc extension, compared case-insensitively. Supports the same six run execution options. An incorrect extension is an argument error (2); an unreadable or invalid compiled file produces 5.

version

Equivalent forms
flx version
flx --version
flx -v

Writes only the semantic version to stdout and exits with 0, without opening a project or starting Engine. Does not accept a target or format options.

help

General and specific help
flx help
flx --help
flx -h
flx help run
flx run --help

Command-specific help supports run, compile, run-compiled, validate and version. It also supports flx <command> --help or -h, with no subsequent arguments; for example, flx compile --help. flx --help run and flx help help are not valid forms.

Output format

--format=<text|json> is only available for compile and validate; the default value is text. run and run-compiled reject this option, including with the value text. The CLI does not offer JSON runtime output in v0.3.0.

In text mode, normal output goes to stdout and diagnostics to stderr. In JSON, the structured result combines both in stdout. For automation, place --format=json immediately after compile or validate: an argument error before that option is recognized is still reported as text. See Diagnostics · JSON output.

Exit codes

Defined codes and current usage
CodeNamev0.3.0 contract
0SuccessSuccessful operation; warnings may be present.
1InternalErrorCode defined for internal errors; should not be interpreted as the universal destination for any failure.
2InvalidArgumentsInvalid command, option or arguments.
3ProjectResolutionErrorCannot resolve the project manifest.
4CompilationErrorCompilation/validation failure or failure to write the compiled project.
5InvalidCompiledProjectFailure to read or validate a compiled project.
6RuntimeInitializationErrorrun and run-compiled currently return this code for any failed EngineResult.
7RuntimeExecutionErrorDefined; current commands do not distinguish Engine failures using this code.
8BuildErrorDefined; build is not available as an operational command.

The exit code expresses the overall category. The diagnostics describe what happened and where. Do not infer the specific cause from the exit number alone.
