Objeto JSON

Un Object es una declaración de un elemento del World. Puede combinar representación, movimiento, colisiones, comportamiento, estado, audio y children. Ninguna propiedad raíz es obligatoria por sí sola; un objeto vacío es válido según el schema.

Objeto mínimo visible
{
  "origin": {
    "x": 160,
    "y": 90
  },
  "size": {
    "width": 18,
    "height": 24
  },
  "visual": {
    "color": "white",
    "representation": [
      {
        "primitive": "triangle"
      }
    ]
  }
}

Propiedades raíz

El schema raíz tiene additionalProperties: false. Las únicas propiedades admitidas son las siguientes; las claves de los mapas nombrados se definen dentro de cada bloque.

  • $schema: string; metadato de validación.
  • like: string; composición desde una base.
  • spawn: auto o manual.
  • component: boolean; integra el child en la entidad lógica de su parent.
  • creation: objeto o referencia; materialización de children.
  • offset: objeto; desplazamiento de creación.
  • visible: boolean; visibilidad inicial.
  • attach: objeto; seguimiento del parent.
  • origin: objeto; posición inicial.
  • size: objeto; tamaño lógico.
  • visual: objeto o referencia; representación.
  • mechanics: objeto o referencia; movimiento y rotación.
  • inherit: objeto o referencia; herencia de movimiento y orientación desde el parent.
  • bounds: objeto o referencia; límites del World.
  • delimit: boolean; extensión lógica del World.
  • group: string; grupo lógico.
  • control: objeto; jugador asociado.
  • local: mapa; valores iniciales de instancia.
  • collisions: mapa o referencia; colliders nombrados.
  • behavior: objeto o referencia; scripts.
  • states: objeto o referencia; estados y transiciones.
  • sounds: mapa; sonidos nombrados.
  • music: mapa; música nombrada.
  • children: mapa; declaraciones de hijos.

$schema

String opcional que identifica el schema para herramientas de validación. No selecciona la versión del motor ni cambia los defaults del objeto.

$schema
{
  "$schema": "https://flxforge.github.io/FLXEngine/schemas/object.schema.json"
}

origin

Objeto opcional con coordenadas numéricas x e y; cada eje omitido vale 0. X crece hacia la derecha e Y hacia abajo. Es la posición del objeto, no la esquina de su caja lógica. En los children, las reglas de Creation determinan cómo se obtiene la posición inicial a partir del parent, origin, offset y el modo de creación.

origin
{
  "origin": {
    "x": 160,
    "y": 90
  }
}

size

Objeto opcional con width y height numéricos, ambos obligatorios cuando aparece. Define el tamaño lógico; no se calcula automáticamente desde el dibujo. Sin size no hay tamaño lógico declarado. Las primitivas visuales y los colliders pueden aportar su propio tamaño. El schema de Object no impone un mínimo positivo, pero un collider necesita dimensiones efectivas positivas.

size
{
  "size": {
    "width": 32,
    "height": 16
  }
}

Véanse tamaño de representación y tamaño de collider.

visible

Boolean opcional; default del runtime: true. Controla la presentación visual inicial. Ocultar el objeto no equivale a eliminarlo ni deshabilita por sí solo sus colliders.

visible
{
  "visible": false
}

group

String opcional; por defecto no hay grupo asignado (cadena vacía). Clasifica el objeto para filtros de colisión y consultas. collisions.<id>.with contiene los nombres de grupo que un collider consulta activamente.

group
{
  "group": "enemy"
}

control

  • player — integer ≥ 1. Opcional; sin asociación si se omite. Asocia el objeto con un jugador para las consultas de input que reciben un objeto. No declara acciones ni capacidades de la Machine.
control
{
  "control": {
    "player": 1
  }
}

local

Mapa opcional de valores string, number o boolean. Inicializa el estado propio de cada instancia; sin el bloque, el mapa está vacío. No admite objetos, arrays ni null.

local
{
  "local": {
    "lives": 3,
    "ready": true,
    "label": "player"
  }
}

behavior

Objeto o referencia de bloque. Si se declara inline, scripts es obligatorio: array de strings con rutas de scripts JavaScript. Sin behavior no se asocian scripts; scripts: [] es válido. Las rutas relativas se resuelven desde el archivo de origen que el cargador conserva para el comportamiento; .js es opcional.

behavior
{
  "behavior": {
    "scripts": [
      "player"
    ]
  }
}

El archivo del ejemplo es player.js. Los callbacks y funciones se documentan en Scripting y FLX API.

states

Objeto o referencia de bloque. Declara una máquina de estados ligera. initial es un string no vacío obligatorio y debe nombrar un estado declarado. Cada otra clave nombra un estado cuyo valor es un objeto con un único campo opcional, next: array de nombres no vacíos, únicos y declarados en el mismo bloque. Sin next, no hay destinos declarados desde ese estado. Sin states, el objeto no declara máquina de estados propia.

states
{
  "states": {
    "initial": "idle",
    "idle": {
      "next": [
        "active"
      ]
    },
    "active": {
      "next": [
        "idle"
      ]
    }
  }
}

Un component sin máquina propia puede utilizar el estado efectivo de su cadena de parents. Los filtros de collider.states consultan ese estado efectivo.

bounds

Objeto o referencia de bloque. Define el comportamiento al cruzar la extensión lógica del World.

  • mode — string: none | wrap. Default: none. none no aplica envoltura; wrap lleva el objeto al lado opuesto.
  • overflow — boolean. Default: false. Con wrap, controla la presentación del objeto al atravesar los bordes; true habilita las copias visuales de continuidad.
bounds
{
  "bounds": {
    "mode": "wrap",
    "overflow": true
  }
}

Los límites proceden de delimit, no del tamaño de la pantalla.

delimit

Boolean opcional; default: false. Con true, aporta su posición y tamaño lógico a la extensión del World durante la carga. Con tamaño, aporta el rectángulo centrado en su posición; sin tamaño, un punto. La envolvente final debe tener anchura y altura positivas: un único punto no basta.

delimit
{
  "origin": {
    "x": 160,
    "y": 90
  },
  "size": {
    "width": 320,
    "height": 180
  },
  "delimit": true
}

La extensión se calcula durante la carga a partir de los objetos delimit materializados en esa fase. Una vez fijada, movimiento, resize e instancias creadas posteriormente no la recalculan. Si no hay contribuidores, el runtime usa (0, 0), 640 × 480.
