Archivos del proyecto

FLX separa los metadatos del proyecto de los datos del mundo.

  • .flx: define metadatos del proyecto y puntos de entrada de compilacion.
  • object: define un objeto que puede contener otros elementos.
  • object: define objetos que pueden representarse visualmente.

Manifiesto FLX

El archivo .flx es un manifiesto de estilo properties. Apunta al objeto raiz, a la Machine y al mapping de input. Las opciones de runtime, como debug o pantalla completa, pertenecen al CLI o al entorno de ejecucion, no al manifiesto.

game.flx
name=Asteroids
version=1.0.0
engine=0.2.0
path=asteroids
root=space
title=Asteroids
machine=machines/standard.yml
input.mapping=input/default.input
notes=FLX example with spawn and basic UI

Campos

  • name: nombre del proyecto. [ Opcional ]
  • version: versiÃƒÆ’Ã†â€™Ãƒâ€šÃ‚Â³n del proyecto. [ Opcional ]
  • engine: versiÃƒÆ’Ã†â€™Ãƒâ€šÃ‚Â³n objetivo de FLX. [ Opcional ]
  • path: directorio de contenido del proyecto. [ Opcional ]
  • root: objeto JSON raiz compilado como entrada del mundo. [ Obligatorio ]
  • title: tÃƒÆ’Ã†â€™Ãƒâ€šÃ‚Â­tulo de la ventana. [ Opcional ]

  • notes: notas libres del proyecto. [ Opcional ]

El parser del manifiesto rechaza campos de runtime eliminados como screen.width, screen.height, screen.scale, window.mode y debug.*. Tamano de pantalla y escala vienen del chip de video. Las opciones de debug/ventana pertenecen a la capa de ejecucion, por ejemplo flx run --window-mode=fullscreen --scale=3 project.flx.

Una Machine describe capacidades disponibles mediante chips como video, audio e input. El tamano de pantalla, el color de fondo y la escala de salida vienen ahora del chip de video, no del manifiesto .flx.

En archivos .input, la coma separa alternativas y + une entradas simultaneas. El mapping se valida contra el Input Chip. Tokens, jugadores o botones fuera de los limites del chip se ignoran con warnings.

Referencias JSON FLX

Los recursos JSON pueden usar referencias desde la raiz del proyecto empezando un string con /. Esa barra inicial es la raiz de contenido FLX declarada por path en el manifiesto, no la raiz del sistema operativo.

JSON completo
"shape": "/ui/title_shape"
clave de primer nivel dentro del JSON
"note": "/music/notes:a"

/music/notes carga path/music/notes.json. /music/notes:a carga el mismo archivo y devuelve su entrada de primer nivel a. La extension .json es opcional. Strings normales como red, C4, square o player no son referencias. Archivos inexistentes, JSON invalido, claves no encontradas e intentos de salir de la raiz del proyecto se registran como errores.

En color.levels, cada canal RGB acepta valores desde 0. El valor 0 desactiva ese canal. En color.tone.base, los colores hexadecimales pueden escribirse con comillas o sin comillas, por ejemplo base: "#9BBC0F" y base: #9BBC0F.

input chip
input:
  system:
    buttons: 2
  players:
    count: 1
    controls:
      directions:
        - type: 4way
          simultaneous: last
          buffer: 0
      buttons: 1

El Input Chip declara solo capacidades de entrada. No nombra acciones semanticas como start, pause o fire. Los botones de jugador, direcciones de jugador y botones de sistema son presupuestos separados. Si no se declara Input Chip, FLX usa un chip interno permisivo. Esta iteracion soporta direcciones digitales 2way y 4way.

El chip de audio define las capacidades sonoras de la Machine. No declara sonidos concretos, canciones, instrumentos ni assets. voices.music limita los canales de musica generada y voices.sound limita los efectos generados. En modo reserved esos presupuestos son independientes. En modo shared forman un unico pool con voices.music + voices.sound voces.

audio chip
audio:
  voices:
    music: 3
    sound: 1
    mode: reserved
    overflow: replace_oldest

  synthesis:
    model: pulse
    texture: clean
    movement: simple
    noise: simple

  fidelity:
    resolution: low
    dynamics: limited
    space: mono

  resources:
    generated: true
    samples: false
    streams: false

  fileAudio:
    mode: off

voices.mode acepta shared, preferred y reserved. voices.overflow acepta ignore, replace_oldest, replace_newest, replace_lowest_priority y steal_from_music. Los efectos generados actuales usan la misma prioridad. En modo shared, steal_from_music puede pausar una voz de musica para reproducir un efecto y reanudar la musica cuando las voces de sonido vuelven a quedar libres.

synthesis, fidelity, resources y fileAudio se validan y se guardan en la definicion de Machine. El audio generado usa synthesis.model, synthesis.texture, synthesis.movement, synthesis.noise, fidelity.resolution y fidelity.dynamics para moldear los osciladores. Los campos de audio por archivo siguen siendo solo validacion y todavia no activan reproduccion de WAV, OGG o MP3.

  name: standard

El campo children permite declarar objetos contenidos por otro objeto.

Creation

El bloque opcional creation controla como un parent crea sus children declarados. Si no aparece, FLX usa creation.mode = "individual".

creation individual
"creation": {
    "mode": "individual"
}
creation grid con pattern lineal
"children": {
    "a": { "like": "brick_red" },
    "b": { "like": "brick_blue", "spawn": "manual" }
},
"creation": {
    "mode": "grid",
    "rules": {
        "rows": 2,
        "columns": 3,
        "cellWidth": 32,
        "cellHeight": 16
    },
    "pattern": ["a", "b"]
}
creation grid con pattern por filas
"creation": {
    "mode": "grid",
    "rules": {
        "rows": 2,
        "columns": 3,
        "cellWidth": 32,
        "cellHeight": 16
    },
    "pattern": [
        ["a"],
        ["b"]
    ]
}

En modo grid, la posicion del parent es el origen de la rejilla. Cada celda usa column * cellWidth y row * cellHeight. El offset del child se aplica dentro de la celda y el origin del child se ignora.

Un pattern lineal se consume en orden row-major y se repite al terminar. Un pattern por filas repite sus filas exteriores y cada fila interior repite sus columnas. Los children manuales dentro de un grid no aparecen automaticamente; al llamar spawn(parent, "child") se crean todas las celdas del grid donde el pattern referencia ese child.

Sounds

El campo sounds declara sonidos que pertenecen a un objeto. Los scripts pueden reproducirlos con play_sound(object, "id").

                "noise": 0.0,
                "resonance": 0.0,
                "metal": 0.0
            },

                "attack": 0.0,
                "decay": 0.05,
                "sustain": 0.0,
                "release": 0.0
            },
            "space": {
                "mode": "mono",
                "width": 0.0,
                "echo": 0.0

        "duration": 0.08,
        "volume": 0.7

sounds (referencia)

kind define el evento sonoro. kind.source puede usar oscillator o noise en esta implementacion. kind.note acepta una nota musical como C4, una frecuencia numerica como 1200, un objeto como { "frequency": 1200 }, o una referencia FLX explicita como /music/notes:a. Si falta, FLX usa A4.

kind.slide es el cambio total de frecuencia durante el sonido. kind.movement.type = "fall" o "rise" puede mapear el movimiento a slide cuando slide no esta especificado. "wobble" aplica vibrato y "pulse" aplica tremolo.

tone define el caracter del sonido mediante material, envelope y space. El envelope se aplica a cada muestra generada. Material brightness, roughness, noise, resonance y metal aportan caracter audible. space.echo anade un pequeno delay; el ancho stereo esta preparado en el modelo de datos, pero el generador actual sigue renderizando en mono.

Las ondas soportadas son square, sine, triangle, saw , pulse y noise. source.duty controla el ciclo de trabajo de pulse entre 0.05 y 0.95. square siempre usa duty 0.5.

Las declaraciones de sonido son datos. Pueden estar en linea, referenciadas como JSON o compuestas con like.

Music

El campo music declara canciones generadas que pertenecen a un objeto. Los scripts pueden reproducirlas con play_music(object, "id"). La musica usa la capacidad voices.music del Audio Chip y no consume voices.sound.

        "loop": true,

                            "roughness": 0.1,
                            "noise": 0.0,
                            "resonance": 0.2,
                            "metal": 0.0
                        },
                        "envelope": {
                            "attack": 0.0,
                            "decay": 0.05,
                            "sustain": 0.5,
                            "release": 0.03
                        },
                        "space": {
                            "mode": "mono",
                            "width": 0.0,
                            "echo": 0.0
                        }
                    },
                    "play": {
                        "legato": false,
                        "glide": 0.0,
                        "vibrato": 0.0
                    },
                    "range": {
                        "min": "C0",
                        "max": "B8"
                    }
                },
                "volume": 0.35,
                "length": "1/8",
                "notes": ["C4", "E4", "G4", "C5"]
            },
            "bass": {
                "wave": "triangle",
                "volume": 0.25,
                "length": "1/4",
                "notes": ["C3", "-", "G2", "-"]
            }

Un canal puede declarar instrument en linea o como referencia explicita, por ejemplo /music/instruments:lead_square. Los instrumentos usan el mismo modelo source y tone que los sonidos, ademas de play y range. En esta primera implementacion, legato, glide y stereo width se cargan y validan, pero quedan preparados para comportamiento audible futuro. play.vibrato y tone.space.echo ya afectan a la musica generada.

Para canales simples, wave puede declararse directamente en el canal. FLX lo interpreta como instrument.source.wave.

Cada canal puede declarar su propio length. Si se omite, FLX usa 1/4. Los valores aceptados son 1/1, 1/2, 1/4, 1/8 y 1/16. A tempo 120, 1/4 dura 0.5 segundos, 1/8 dura 0.25 segundos y 1/16 dura 0.125 segundos.

- es silencio. En un canal noise, x es un golpe de ruido. Los canales conservan el orden declarado en JSON; si una cancion declara mas canales que voices.music, los canales sobrantes se ignoran con un warning.

States

El bloque opcional states declara una maquina de estados ligera propiedad del objeto. JSON define solo los nombres de estado y las transiciones validas; los scripts deciden cuando ocurren.

states
"states": {
    "initial": "title",

    "title": {
        "next": ["playing"]
    },

    "playing": {
        "next": ["gameover", "next_level"]
    },

    "gameover": {
        "next": ["title"]
    }
}
states (referencia)
"states": "logic/game_states"

Usa state_to(object, "playing") para solicitar una transicion. Las declaraciones invalidas fallan durante la compilacion. Las transiciones invalidas en runtime se ignoran y se registran como warnings.

Cuando states existe, initial es obligatorio y debe nombrar un estado declarado. Un estado sin next, o con next vacio, es terminal. Los ciclos son validos. Una autotransicion solo es valida si el estado se incluye explicitamente a si mismo en next.

Capacidades de objeto

Un archivo object define un objeto FLX. Sus propiedades determinan qué capacidades tiene.

Puede ser dibujable si declara shape, colisionable si declara collision, scriptable si declara behavior o un controlador lógico sin datos visuales.

Si no define información visual, el objeto seguirá existiendo dentro del runtime pero no será representado en pantalla.

Mechanics

Define reglas de movimiento y rotacion. Mechanics es declarativo: los scripts aplican intencion mediante funciones como move_horizontal(), move_vertical(), advance(), accelerate() y rotate().

mechanics
"mechanics": {
    "type": "polar",
    "motion": {
        "speed": {
            "start": 90,
            "limit": 150
        },
        "acceleration": 120,
        "inertia": 0.99,
        "step": 0,
        "diagonal": "independent"
    },
    "rotation": {
        "angle": 45,
        "speed": 180,
        "acceleration": 0,
        "inertia": 0,
        "step": 0
    }
}

Campos

  • type: direct o polar. Por defecto es direct.
  • motion.speed: forma corta numerica u objeto con start y limit. Un limite 0 significa sin limite.
  • motion.acceleration: tasa temporal de aceleracion. Por defecto es 0.
  • motion.inertia: persistencia normalizada de 0 a 1. Por defecto es 0.
  • motion.step: cuantizacion del movimiento. 0 significa continuo.
  • motion.diagonal: independent o vector.
  • motion.horizontal y motion.vertical: overrides opcionales por eje para speed, acceleration, inertia y step.
  • rotation.angle: angulo vivo inicial en grados.
  • rotation.speed: velocidad de rotacion como forma corta numerica o { "start", "limit" }.
  • rotation.acceleration, rotation.inertia y rotation.step: equivalentes rotacionales de los campos de movimiento.

Inherit

Define que estado vivo recibe un child desde su parent original. No hereda las reglas declarativas de mechanics.

inherit
"inherit": {
    "creation": {
        "angle": "copy",
        "velocity": "compose"
    },
    "live": {
        "angle": "copy"
    }
}

Campos

  • creation.angle = "copy": copia el angulo del parent cuando se crea el child.
  • creation.velocity = "copy": copia la velocity lineal viva del parent cuando se crea el child.
  • creation.velocity = "compose": suma la velocity lineal viva del parent a la velocity lineal propia del child al crearse, sin modificar su velocidad polar declarada.
  • live.angle = "copy": mantiene sincronizado el angulo del child con su parent original.
