Creation · Referencia JSON

Índice | Project | Object | Composition | Visual | Creation | Mechanics | Collision | Audio

Creation reúne las declaraciones que determinan qué children puede crear un parent, cuándo se crean y cómo reciben posición o estado vivo. Las reglas de creación se declaran en el parent; spawn, component, offset, attach e inherit describen al child.

children

Mapa de nombres de child a objetos inline o strings de referencia. Sin el bloque no hay children declarados. Cada valor inline usa Object; el string equivale a un Object con like. Un nombre identifica la declaración reutilizable, no una única instancia de runtime.

children
{
  "children": {
    "ship": "objects/ship",
    "marker": {
      "origin": {
        "x": 80,
        "y": 40
      }
    },
    "laser": {
      "like": "objects/laser",
      "spawn": "manual"
    }
  }
}

spawn

String: auto o manual; default auto. En modo individual, un child auto entra con su parent y uno manual espera una llamada a spawn(parent, "child"). La llamada también puede crear instancias adicionales de un child auto. Grid e iterator aplican sus reglas específicas. No es un temporizador ni una condición de aparición.

Child manual
{
  "children": {
    "bullet": {
      "spawn": "manual",
      "offset": {
        "x": 0,
        "y": -12
      }
    }
  }
}

component

Boolean; default false. Marca un child como parte de la entidad lógica de su parent. Las consultas de rayos excluyen la entidad lógica del objeto que consulta; al matar al parent se eliminan sus descendientes unidos por una cadena de components. Un componente sin máquina de estados propia busca estado efectivo en esa cadena. El Object raíz no puede declarar component: true.

Component no activa automáticamente el seguimiento espacial: para ello se declara attach.

Componente unido al parent
{
  "children": {
    "turret": {
      "component": true,
      "offset": {
        "x": 0,
        "y": -10
      },
      "attach": {
        "born": true,
        "position": true
      }
    }
  }
}

creation

Objeto o referencia de bloque del parent. mode selecciona individual, grid o iterator. Si se omite el bloque o el modo de la forma individual, se usa individual. Cada modo tiene una estructura distinta; no se combinan sus campos.

individual

Admite únicamente mode, opcional. Materializa una instancia inicial de cada child auto. La posición sigue las reglas de offset/origin.

creation individual
{
  "children": {
    "marker": {}
  },
  "creation": {
    "mode": "individual"
  }
}

grid

  • mode — string: grid. Obligatorio. Selecciona rejilla.
  • rules.rows / rules.columns — integer ≥ 1. Ambos obligatorios. Número de filas y columnas.
  • rules.cellWidth / rules.cellHeight — number > 0. Ambos obligatorios. Separación entre orígenes de celdas.
  • pattern — array de strings o array de filas de strings. Obligatorio. Nombres de children que ocupan las celdas. Use un patrón no vacío; el runtime rechaza la rejilla sin patrón efectivo.
grid — patrón lineal
{
  "children": {
    "a": {
      "size": {
        "width": 30,
        "height": 14
      }
    },
    "b": {
      "spawn": "manual"
    }
  },
  "creation": {
    "mode": "grid",
    "rules": {
      "rows": 2,
      "columns": 3,
      "cellWidth": 32,
      "cellHeight": 16
    },
    "pattern": [
      "a",
      "b"
    ]
  }
}

El patrón lineal se recorre por filas y se repite. En un patrón por filas, se repiten las filas exteriores y cada fila repite sus columnas. Una fila vacía no produce child en sus celdas. Los nombres usados deben corresponder a children declarados.

grid — patrón por filas
{
  "children": {
    "a": {},
    "b": {}
  },
  "creation": {
    "mode": "grid",
    "rules": {
      "rows": 2,
      "columns": 3,
      "cellWidth": 32,
      "cellHeight": 16
    },
    "pattern": [
      [
        "a"
      ],
      [
        "b"
      ]
    ]
  }
}

La posición es parent.position + (column × cellWidth, row × cellHeight) + child.offset. Se ignora child.origin; el offset no se rota con el ángulo del parent en este modo. Los children manuales no aparecen automáticamente. spawn(parent, "child") crea todas las celdas asignadas a ese nombre, no una instancia libre.

iterator

  • mode — string: iterator. Obligatorio. Selecciona creación secuencial.
  • pattern — array no vacío de strings. Obligatorio. Nombres de children existentes con spawn: "auto". No admite patrón por filas.
  • rules.concurrent — integer ≥ 1. Default: 1. Máximo de instancias de este iterator vivas o pendientes simultáneamente.
  • rules.repeat — boolean. Default: false. Reinicia el recorrido del patrón al alcanzar el final.
iterator
{
  "children": {
    "enemy": {}
  },
  "creation": {
    "mode": "iterator",
    "rules": {
      "concurrent": 1,
      "repeat": false
    },
    "pattern": [
      "enemy",
      "enemy"
    ]
  }
}

El iterator produce entradas a medida que quedan plazas libres. rules es opcional. No admite spawn(parent, "child") manual en el parent iterator. Su creación usa el posicionamiento individual. creation_active(object) permite consultar si aún tiene actividad; individual y grid devuelven false.

offset

Objeto opcional con x e y numéricos; cada eje vale 0 si se omite. En individual/iterator, si el bloque existe, el child nace en la posición del parent más el offset rotado por el ángulo actual del parent y se ignora origin. Sin offset, un origin declarado se conserva; si tampoco hay origin, nace en la posición del parent.

offset
{
  "offset": {
    "x": 0,
    "y": -14
  }
}

Declarar offset: {} es significativo: aplica un offset cero y tiene prioridad sobre origin. En grid rige la fórmula de celda.

attach

Objeto inline opcional con flags booleanos. Usa siempre el parent original; no reasigna parents ni declara jerarquías dinámicas.

  • born — boolean. Default: false. Nace attached si es true.
  • position — boolean. Default: false. Activa seguimiento de X e Y.
  • x / y — boolean. Por defecto toman position. Cada eje explícito sustituye position para ese eje.
  • angle — boolean. Default: false. Sincroniza el ángulo sin rotar el offset de seguimiento.
attach
{
  "attach": {
    "born": true,
    "position": true,
    "y": false,
    "angle": true
  }
}

El attach inicial conserva la separación capturada al crear. Un attach posterior captura la separación actual en los ejes seguidos; detach suspende el seguimiento, manteniendo el parent original. Véase inherit.live.angle para sincronización declarativa del ángulo.

inherit

Objeto o referencia de bloque. Recibe estado vivo del parent original, no sus reglas declarativas de Mechanics. Los tres modos omitidos valen none.

  • creation.angle — string: none | copy. Default: none. Copia el ángulo al crear el child.
  • creation.velocity — string: none | copy | compose. Default: none. copy copia la velocidad lineal viva; compose suma la del parent a la propia del child al crearlo, sin cambiar su velocidad polar declarada.
  • live.angle — string: none | copy. Default: none. Sincroniza continuamente el ángulo con el parent original.
inherit
{
  "inherit": {
    "creation": {
      "angle": "copy",
      "velocity": "compose"
    },
    "live": {
      "angle": "none"
    }
  }
}

La reutilización estática de declaraciones pertenece a like; las reglas de velocidad y rotación pertenecen a Mechanics.
