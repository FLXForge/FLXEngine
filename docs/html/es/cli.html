flx es la interfaz de línea de comandos para operar sobre proyectos FLX y ejecuciones concretas del runtime. El CLI opera sobre el proyecto; sus opciones de ejecución no redefinen la configuración persistente del manifiesto, la Machine o el archivo compilado.

Sintaxis y ejecución implícita

Forma general
flx [command] [options...] [target]

flx
flx .
flx project.flx

El comando predeterminado es run y el target predeterminado es ., el directorio actual. Las dos primeras formas ejecutan el proyecto del directorio actual; la tercera utiliza el manifiesto indicado. Un primer argumento que existe como ruta o termina en .flx se interpreta como target de run, salvo que sea un nombre de comando reconocido.

Los ejemplos sitúan las opciones antes del target. Usa = para los valores de las opciones largas mostradas aquí; --output admite también un argumento separado. Las rutas con espacios deben ir entre comillas. Sólo se admite un target y no se pueden repetir las opciones de ejecución, salida o formato.

Resolución del proyecto

Targets de run, validate y compile
target
├── archivo .flx → usarlo
└── directorio
    ├── project.flx → usarlo con prioridad
    └── sin project.flx
        ├── un único *.flx → usarlo
        ├── ninguno → error
        └── varios → error por ambigüedad

La búsqueda de candidatos sólo recorre el primer nivel del directorio. La extensión .flx se compara sin distinguir mayúsculas/minúsculas. Un target inexistente, un archivo de otro tipo o un directorio ambiguo produce un error de resolución; no se elige arbitrariamente un candidato. La prioridad corresponde al nombre project.flx buscado en el sistema de archivos.

Comandos de v0.3.0

Operaciones disponibles
ComandoResultado

build está reservado para trabajo futuro y no es un comando operativo de v0.3.0.

run

Ejecución desde fuentes
flx run --frames=120 --scale=2 .

Resuelve el manifiesto y compila el proyecto. Sólo si la compilación tiene éxito lo ejecuta con Engine. Las opciones siguientes se aplican también a run-compiled.

Opciones de ejecución
OpciónValores / defaultEfecto
--frames=<positive-integer>Entero positivo. Omitida: sin límite de frames del CLI.Limita los frames de esta ejecución. Cero, negativos, texto y valores fuera del rango entero admitido son inválidos.
--window-mode=<window|fullscreen>window por defecto.Selecciona ventana o pantalla completa para esta ejecución.
--scale=<positive-integer>Entero positivo. Omitida: escala de Machine.Sobrescribe video.output.scale para esta ejecución. No modifica la Machine ni el .flxc.
--debug-logs[=<true|false>]false por defecto.Controla la generación de logs internos de depuración.
--debug-console[=<true|false>]false por defecto.Controla la salida de logs del runtime por consola.
--debug-collisions[=<true|false>]false por defecto.Controla el dibujado de colisiones de depuración.

Los tres booleanos sin valor equivalen a true; los valores explícitos son exactamente true o false. --debug-logs y --debug-console controlan aspectos distintos: generar logs y enviarlos a consola. Consulta Machine · Video para la configuración de salida persistente.

validate

Validación sin ejecución
flx validate .
flx validate --format=json project.flx

Resuelve el proyecto y realiza la compilación/validación disponible en v0.3.0. No inicia el runtime ni genera .flxc. Admite --format=text y --format=json. Una validación satisfactoria devuelve 0 y puede incluir warnings; no garantiza que toda ejecución posterior tenga éxito.

compile

Salida explícita obligatoria
flx compile --output=game.flxc .
flx compile -o game.flxc project.flx
flx compile --format=json --output=game.flxc .

Genera la representación compilada del proyecto FLX. La salida es obligatoria: usa --output=<path>, --output <path> o -o <path>. No existe un nombre de salida automático. El CLI escribe en la ruta indicada; utiliza la extensión .flxc para poder ejecutarla con run-compiled.

Admite formato text o json. Un .flxc es un proyecto compilado; el futuro producto distribuible de build queda fuera de esta operación.

run-compiled

Ejecución compilada
flx run-compiled --frames=120 game.flxc

Lee un proyecto ya compilado y lo ejecuta con Engine. El target debe tener extensión .flxc, comparada sin distinguir mayúsculas/minúsculas. Admite las mismas seis opciones de ejecución de run. Una extensión incorrecta es un error de argumentos (2); un archivo compilado que no se puede leer o es inválido produce 5.

version

Formas equivalentes
flx version
flx --version
flx -v

Escribe únicamente la versión semántica en stdout y termina con 0, sin abrir un proyecto ni iniciar Engine. No acepta un target ni opciones de formato.

help

Ayuda general y específica
flx help
flx --help
flx -h
flx help run
flx run --help

La ayuda por comando admite run, compile, run-compiled, validate y version. También se admite flx <command> --help o -h, sin argumentos posteriores; por ejemplo, flx compile --help. flx --help run y flx help help no son formas válidas.

Formato de salida

--format=<text|json> sólo está disponible para compile y validate; el valor predeterminado es text. run y run-compiled rechazan esta opción, también con valor text. El CLI no ofrece salida JSON del runtime en v0.3.0.

En texto, el resultado normal va a stdout y los diagnósticos a stderr. En JSON, el resultado estructurado reúne ambos en stdout. Para automatización, coloca --format=json inmediatamente después de compile o validate: un error de argumentos anterior a reconocer esa opción se informa todavía en texto. Consulta Diagnostics · Salida JSON.

Códigos de salida

Códigos definidos y uso actual
CódigoNombreContrato en v0.3.0
0SuccessOperación satisfactoria; puede haber warnings.
1InternalErrorCódigo definido para error interno; no debe interpretarse como destino universal de cualquier fallo.
2InvalidArgumentsComando, opción o argumentos no válidos.
3ProjectResolutionErrorNo se puede resolver el manifiesto del proyecto.
4CompilationErrorFallo de compilación/validación o de escritura del proyecto compilado.
5InvalidCompiledProjectFallo al leer o validar un proyecto compilado.
6RuntimeInitializationErrorrun y run-compiled devuelven actualmente este código ante cualquier EngineResult fallido.
7RuntimeExecutionErrorDefinido; los comandos actuales no separan los fallos de Engine con este código.
8BuildErrorDefinido; build no está disponible como comando operativo.

El código de salida expresa la categoría global. Los diagnósticos describen qué ocurrió y dónde. No deduzcas la causa concreta únicamente del número de salida.
