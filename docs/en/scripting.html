FLX Documentation

Scripting

FLX uses JavaScript to define behavior during runtime execution.

Scripts can react to object lifecycle stages, access the runtime context and modify properties in real time.

FLX is under active development. Some functions and structures may change during the 0.x versions.

Basic Structure

An FLX script is a standard JavaScript file.

Scripts are usually associated through the behavior block.

tofu.json
"behavior": {
    "scripts": [ "tofu" ]
}

The runtime will automatically load:

script path
scripts/tofu.js

Reference

FLX provides TypeScript definitions to improve autocomplete and editor validation.

tofu.js
/// <reference path="../tools/scripts/flx.d.ts" />

This allows development assistance in compatible editors such as Visual Studio Code.

Lifecycle

The runtime automatically executes specific functions when they exist inside the script.

lifecycle.js
function start(self) {}

function action(self) {}

function motion(self) {}

function collision(self, other) {}

function draw(self) {}

function end(self) {}

Functions

  • start: called when the object is initialized.
  • action: main logic and input handling.
  • motion: movement and transformations.
  • collision: collision handling.
  • draw: additional drawing logic.
  • end: called before destroying the object.

Property Access

Scripts can access and modify object properties.

properties.js
function action(self) {

    self.origin.x += 1;

    self.motion.maxSpeed = 250;
}

This allows combining JSON structures with dynamic runtime logic.

Program Scripts

Scripts can also be associated with the program block of the main structure.

world.json
"program": {
    "scripts": [ "scripts/program" ]
}

These scripts allow implementing global runtime logic.

Best Practices

  • Keep scripts small and specialized.
  • Separate global logic from object logic.
  • Use JSON for configuration and JavaScript for behavior.
  • Avoid modifying structures unnecessarily during draw().
