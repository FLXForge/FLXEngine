FLX Documentation

JSON Reference

This section documents the JSON structures used by FLX to define the main runtime, objects and their properties.

FLX is under active development. Some fields may change during 0.x versions.

JSON Types

FLX currently uses different JSON files depending on their role within the runtime.

  • main: defines the runtime entry point.
  • node: defines a container that may contain other elements.
  • drawable: defines objects that can be rendered visually.

Main JSON

The main file organizes the base structure of the runtime.

world.json
{
    "$schema": "tools/schemas/main.schema.json",
    "name": "Main",
    "description": "This is a description.",

 
"screen": {
    "title": "Title in window",
    "width": 320,
    "height": 180
},

"scale": 3,

"children": [ ... ],

"spawns": { ... },

"behavior": {
    "scripts": [ "scripts/game" ]
}
 

}

Fields

  • $schema: schema path used for validation. [ Optional ]
  • name: logical name of the main runtime. [ Required ]
  • description: optional description. [ Optional ]
  • screen: window or runtime surface configuration. [ Required ]
  • scale: scale factor applied to rendering. [ Optional ]
  • children: list of structures loaded by the main runtime. [ Optional ]
  • spawns: declarative spawn definitions associated with the object. [ Optional ]
  • behavior: scripts associated with the overall behavior. [ Optional ]

Screen

The screen block defines the basic window properties.

screen
"screen": {
    "title": "Title in window",
    "width": 320,
    "height": 180
}
  • title: window title. [ Optional ]
  • width: internal reference width. [ Required ]
  • height: internal reference height. [ Required ]

Children

The children field declares objects contained by the main runtime.

children (link)
"children": [ "objects/tofu" ]
children (inline)
"children": [ {"name": "Tofu", ... } ]
children (mix)
"children": [ "objects/tofu", {"name": "Tofu", ... }, ... ]

Each value references an object that the runtime must load.

Objects may be referenced as external files (the JSON extension is not required) or declared inline.

JSON Composition (like)

FLX allows JSON definitions to be reused through the like field.

This feature makes it possible to build new configurations from existing ones while overriding only the required fields.

like
{
    "name": "DeepSpaceLeft",

 
"like": "asteroid/deep_space",

"origin": {
    "x": 5,
    "y": 5
}
 

}

The runtime first loads the definition referenced by like and then overrides the fields declared in the current JSON.

Composition is performed recursively, allowing only the necessary parts to be modified.

Fields

  • like: path to the base definition used for composition.

Important: like does not implement inheritance.

Its purpose is to reuse and compose data.

Node JSON

A node defines a group of objects. It is not rendered visually but may contain logic.

tofu.json
{
    "$schema": "tools/schemas/node.schema.json",
    "name": "Level",
    "description" : "This is a description.",

 
"children": [...],

"spawns": {...}
 

}

Fields

  • $schema: schema path used for validation. [ Optional ]
  • name: logical name of the node. [ Required ]
  • description: optional description. [ Optional ]
  • children: list of objects loaded by the runtime. [ Optional ]
  • spawns: declarative spawn definitions associated with the object. [ Optional ]

Drawable JSON

A drawable file defines an object that can be rendered visually.

A drawable may also be used as a logical node.

If no visual information is defined, the object will still exist within the runtime but will not be rendered on screen.

tofu.json
{
    "$schema": "../tools/schemas/drawable.schema.json",
    "name": "Tofu",

 
"origin": {
    "x": 157,
    "y": 87
},

"shape": {
    "type": "triangle",
    "color": "WHITE",
    "size": {
        "width": 18,
        "height": 24
    }
},

"motion": {
  "rotationSpeed": 180,
  "acceleration": 120,
  "inertia": 0.99,
  "maxSpeed": 180
},

"bounds": {
  "mode": "wrap",
  "overflow": true
},

"spawns": {
    "laser": {
        "prefab": "objects/laser",
        "offset": {
            "x": 0,
            "y": -12
        }
    }
},

"group": "paddle",

"behavior": {
    "scripts": [ "tofu" ]
}
 

}

Fields

  • $schema: schema path used for validation. [ Optional ]
  • name: logical object name. [ Required ]
  • origin: object's initial position. [ Optional ]
  • shape: object's visual information. [ Optional ]
  • motion: movement configuration, if any. [ Optional ]
  • bounds: object behavior when reaching screen boundaries. [ Optional ]
  • spawns: declarative spawn definitions associated with the object. [ Optional ]
  • group: logical group associated with the object. [ Optional ]
  • behavior: scripts associated with the object. [ Optional ]

Origin

Defines the object's initial position within the runtime.

origin
"origin": {
    "x": 157,
    "y": 87
}

Fields

  • x: X coordinate (relative to the coordinate system origin, top-left corner). [ Required ]
  • y: Y coordinate (relative to the coordinate system origin, top-left corner). [ Required ]

Shape

Defines the object's basic visual representation.

shape
"shape": {
    "type": "triangle",
    "color": "WHITE",
    "size": {
        "width": 18,
        "height": 24
    }
}

Fields

  • type: shape type to render. [ Optional ]
    • block: default solid block. Rotation mechanics do not apply.
    • rectangle: rectangle with support for rotation and oriented movement.
    • triangle: unfilled triangle.
    • polygon: polygon defined by a list of points.
    • line: line defined between two points.
    • text: renderable text.
  • color: object color. [ Optional ]
  • size: object size. [ Optional ]

Size

Defines the object's size.

size
"size": {
    "width": 18,
    "height": 24
}

Fields

  • width: object width in pixels.
  • height: object height in pixels.

Polygon

Polygons allow irregular shapes to be defined using a list of local points.

polygon
"shape": {
    "type": "polygon",
    "color": "WHITE",

 
"points": [
    { "x": 0, "y": -16 },
    { "x": 12, "y": -8 },
    { "x": 16, "y": 8 },
    { "x": -8, "y": 14 }
]
 

}

Each point is defined in local coordinates relative to the object's origin.

Motion

Defines properties related to object movement.

motion
"motion": {
    "inherit": "creation",
    "rotationSpeed": 180,
    "acceleration": 120,
    "inertia": 0.99,
    "maxSpeed": 180
}

Fields

  • inherit: defines how the spawned object inherits movement. [ Optional ]
    • none: does not inherit movement.
    • creation: inherits the initial movement at spawn time.
  • rotationSpeed: rotation speed.
  • acceleration: acceleration applied to the object.
  • inertia: movement preservation factor.
  • maxSpeed: maximum speed.

Bounds

Defines the object's behavior when reaching screen boundaries.

bounds
"bounds": {
    "mode": "wrap",
    "overflow": true
},

Fields

  • mode: boundary behavior mode. [ Optional ]
    • none: no special behavior.
    • wrap: when reaching a boundary, the object appears on the opposite side while preserving its direction.
  • overflow: controls how boundary behavior is applied. [ Optional ]
    • true: the object begins appearing on the opposite side while progressively disappearing from the current side.
    • false: the object immediately reappears when reaching the boundary.

Spawns

Defines objects that can be instantiated dynamically by the runtime.

spawns
"spawns": {
    "laser": {
        "prefab": "objects/laser",

 
    "offset": {
        "x": 0,
        "y": -12
    }
}
 

}

Spawn definitions use prefabs previously loaded by the runtime.

Prefab paths are resolved relative to the JSON file that declares the spawn.

This allows reusable structures to be built without depending on a fixed location within the project.

Fields

  • prefab: path to the prefab that should be instantiated. [ Required ]
  • offset: local offset applied to the spawned object. [ Optional ]

The offset uses the object's current rotation as reference.

Children and Spawns

  • children: objects that enter the world when the runtime is loaded.
  • spawns: objects that may be instantiated later during execution.

Behavior

Defines the scripts associated with the object.

behavior
"behavior": {
    "scripts": [ "tofu" ]
}

Fields

  • scripts: list of JavaScript scripts associated with the object (file extension is not required). [ Required ]
