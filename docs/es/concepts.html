Documentación FLX

Conceptos básicos

FLX organiza los proyectos mediante estructuras de datos simples, objetos, transformaciones y reglas de ejecución claramente definidas.

Esta sección describe los conceptos fundamentales que forman parte de cualquier proyecto FLX.

Proyecto

Todo proyecto FLX comienza con un archivo principal con extensión .flx.

Este archivo actúa como punto de entrada del proyecto.

Asteroids.flx
name:Asteroids
version:1.0
flxEngineVersion:0.1.0
main:game.json

A partir de este archivo, el runtime carga la estructura principal, los recursos y la configuración necesaria.

Principal (Main)

El principal es la estructura raíz del runtime.

Organiza objetos, recursos y lógica de ejecución.

Dependiendo del proyecto, puede representar:

  • Un nivel
  • Un menú
  • Una pantalla de carga
  • Una presentación
  • Una secuencia narrativa
  • Un estado concreto de la aplicación

FLX no impone una interpretación concreta.

Objetos

Los objetos representan elementos que existen dentro del runtime.

Un objeto puede:

  • Dibujarse
  • Moverse
  • Colisionar
  • Almacenar datos
  • Ejecutar comportamiento mediante scripts

Normalmente los objetos se describen mediante JSON.

Una definición puede escribirse completamente o construirse reutilizando otra definición mediante like.

ship.json
{
    "name": "Ship",

    "shape": {
        "type": "triangle"
    },

    "motion": {
        "maxSpeed": 180
    }
}

Reutilización y composición

FLX permite construir nuevas definiciones a partir de otras ya existentes.

Esta capacidad se basa en el sistema like, que permite reutilizar configuraciones y sobrescribir únicamente los campos necesarios.

DeepSpaceLeft
{
    "name": "DeepSpaceLeft",

    "like": "asteroid/deep_space",

    "origin": {
        "x": 5,
        "y": 5
    }
}

Esta característica permite construir familias completas de objetos reutilizando una única definición base.

Los detalles completos se describen en JSON Reference.

Children y Spawns

FLX distingue entre objetos que existen al iniciar el runtime y objetos que pueden aparecer posteriormente.

  • children: objetos que entran al mundo al cargarse la escena.
  • spawns: definiciones reutilizables utilizadas para crear nuevas instancias durante la ejecución.

Esta separación permite mantener una estructura clara entre el contenido inicial y el contenido dinámico.

Tipos de shape

FLX proporciona varios tipos básicos de representación visual.

Tipo Origen
block Esquina superior izquierda
rectangle Centro
triangle Centro
line Centro
polygon Centro
text Texto

Los colores pueden declararse directamente desde JSON.

shape.json
"shape": {
    "type": "triangle",
    "color": "WHITE"
}

Los polígonos permiten definir formas irregulares mediante listas de puntos.

polygon
"shape": {
    "type": "polygon",

    "points": [
        { "x": 0, "y": -16 },
        { "x": 12, "y": -8 },
        { "x": 16, "y": 8 },
        { "x": -8, "y": 14 }
    ]
}

Shape and Collision

En FLX, la representación visual y la colisión son sistemas independientes.

Con shape block defines como se verá el objeto, mientras que con collision block defines como interactuará con otros objetos en el runtime.

En algunos casos ambas definiciones pueden ser similares, pero no es una condición obligatoria.

shape + collision
{
    "shape": {
        "type": "polygon"
    },

    "collision": {
        "type": "circle",
        "radius": 12
    }
}

Esta separación permite que la detección de colisiones siga siendo sencilla y eficiente, mientras que la representación visual puede ser tan detallada como sea necesario.

Sistema de coordenadas

FLX utiliza un sistema de coordenadas 2D con origen en la esquina superior izquierda de la pantalla.

  • x crece hacia la derecha.
  • y crece hacia abajo.
  • Subir implica reducir y.
  • Bajar implica aumentar y.

Sistema angular

FLX utiliza una convención angular propia.

  • 0° apunta hacia arriba.
  • 90° apunta hacia la derecha.
  • 180° apunta hacia abajo.
  • 270° apunta hacia la izquierda.
  • Los ángulos positivos giran en sentido horario.
rotation
rotate(ship, RIGHT);
advance(ship);

Movimiento

FLX combina un sistema clásico basado en velocidad con un sistema basado en aceleración e inercia.

Entre las propiedades más habituales se encuentran:

  • speed
  • velocityX
  • velocityY
  • acceleration
  • inertia
  • rotationSpeed

Las funciones de movimiento utilizan automáticamente la convención angular FLX.
