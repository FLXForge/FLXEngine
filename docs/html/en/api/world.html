World manages instances of definitions already declared. Here, objects are created, hidden or removed, and values are retained across runs. Visibility controls only visual output.

Creation · Lifecycle and visibility · Persistence

Creation

Instantiation rules are declared in JSON · Creation. Spawn requests instances of those definitions.

spawn()

Signatures
spawn(object: RuntimeObject, childName: string): void;

Requests instantiation of childName, a definition already present in the children map of object. Does not accept an arbitrary definition or return the created instance. Also allows another instance of a child declared with spawn auto. World integrates pending instances and calls born when they enter the world.

object: RuntimeObject
Instance received or resolved during the current hook.
childName: string
Key declared in children.

Returns: no value (undefined in JavaScript; void in the signature).

JavaScript example
spawn(object, "laser");

Related: creation_active(), born(), find_children().

creation_active()

Signatures
creation_active(object: RuntimeObject): boolean;

Queries the object's iterator creation. Individual and grid return false. A finite iterator remains active while it has pending entries in its pattern or live instances it produced; a repeating iterator remains active while its owner is alive.

object: RuntimeObject
Instance received or resolved during the current hook.

Returns: boolean.

JavaScript example
if (!creation_active(object)) {
  console.log("Creation finished");
}

Related: spawn().

Lifecycle and visibility

kill()

Signatures
kill(object: RuntimeObject): void;

Marks the instance for destruction. It stops being alive; World executes dead before removing it during cleanup. Do not continue using a normal view after killing its instance.

object: RuntimeObject
Instance received or resolved during the current hook.

Returns: no value (undefined in JavaScript; void in the signature).

JavaScript example
kill(object);

Related: dead(), keep_only(), exit().

keep_only()

Signatures
keep_only(object: RuntimeObject): void;

Marks all live objects for destruction except the exact instance received. Does not automatically preserve its children.

object: RuntimeObject
Instance received or resolved during the current hook.

Returns: no value (undefined in JavaScript; void in the signature).

JavaScript example
keep_only(object);

Related: kill(), find_children().

show()

Signatures
show(object: RuntimeObject): void;

Enables the object's visual output. Does not create a new instance or reset its state.

object: RuntimeObject
Instance received or resolved during the current hook.

Returns: no value (undefined in JavaScript; void in the signature).

JavaScript example

Related: hide().

hide()

Signatures
hide(object: RuntimeObject): void;

Disables only visual output. The instance continues participating in action, motion, collision, states and timers. This is not equivalent to pausing or destruction.

object: RuntimeObject
Instance received or resolved during the current hook.

Returns: no value (undefined in JavaScript; void in the signature).

JavaScript example
hide(object);

Related: show(), kill().

Persistence

Persistence stores only boolean, number and string. It is independent of in-memory local/global state. Does not save the entire World.

save()

Signatures
save(name: string, key: string, value: boolean | number | string): void;

Stores value under key in saves/<name>.flxsave. Only supports boolean, number and string. Does not serialize arrays, objects or RuntimeObjects; does not return confirmation of success.

name: string
Persistence file name, without the .flxsave extension.
key: string
Value key.
value: boolean | number | string
Value to assign.

Returns: no value (undefined in JavaScript; void in the signature).

JavaScript example
save("progress", "completed", true);
save("progress", "score", 100);

Related: load(), ScriptValue.

load()

Signatures
load<T extends boolean | number | string>(name: string, key: string, defaultValue: T): T;

Reads key from saves/<name>.flxsave. defaultValue determines both the fallback and the expected type: boolean, number or string. If the file or key is missing, or the stored value has a different type, returns the fallback without conversion. For example, a stored number is not loaded as a string by passing "0". The generic signature describes this type selection; in JavaScript it is called without <T>.

name: string
Persistence file name, without the .flxsave extension.
key: string
Value key.
defaultValue: T
Fallback and expected type selector.

Returns: T.

JavaScript example
const score = load("progress", "score", 0);
const completed = load("progress", "completed", false);

Related: save().
