FLX Documentation

Cómo piensa FLX

Antes de aprender JSON, APIs o ciclos de vida, merece la pena comprender la idea central sobre la que está construido FLX.

FLX no intenta trasladar el motor al script.

El runtime mantiene las reglas del mundo; los scripts expresan el comportamiento de los objetos.

Mental model
Objetos -> Datos

Scripts -> Funciones

Runtime -> Conecta ambos

Los objetos contienen datos

Un objeto describe algo que existe dentro del runtime.

Puede tener posición, tamaño, movimiento, representación visual, estado local y otras capacidades declaradas.

Los objetos no implementan su comportamiento.

Declaran su estado, sus capacidades y los scripts que pueden actuar sobre ellos.

Los scripts contienen funciones

Un script es un conjunto de funciones JavaScript.

Esas funciones describen qué ocurre con los objetos a lo largo de su vida.

Los scripts no pertenecen a los objetos.

Son recursos compartidos que pueden ser utilizados por muchos objetos simultáneamente.

ship.js
function action(ship) {
    accelerate(ship);
}

El runtime conecta ambos

Durante la ejecución, el runtime invoca funciones y les proporciona los objetos sobre los que deben trabajar.

Los scripts describen comportamiento.

Los objetos almacenan estado.

El runtime coordina la interacción entre ambos.

Estado compartido y estado individual

Un mismo script puede utilizarse desde cientos de objetos.

Esto significa que existen distintos ámbitos de información.

  • Ámbito de función: variables locales de cada ejecución.
  • Ámbito de script: variables compartidas por las funciones del script.
  • Ámbito de objeto: estado propio mediante read_local() y write_local().
  • Ámbito global: estado compartido mediante read_global() y write_global().

Un mismo script puede actuar sobre muchos objetos, pero cada objeto mantiene su propio estado local.

Comprender esta diferencia es una de las claves para comprender FLX.

Objetos vivos

FLX entiende los objetos como entidades que nacen, existen y desaparecen.

Lifecycle
         born()
           ↓
    ┌─────────────┐
    │   action()  │
    │   motion()  │
    │ collision() │
    │    draw()   │
    └─────────────┘
           ↓
         dead()

born() se ejecuta cuando el objeto entra en el mundo. Durante su vida, el runtime puede invocar sus distintos hooks de comportamiento. dead() se ejecuta una vez antes de que el objeto sea retirado.

Un script puede solicitar su destrucción mediante kill(), pero el ciclo de vida pertenece al runtime.

Esta terminología no es accidental.

El ciclo de vida forma parte del modelo mental del runtime.
