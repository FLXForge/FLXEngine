FLX Documentation

Introduction

A small data-driven 2D engine

Define structures with JSON, behaviors with JavaScript and let the runtime handle the rest.

The FLX philosophy: data, functions and runtime

FLX is built around a simple idea:

Mental model
Objects -> Data

Scripts -> Functions

Runtime -> Connects both

Objects define what exists.

Scripts define what happens.

The runtime connects both during execution.

ship.json
{
    "$schema": "https://flxforge.github.io/FLXEngine/schemas/drawable.schema.json",

    "name": "Ship",

    "shape": {
        "type": "triangle",
        "color": "white",
        "size": {
            "width": 18,
            "height": 24
        }
    },

    "motion": {
        "rotationSpeed": 180,
        "acceleration": 120,
        "inertia": 0.99,
        "maxSpeed": 180
    }
}

Data defines existence.

ship.js
/// <reference path="https://flxforge.github.io/FLXEngine/scripts/flx.d.ts" />

function action(ship) {
    if (Key.down(KEY_UP)) {
        accelerate(ship);
    }
}

function motion(ship) {
    advance(ship);
}

Functions define behavior.

FLX does not try to simplify C++.

It tries to make runtime behavior scriptable.
