How FLX thinks

Before learning JSON, APIs or lifecycles, it is useful to understand the central idea on which FLX is built.

FLX does not try to move the engine into the script.

The runtime maintains the rules of the world; scripts express object behavior.

Mental model
Objects -> Data

Scripts -> Functions

Runtime -> Connects both

The world exists on a machine

The runtime does not execute the world in an undefined environment. Each project uses a machine that establishes the characteristics of the environment in which that world can exist.

FLX provides a default machine, so you do not need to define one to get started.

Later, we will see how a machine lets you explicitly control those characteristics.

Objects contain data

An object describes something that exists within the runtime.

It can have position, size, movement, visual representation, local state and other declared capabilities.

Objects do not implement their behavior.

They declare their state, capabilities and the scripts that can act on them.

Scripts contain functions

A script is a collection of JavaScript functions.

Those functions describe what happens to objects throughout their lives.

Scripts do not belong to objects.

They are shared resources that many objects can use simultaneously.

ship.js
function action(ship) {
    accelerate(ship);
}

The runtime connects both

During execution, the runtime invokes functions and provides them with the objects they should work on.

Scripts describe behavior.

Objects store state.

The runtime coordinates the interaction between both.

Shared state and individual state

The same script can be used by hundreds of objects.

This means there are different scopes of information.

  • Function scope: local variables for each execution.
  • Script scope: variables shared by the script's functions.
  • Object scope: its own state through read_local() and write_local().
  • Global scope: shared state through read_global() and write_global().

The same script can act on many objects, but each object maintains its own local state.

Understanding this distinction is one of the keys to understanding FLX.

Living objects

FLX sees objects as entities that are born, exist and disappear.

Lifecycle
         born()
           ↓
    ┌─────────────┐
    │   action()  │
    │   motion()  │
    │ collision() │
    │    draw()   │
    └─────────────┘
           ↓
         dead()

born() runs when the object enters the world. During its life, the runtime may invoke its various behavior hooks. dead() runs once before the object is removed.

A script can request its destruction through kill(), but the lifecycle belongs to the runtime.

This terminology is deliberate.

The lifecycle is part of the runtime's mental model.
