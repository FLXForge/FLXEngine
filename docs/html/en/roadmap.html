FLX Documentation

Roadmap

FLX is developed incrementally and practically.

Each game lets us test existing capabilities, combine them in real situations and discover what needs to evolve before moving forward.

Development principle

FLX evolves from needs encountered while building real games.

Before adding a new engine capability, we try to solve the problem by combining existing capabilities. When a limitation prevents a reasonable solution, that limitation becomes a candidate for runtime evolution.

This way, new features emerge from using the engine rather than trying to anticipate every feature it might need.

FLX v0.3.0 · Consolidating the foundation

FLX v0.3.0 consolidates the engine's first stable foundation.

Pong, Asteroids, Arkanoid, Invaders and Tank have helped develop, review and unify the model used to build FLX worlds.

This version establishes a common foundation for:

  • object declaration, composition and creation;
  • visual representation and immediate drawing;
  • movement, orientation and inertia;
  • input and logical controls;
  • collisions and spatial queries;
  • state, timers and lifecycle;
  • relationships between objects;
  • sound and music;
  • machines and environment configuration;
  • scripting and the JavaScript API;
  • CLI, diagnostics and project validation.

The goal of this version is not to close off FLX's possibilities, but to provide a coherent foundation on which to build and experiment.

Future directions

From v0.3.0 onward, FLX will continue evolving through the development of new games and the gradual addition of new capabilities.

These are directions for exploration, not commitments to a specific version.

Machines and new generations

Machines express the capabilities and constraints of the environment in which an FLX world runs.

Their evolution will let us progressively explore new ways to build games and represent different generations of 2D systems.

Scrolling, spaces and camera

Moving the world beyond a single screen opens a new stage for FLX.

Developing scrolling and, when needed, a camera model will let us explore larger environments and new relationships between world coordinates, the screen and representation.

Representation and animation

Visual representation will continue evolving from the current primitives and capabilities.

Areas for exploration include new declarative ways to represent images, animation and transformations, while maintaining the separation between the object, its representation and its behavior.

Tools

FLX may incorporate tools that make its declarations easier to create and edit without making those tools a requirement for developing a project.

Project files will remain directly usable, and tools will need to work with that same declarative model.

Known technical debt

The v0.3.0 foundation is consolidated, but some internal areas may be revisited as the engine continues to evolve.

  • Add typed validation after reference resolution, so reused blocks can be checked against the expected FLX resource type before parsing them.
  • Review cycle detection so the different forms of composition through like provide equivalent protection.
  • Continue simplifying and centralizing resource resolution internally when cases arise that justify that refactoring.
  • Expand diagnostics and runtime inspection tools when new games require new ways to observe its state.
