World gestiona instancias de definiciones ya declaradas. Aquí se crean, se ocultan o se retiran objetos y se conservan valores entre ejecuciones. La visibilidad controla sólo la salida visual.

Creación · Lifecycle y visibilidad · Persistence

Creación

Las reglas de instanciación se declaran en JSON · Creation. Spawn solicita instancias de esas definiciones.

spawn()

Firmas
spawn(object: RuntimeObject, childName: string): void;

Solicita instanciar childName, una definición ya existente en el mapa children de object. No acepta una definición arbitraria ni devuelve la instancia creada. También permite otra instancia de un child declarado con spawn auto. World integra las instancias pendientes y llama a born cuando entran en el mundo.

object: RuntimeObject
Instancia recibida o resuelta durante el hook actual.
childName: string
Clave declarada en children.

Retorno: sin valor (undefined en JavaScript; void en la firma).

Ejemplo JavaScript
spawn(object, "laser");

Relacionados: creation_active(), born(), find_children().

creation_active()

Firmas
creation_active(object: RuntimeObject): boolean;

Consulta la creación iterator del objeto. Individual y grid devuelven false. Un iterator finito sigue activo mientras hay entradas pendientes en su patrón o instancias producidas vivas; uno repetitivo sigue activo mientras su propietario esté vivo.

object: RuntimeObject
Instancia recibida o resuelta durante el hook actual.

Retorno: boolean.

Ejemplo JavaScript
if (!creation_active(object)) {
  console.log("Creación terminada");
}

Relacionados: spawn().

Lifecycle y visibilidad

kill()

Firmas
kill(object: RuntimeObject): void;

Marca la instancia para destrucción. Deja de estar viva; World ejecuta dead antes de retirarla en el cleanup. No sigas utilizando una vista normal después de matar su instancia.

object: RuntimeObject
Instancia recibida o resuelta durante el hook actual.

Retorno: sin valor (undefined en JavaScript; void en la firma).

Ejemplo JavaScript
kill(object);

Relacionados: dead(), keep_only(), exit().

keep_only()

Firmas
keep_only(object: RuntimeObject): void;

Marca para destrucción todos los objetos vivos excepto la instancia exacta recibida. No conserva automáticamente sus hijos.

object: RuntimeObject
Instancia recibida o resuelta durante el hook actual.

Retorno: sin valor (undefined en JavaScript; void en la firma).

Ejemplo JavaScript
keep_only(object);

Relacionados: kill(), find_children().

show()

Firmas
show(object: RuntimeObject): void;

Habilita la salida visual del objeto. No crea una nueva instancia ni reinicia su estado.

object: RuntimeObject
Instancia recibida o resuelta durante el hook actual.

Retorno: sin valor (undefined en JavaScript; void en la firma).

Ejemplo JavaScript
show(object);

Relacionados: hide().

hide()

Firmas
hide(object: RuntimeObject): void;

Deshabilita sólo la salida visual. La instancia continúa participando en action, motion, collision, estados y timers. No equivale a pausa ni destrucción.

object: RuntimeObject
Instancia recibida o resuelta durante el hook actual.

Retorno: sin valor (undefined en JavaScript; void en la firma).

Ejemplo JavaScript
hide(object);

Relacionados: show(), kill().

Persistence

Persistence guarda sólo boolean, number y string. Es independiente del estado local/global en memoria. No guarda el World completo.

save()

Firmas
save(name: string, key: string, value: boolean | number | string): void;

Guarda value bajo key en saves/<name>.flxsave. Sólo admite boolean, number y string. No serializa arrays, objetos o RuntimeObjects; no devuelve una confirmación de éxito.

name: string
Nombre del archivo de persistencia, sin la extensión .flxsave.
key: string
Clave del valor.
value: boolean | number | string
Valor que se asigna.

Retorno: sin valor (undefined en JavaScript; void en la firma).

Ejemplo JavaScript
save("progress", "completed", true);
save("progress", "score", 100);

Relacionados: load(), ScriptValue.

load()

Firmas
load<T extends boolean | number | string>(name: string, key: string, defaultValue: T): T;

Lee key de saves/<name>.flxsave. defaultValue determina tanto el fallback como el tipo esperado: boolean, number o string. Si faltan archivo o clave, o el valor guardado tiene otro tipo, devuelve el fallback sin convertirlo. Por ejemplo, un número guardado no se carga como string por pasar "0". La firma genérica describe esta selección de tipo; en JavaScript se llama sin <T>.

name: string
Nombre del archivo de persistencia, sin la extensión .flxsave.
key: string
Clave del valor.
defaultValue: T
Fallback y selector de tipo esperado.

Retorno: T.

Ejemplo JavaScript
const score = load("progress", "score", 0);
const completed = load("progress", "completed", false);

Relacionados: save().
