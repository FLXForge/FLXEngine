JSON object

An Object is a declaration of a World element. It can combine representation, movement, collisions, behavior, state, audio and children. No root property is required on its own; an empty object is valid according to the schema.

Minimal visible object
{
  "origin": {
    "x": 160,
    "y": 90
  },
  "size": {
    "width": 18,
    "height": 24
  },
  "visual": {
    "color": "white",
    "representation": [
      {
        "primitive": "triangle"
      }
    ]
  }
}

Root properties

The root schema has additionalProperties: false. Only the following properties are allowed; keys in named maps are defined within each block.

  • $schema: string; validation metadata.
  • like: string; composition from a base.
  • spawn: auto or manual.
  • component: boolean; integrates the child into its parent's logical entity.
  • creation: object or reference; materialization of children.
  • offset: object; creation displacement.
  • visible: boolean; initial visibility.
  • attach: object; parent following.
  • origin: object; initial position.
  • size: object; logical size.
  • visual: object or reference; representation.
  • mechanics: object or reference; movement and rotation.
  • inherit: object or reference; inheritance of movement and orientation from the parent.
  • bounds: object or reference; World boundaries.
  • delimit: boolean; logical World extent.
  • group: string; logical group.
  • control: object; associated player.
  • local: map; initial instance values.
  • collisions: map or reference; named colliders.
  • behavior: object or reference; scripts.
  • states: object or reference; states and transitions.
  • sounds: map; named sounds.
  • music: map; named music.
  • children: map; child declarations.

$schema

Optional string identifying the schema for validation tools. Does not select the engine version or change object defaults.

$schema
{
  "$schema": "https://flxforge.github.io/FLXEngine/schemas/object.schema.json"
}

origin

Optional object with numeric coordinates x and y; each omitted axis is 0. X increases to the right and Y downward. This is the object's position, not the corner of its logical box. For children, the rules of Creation determine how the initial position is obtained from the parent, origin, offset and the creation mode.

origin
{
  "origin": {
    "x": 160,
    "y": 90
  }
}

size

Optional object with numeric width and height, both required when the object is present. Defines logical size; it is not calculated automatically from the drawing. Without size, no logical size is declared. Visual primitives and colliders can supply their own size. The Object schema imposes no positive minimum, but a collider needs positive effective dimensions.

size
{
  "size": {
    "width": 32,
    "height": 16
  }
}

See representation size and collider size.

visible

Optional boolean; runtime default: true. Controls initial visual presentation. Hiding an object is not equivalent to removing it and does not, by itself, disable its colliders.

visible
{
  "visible": false
}

group

Optional string; by default, no group is assigned (empty string). Classifies the object for collision filters and queries. collisions.<id>.with contains the group names that a collider actively queries.

group
{
  "group": "enemy"
}

control

  • player — integer ≥ 1. Optional; no association if omitted. Associates the object with a player for input queries that receive an object. Does not declare actions or Machine capabilities.
control
{
  "control": {
    "player": 1
  }
}

local

Optional map of values of type string, number or boolean. Initializes each instance's own state; without this block, the map is empty. Does not support objects, arrays or null.

local
{
  "local": {
    "lives": 3,
    "ready": true,
    "label": "player"
  }
}

behavior

Object or block reference. If declared inline, scripts is required: an array of strings containing JavaScript script paths. Without behavior, no scripts are associated; scripts: [] is valid. Relative paths are resolved from the source file the loader retains for the behavior; .js is optional.

behavior
{
  "behavior": {
    "scripts": [
      "player"
    ]
  }
}

The example file is player.js. Callbacks and functions are documented in Scripting and FLX API.

states

Object or block reference. Declares a lightweight state machine. initial is a required nonempty string and must name a declared state. Each other key names a state whose value is an object with a single optional field, next: an array of unique nonempty names declared in the same block. Without next, no destinations are declared from that state. Without states, the object does not declare its own state machine.

states
{
  "states": {
    "initial": "idle",
    "idle": {
      "next": [
        "active"
      ]
    },
    "active": {
      "next": [
        "idle"
      ]
    }
  }
}

A component without its own machine can use the effective state from its parent chain. The filters in collider.states query that effective state.

bounds

Object or block reference. Defines behavior when crossing the logical World extent.

  • mode — string: none | wrap. Default: none. none does not apply wrapping; wrap moves the object to the opposite side.
  • overflow — boolean. Default: false. With wrap, controls object presentation when crossing the edges; true enables visual continuity copies.
bounds
{
  "bounds": {
    "mode": "wrap",
    "overflow": true
  }
}

The boundaries come from delimit, not the screen size.

delimit

Optional boolean; default: false. With true, contributes its position and logical size to the World extent during loading. With size, it contributes the rectangle centered on its position; without size, a point. The final envelope must have positive width and height: a single point is not enough.

delimit
{
  "origin": {
    "x": 160,
    "y": 90
  },
  "size": {
    "width": 320,
    "height": 180
  },
  "delimit": true
}

The extent is calculated during loading from the delimit objects materialized in that phase. Once fixed, movement, resize and subsequently created instances do not recalculate it. If there are no contributors, the runtime uses (0, 0), 640 × 480.
