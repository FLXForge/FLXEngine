FLX Documentation

FLX API

This section documents the JavaScript functions exposed by FLX to the runtime.

FLX is under active development. Some functions may change during 0.x versions.

Constants

FLX exposes global constants to work with logical direction components in a readable way. Scripts should not depend on their numeric representation.

Direction

  • UP: logical up component.
  • DOWN: logical down component.
  • LEFT: logical left component.
  • RIGHT: logical right component.
  • NEGATIVE: logical negative component.
  • POSITIVE: logical positive component.
  • STOP: neutral or stopped movement.

RuntimeObject

Objects received by scripting functions are instances of RuntimeObject.

A RuntimeObject represents a living entity inside the runtime and contains both JSON-defined data and runtime-generated state.

RuntimeObject
function motion(ship) {

    ship.x += 10;

    console.log(ship.id);
}

id

Unique identifier assigned to the runtime instance.

Unlike name, every spawned object receives a unique identifier.

id
console.log(ship.id);

name

Logical object name.

It usually comes from the JSON definition.

name
console.log(ship.name);

Local State

Persistent state for one instance is read and written with read_local() and write_local(). The JavaScript object does not expose object.local.

local state
const timer = (read_local(ship, "timer") || 0) + delta();
write_local(ship, "timer", timer);

group

Logical group assigned to the object.

It can be used to classify entities and may be used by future filtering systems.

Position and Size

These properties are a live read-only view. To change position or size, use position(), position_x(), position_y(), resize(), resize_width() or resize_height().

  • x: horizontal position.
  • y: vertical position.
  • width: width.
  • height: height.

Movement

These properties are read-only too. To change live movement state, use explicit functions such as apply_speed(), apply_angle(), apply_velocity() or apply_rotation_speed().

  • speed: current speed.
  • velocityX: horizontal velocity.
  • velocityY: vertical velocity.
  • rotationSpeed: current angular speed.

angle

The angle property represents the object's current rotation in degrees.

FLX uses the following convention:

  • 0: up.
  • 90: right.
  • 180: down.
  • 270: left.

accelerate(object, intent)

Applies acceleration using the object's declared mechanics and moves it during the same frame. intent is optional and defaults to 1.

accelerate
accelerate(ship);
accelerate(ship, input_direction(ship, direction(0), VERTICAL));

Configuration Used

  • mechanics.motion.acceleration: acceleration rate.
  • mechanics.motion.speed.limit: maximum live speed.
  • angle: object's current direction for polar mechanics.
  • velocityX and velocityY: accumulated velocity.

apply_speed(object, value)

Applies a live speed value without changing the JSON declaration. If mechanics.motion.speed.limit is greater than zero, FLX clamps the requested value to that limit. In polar mechanics this changes the object's own polar speed; inherited or accumulated velocityX/velocityY remains separate. In direct mechanics, axis movement without acceleration uses this live speed.

apply_speed
apply_speed(ball, ball.speed + 5);

apply_velocity(object, direction, speed)

Replaces the object's live linear velocity with a vector using direction in FLX degrees and speed as magnitude. It does not move the object immediately. If mechanics.motion.speed.limit is greater than zero, FLX clamps the requested magnitude to that limit and logs a warning.

speed is the live scalar speed used by helpers such as apply_speed(). velocityX and velocityY are the live linear vector. angle is the live orientation. apply_velocity() changes only the vector, so direct objects can move on a stable trajectory while rotate() changes their visual orientation.

apply_velocity
apply_velocity(asteroid, random(0, 360), random(20, 70));

apply_angle(object, angle)

Changes the object's live angle without modifying its JSON declaration.

apply_angle
apply_angle(ball, -45);

apply_rotation_speed(object, speed)

Changes the object's live angular speed.

apply_rotation_speed
apply_rotation_speed(fragment, 180);

restore_speed(object)

Restores live speed to mechanics.motion.speed.start. It does not rebuild accumulated linear velocity.

restore_speed
restore_speed(ball);

advance(object)

Moves the object using its current mechanics state.

For polar objects, advance() uses live angle and speed. If live speed is zero, it can reactivate movement from mechanics.motion.speed.start. Any accumulated or inherited linear velocity is added once as a separate contribution.

advance
function motion(ship) {
    advance(ship);
}

position(object, x, y)

Places an object using logical coordinates. Use position_x(object, x) and position_y(object, y) to modify one axis.

position
position(player, 160, 120);
position_x(player, player.x + 4);

resize(object, width, height)

Changes the object's live size. Use resize_width(object, width) and resize_height(object, height) for one dimension.

resize
resize(paddle, 48, paddle.height);
resize_width(paddle, paddle.width + 8);

reflect_x(object)

Reflects the horizontal component of the object's live movement.

reflect_x
reflect_x(ball);

reflect_y(object)

Reflects the vertical component of the object's live movement.

reflect_y
reflect_y(ball);

console.log(...values)

Sends messages to the internal FLX logger.

console.log
console.log("Ship position:", ship.x, ship.y);

delta()

Returns the elapsed time, in seconds, since the previous frame. FLX clamps this value to a safe maximum of 1 / 30 seconds to avoid large jumps after window moves, pauses or focus stalls.

It allows movement, timers and behaviors to be independent from frame rate without exposing scripts to abnormal frame spikes.

timer
function motion(spawner) {

    const timer = (read_local(spawner, "timer") || 0) + delta();
    write_local(spawner, "timer", timer);

    if (timer > 3) {
        spawn(spawner, "asteroid");
        write_local(spawner, "timer", 0);
    }
}

Draw_text(x, y, text, size, color)

Draws text on screen using logical screen coordinates.

Coordinates are expressed in FLX logical resolution. The engine applies the configured screen scale internally. This is a screen-space helper. World text should use shape.type = "text".

timer
draw_text( 10, 10, "HELLO ");
draw_text( 40, 10, "WORLD!", 15);
draw_text( 10, 30, "READY", 10, "#ffffff");

*size is optional, by default is 10. color is optional and uses white by default.

draw_pixel(x, y, color)

Draws one immediate screen-space pixel using logical FLX coordinates. The engine applies the video chip output scale internally.

This is an overlay drawing helper, like draw_text(). It does not create runtime objects, does not collide, and is drawn above world objects in this version.

pixels
function draw(space) {
    draw_pixel(4, 10);
    draw_pixel(10, 10, "white");
    draw_pixel(20, 20, "#ffcc00");
}

color is optional and uses white by default. It accepts FLX named colors and hexadecimal color values. The final color is projected through the active video chip.

draw_line(x, y, x1, y1, color)

Draws one immediate screen-space line using logical FLX coordinates. The engine applies the video chip output scale internally.

This is an overlay drawing helper. It does not create runtime objects and does not collide.

line
draw_line(10, 10, 40, 10);
draw_line(10, 20, 40, 40, "#ffcc00");

color is optional and uses white by default. The final color is projected through the active video chip.

draw_rectangle(x, y, width, height, color)

Draws one immediate screen-space rectangle outline using logical FLX coordinates. The engine applies the video chip output scale internally.

This is an overlay drawing helper. It does not create runtime objects and does not collide.

rectangle
draw_rectangle(8, 8, 40, 20);
draw_rectangle(60, 8, 30, 30, "green");

color is optional and uses white by default. The final color is projected through the active video chip.

fade_on(color)

Starts a full-screen fade from transparent to opaque. The overlay is drawn above the world and above text drawn with draw_text().

The color parameter is optional. If omitted, the fade uses black. Named colors and hexadecimal colors such as #000 and #000000 are supported. The final color is projected through the active video chip.

fade_on
fade_on();
fade_on("black");
fade_on("#000000");

The transition currently lasts one second and remains fully covered when it finishes.

fade_off(color)

Starts a full-screen fade from opaque to transparent. When the transition finishes, the overlay becomes inactive.

The color parameter is optional and follows the same color rules as fade_on().

fade_off
fade_off();
fade_off("black");
fade_off("#000000");

Duration and intensity parameters are intentionally not part of the API yet. They are planned as future extensions.

fade_set(alpha, color)

Sets the fade overlay alpha immediately. 0 means fully visible and 1 means fully covered. The value is clamped between 0 and 1.

fade_set
function born(title) {
    fade_set(1);
    fade_off();
}

fade_set(0, "black");

The color parameter is optional and uses black by default.

fade_active()

Returns true while a fade transition is running. It returns false when the overlay is stable.

fade_done()

Returns true when there is no fade transition running. This is useful before continuing with a scene transition.

fade_alpha()

Returns the current fade alpha.

safe transition
function action(title) {
    if (input_pressed(title, button(0))) {
        write_local(title, "leaving", 1);
        fade_on();
    }

    if (read_local(title, "leaving") == 1 && fade_done()) {
        // load next scene
    }
}

follow_x(object, targetName)

Moves an object horizontally toward another object. The target is resolved internally by name. It only modifies the object's X position.

follow_x
follow_x(cursor, "ball");

Configuration Used

  • object: object that moves.
  • targetName: logical instance name to follow.

follow_y(object, targetName)

Moves an object vertically toward another object. The target is resolved internally by name. It only modifies the object's Y position.

follow_y
follow_y(enemy, "ball");

Configuration Used

  • object: object that moves.
  • targetName: logical instance name to follow.

attach(object)

Enables the attach rules declared in JSON for the object. The object follows its original parent only; this does not create a new parent relationship.

attach
attach(ball);

detach(object)

Disables attach rules. The object keeps its current position and angle.

detach
if (attach_active(ball) && input_pressed(ball, button(0))) {
    detach(ball);
    apply_angle(ball, -45);
}

attach_active(object)

Returns whether the object is currently attached to its original parent.

carry(object, carrier)

Applies the carrier movement delta to another object during the current frame. It does not change parent, attach state, offset, ownership or collision.

carry
function collision(player, platform) {
    carry(player, platform);
}

Input

Input reads logical controls declared by the project input.mapping file and consumed through the active Input Chip. If the manifest omits input.mapping, FLX compiles the default mapping. Machine/Input coverage differences produce warnings, not compilation errors.

Input
const EXIT = button(0);
const FIRE = button(0);
const MOVE = direction(0);

if (input_pressed(system(), EXIT)) {
    exit();
}

move_vertical(player, input_direction(player, MOVE, VERTICAL));

if (input_pressed(player, FIRE)) {
    spawn(player, "laser");
}
  • button(index): logical button descriptor.
  • direction(index): logical direction descriptor.
  • player(index): explicit player subject.
  • system(): system subject.
  • input_pressed(subject, button): true on the frame a mapped button is pressed.
  • input_down(subject, button): true while a mapped button is held.
  • input_released(subject, button): true on the frame a mapped button is released.
  • input_pressed(subject, direction, component), input_down(...) and input_released(...): query a direction component such as UP, LEFT, NEGATIVE or POSITIVE.

kill(object)

Marks an object for destruction.

The object is not removed immediately, but at the end of the current frame. This prevents modifications to the object list while the runtime is processing it.

Before final removal, the runtime will execute the dead(object) phase. That phase cannot cancel destruction. Writing to object.alive from JavaScript is ignored; use kill(object) as the explicit destruction API.

kill
function collision(object, other) {
    kill(object);
}

show(object)

Makes a runtime object visible again. Visibility only affects drawing: action, motion, collision, timers and state time continue to run.

show
show(player);

hide(object)

Hides a runtime object without destroying it. Hidden objects do not draw their declared shape and do not execute their JavaScript draw(object) callback. Writing to object.visible from JavaScript is ignored.

hide
hide(player);

keep_only(object)

Marks every living runtime object for destruction except the exact object passed as parameter. The kept object remains alive, but its children are not preserved automatically.

Objects removed by keep_only() follow the normal dead() and cleanup flow. The runtime is not modified immediately while scripts are iterating.

scene transition
function action(game) {
    if (read_global("startLevel") == 1) {
        keep_only(game);
        spawn(game, "level1");
    }
}

exit()

Requests an orderly shutdown of the current project. The runtime finishes the main loop and then releases resources normally.

exit
function action(menu) {
    if (input_pressed(system(), button(0))) {
        exit();
    }
}

save(name, key, value)

Stores a boolean, number or string in a binary saves/<name>.flxsave file. Saving one key does not remove the other keys from the same file.

save
save("progress", "pong_completed", true);
save("progress", "score", 12500);
save("settings", "music", false);

load(name, key, defaultValue)

Loads a stored value. If the file does not exist, the key does not exist, the file is corrupt or the stored type differs from defaultValue, FLX returns defaultValue.

load
let completed = load("progress", "pong_completed", false);
let score = load("progress", "score", 0);
let music = load("settings", "music", true);

Save files are not JSON or plain text. They include a format version, typed entries, light obfuscation and a simple checksum to detect casual edits or corruption.

move_horizontal(object, intent)

Moves the object horizontally using declared mechanics and a normalized intent in the -1..1 range.

move_horizontal
move_horizontal(player, input_direction(player, direction(0), HORIZONTAL));

move_vertical(object, intent)

Moves the object vertically using declared mechanics and a normalized intent in the -1..1 range.

move_vertical
move_vertical(player, input_direction(player, direction(0), VERTICAL));

input_direction(subject, direction, axis)

Returns normalized directional intent for a logical direction: -1, 0 or 1 in the current digital input implementation. RIGHT and UP are positive; LEFT and DOWN are negative. In a 4way direction, HORIZONTAL reads only LEFT/RIGHT and VERTICAL reads only UP/DOWN. In a 2way direction, positive/negative intent can be projected onto either axis. Mapping files still declare only up, right, down and left; up/right normalize to positive and down/left normalize to negative for 2way chips.

input_direction
const MOVE = direction(0);

move_horizontal(player, input_direction(player, MOVE, HORIZONTAL));
move_vertical(player, input_direction(player, MOVE, VERTICAL));

system() is not a valid subject for input_direction().

ray(source, angle, distance)

Casts an invisible ray from a runtime object and returns the closest compatible collision hit.

The ray starts at source.position, uses FLX logical coordinates, and follows the same angle convention as advance(). It does not draw anything on screen.

ray
function motion(tank) {
    let sight = ray(tank, tank.angle, 200);

    if (sight.hit && sight.group == "player") {
        spawn(tank, "bullet");
    }
}

Return Value

  • No hit: { hit: false, group: "" }
  • Hit: { hit: true, group, distance, x, y }

Collision Rules

  • The group filter comes from source.collision.with.
  • The hit object does not need collision.active = true.
  • Invisible objects can be hit if their collision is valid.
  • The source object, dead objects and unsupported collision types are ignored.
  • This version supports circle and box collisions.

probability(chance, base)

Returns true randomly according to the specified probability.

If base is not specified, the default value is 100.

For example:

  • probability(30) → approximately 30 out of every 100 calls.
  • probability(20, 1000) → approximately 20 out of every 1000 calls.
probability
if (probability(5)) {
    spawn(object, "enemy");
}

if (probability(1, 1000)) {
    spawn(object, "rare_enemy");
}

play_sound(object, id)

Plays a sound declared in the object's sounds block.

The id parameter identifies the sound declaration owned by that object.

play_sound
if (input_pressed(ship, button(0))) {
    play_sound(ship, "laser");
    spawn(ship, "laser");
}

Configuration Used

  • object: object that owns the sound declaration.
  • id: name of the sound declared in JSON.

play_music(object, id)

Plays generated music declared in the object's music block. If another song is playing, it is replaced.

play_music
function born(game) {
    play_music(game, "theme");
}

Configuration Used

  • object: object that owns the music declaration.
  • id: name of the song declared in JSON.

Music uses Audio Chip voices.music. Extra channels beyond that limit are ignored with a warning.

stop_music()

Stops the current generated music.

pause_music()

Pauses the current music, or resumes it if it is already paused.

music_active()

Returns true while generated music is active.

music_paused()

Returns true when the current music is paused.

random(min, max)

Returns a random value between min and max.

Useful for movement variation, procedural generation and dynamic behavior.

random
apply_angle(asteroid, random(0, 360));
apply_speed(asteroid, random(20, 80));

Parameters

  • min: minimum value.
  • max: maximum value.

rotate(object, direction)

Rotates the object using declared rotation mechanics, runtime rotationSpeed and frame time.

rotate
rotate(ship, LEFT);
rotate(ship, RIGHT);

spawn(object, childName)

Creates an instance of a child declared in the object's children block.

The childName parameter identifies which child definition should be instantiated.

Children with spawn: "manual" wait until spawn() is called. Children with spawn: "auto" are created when the parent enters the world, but spawn() may also create another instance later.

The spawned object inherits the position and orientation required to correctly apply that offset.

spawn
if (input_pressed(ship, button(0))) {
    spawn(ship, "laser");
}

Configuration Used

  • object: object performing the spawn.
  • childName: name of the child declared in JSON.

Internally, spawned objects are not inserted into the world immediately.

FLX uses a spawn queue to avoid modifying the object collection while the runtime is iterating over it.

state_to(object, stateName)

Requests a transition for an object that declares states in JSON. The transition is validated against the current state's next list. 

if (state_active(game, "title") && input_pressed(game, button(0))) {
    state_to(game, "playing");
}
  • state_current(object): returns the current state name, or "" when the object has no state machine.
  • state_active(object, "name"): checks the current state. Objects without a state machine always return false.
  • state_entered(object): true only during the first full runtime frame after the object enters its current state.
  • state_time(object): seconds elapsed since entering the current state. The first full frame reports 0.

States do not run callbacks automatically. Scripts keep deciding when transitions happen and what each state does. state_to has no legacy alias.

play_timer(object, name, duration?)

Starts, resumes, or redefines a named timer owned by the object. Timers update automatically and disappear with their owner. A finished timer remains observable as done until it is played again, stopped with stop_timer(), or its owner is destroyed. 

play_timer(paddle, "gun", 5);

if (timer_active(paddle, "gun")) {
    attach(ball);
}

pause_timer(paddle, "gun");
play_timer(paddle, "gun");
stop_timer(paddle, "gun");
  • play_timer(object, "name"): resumes a paused timer or replays a done timer from its known duration.
  • play_timer(object, "name", duration): creates or retimes a timer using total duration, preserving elapsed time when it already exists.
  • pause_timer(object, "name"): pauses a running timer without clearing it.
  • stop_timer(object, "name"): removes the timer immediately. Stop is not done.
  • timer_active(object, "name"): true while the timer is running or paused.
  • timer_paused(object, "name"): true only while the timer is paused.
  • timer_done(object, "name"): true only after natural completion.
  • timer_left(object, "name"): remaining seconds, or 0 when absent, stopped, or done.

position(object, x, y)

Places the object immediately at the specified logical position. This does not change speed, velocity, angle, timers or local state.

position
position(ball, 160, 90);

position_origin(object)

Places the object at its effective runtime origin. To also restore live speed, call restore_speed(object) explicitly.

position_origin
position_origin(ball);
restore_speed(ball);
