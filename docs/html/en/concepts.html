FLX Documentation

Core Concepts

FLX organizes projects through simple data structures, objects, transformations and clearly defined execution rules.

This section describes the fundamental concepts that are part of every FLX project.

Project

Every FLX project begins with a project file using the .flx extension.

This file acts as the project's entry point.

Asteroids.flx
name=Asteroids
version=1.0
engine=0.2.0
path=asteroids
root=space
title=Asteroids
machine=machines/standard.yml

From this file, the runtime loads the root object, resources and required configuration. If the file declares machine, FLX also loads the referenced YAML Machine and its chips.

Root Object

The root object is the object selected by the root field in the .flx file.

It is a normal JSON object that organizes objects, resources and execution logic.

Depending on the project, it may represent:

  • A level
  • A menu
  • A loading screen
  • A presentation
  • A narrative sequence
  • A specific application state

FLX does not impose a specific interpretation.

Objects

Objects represent elements that exist within the runtime.

An object may:

  • Be rendered
  • Move
  • Collide
  • Store data
  • Execute behavior through scripts

Objects are typically described using JSON.

A definition may be written entirely or built by reusing another definition through like.

ship.json
{
    "shape": {
        "type": "triangle"
    },

    "mechanics": {
        "type": "polar",
        "motion": {
            "speed": { "limit": 180 }
        }
    }
}

Reuse and Composition

FLX allows new definitions to be built from existing ones.

This capability is based on the like system, which allows configurations to be reused while overriding only the required fields.

DeepSpaceLeft
{
    "name": "DeepSpaceLeft",

    "like": "asteroid/deep_space",

    "origin": {
        "x": 5,
        "y": 5
    }
}

This feature makes it possible to build entire families of objects from a single base definition.

An object does not require a visual representation to exist within the runtime.

If it defines behavior, children or collision, it can act as a logical node, level manager, HUD, spawner, trigger or game controller.

Additionally, name identifies an object logically or conceptually, while id identifies a specific runtime instance.

Full details are described in JSON Reference.

Children and Spawn Timing

FLX uses children to declare what may exist below an object. The child spawn value defines when it enters the runtime. The optional creation block defines how the parent creates those children.

  • spawn: "auto": the child is instantiated when the parent enters the world.
  • spawn: "manual": the child is registered and can be created later with spawn(parent, "child").

spawn(parent, "child") can create any declared child. The spawn value only controls whether the first instance is created automatically when the parent enters the world.

Together with like, this keeps object composition, reuse and dynamic creation under one JSON property.

When creation is omitted, the parent behaves as creation.mode = "individual": each child is handled by its own declaration. In grid mode, the parent position becomes the grid origin, the pattern chooses which child belongs to each cell, and spawn(parent, "child") creates the matching cells instead of a free instance.

Shape Types

FLX provides several basic visual representation types.

Type Origin
block Pivot / center
rectangle Pivot / center
triangle Pivot / center
line Pivot / center
polygon Pivot
text Pivot / box center

Colors can be declared directly from JSON using raylib color names or hexadecimal values in #rgb and #rrggbb format.

shape.json
"shape": {
    "type": "triangle",
    "color": "#2f3a44"
}

Polygons allow irregular shapes to be defined through lists of points.

polygon
"shape": {
    "type": "polygon",

    "points": [
        { "x": 0, "y": -16 },
        { "x": 12, "y": -8 },
        { "x": 16, "y": 8 },
        { "x": -8, "y": 14 }
    ]
}

Shape and Collision

In FLX, visual representation and collision are independent systems.

The shape block defines how an object is rendered, while the collisions block defines how it interacts with other objects in the runtime.

In many cases both definitions may be similar, but they are not required to match.

In addition to defining named collider shapes, the collisions block can control whether each collider is enabled and which groups it can actively check.

Collision checks are directional: an object only executes collision(object, other, contacts) when one of its enabled colliders includes the other object's group in its with list.

shape + collisions
{
    "shape": {
        "type": "polygon"
    },

    "collisions": {
        "body": {
            "type": "ellipse",
            "size": { "width": 24, "height": 24 }
        }
    }
}

This separation allows collision to remain simple and efficient while visual representation can be as detailed as necessary.

Coordinate System

FLX uses a 2D coordinate system with its origin in the top-left corner of the screen.

  • x grows to the right.
  • y grows downward.
  • Moving up decreases y.
  • Moving down increases y.

At the moment, FLX uses logical screen coordinates in a fixed world without cameras or scrolling.

Objects use these coordinates for their position within the runtime. Text rendering functions such as draw_text() also use logical screen coordinates.

Camera systems, scrolling and the formal separation between world, screen, view and local coordinate spaces remain planned for future versions.

Angular System

FLX uses its own angular convention.

  • 0° points upward.
  • 90° points right.
  • 180° points downward.
  • 270° points left.
  • Positive angles rotate clockwise.
rotation
rotate(ship, RIGHT);
advance(ship);

Movement

FLX combines a classic speed-based system with an acceleration and inertia-based system.

Common movement-related properties include:

  • speed
  • velocityX
  • velocityY
  • acceleration
  • inertia
  • rotationSpeed

Movement functions automatically follow the FLX angular convention.
