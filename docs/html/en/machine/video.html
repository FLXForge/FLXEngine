Video Chip

Index · Video · Audio · Input

Screen · Color · color.palette · color.levels · color.tone · color.alpha · Output · Accepted fields without a specific functional effect

Video Chip defines the logical screen, color capabilities and how that screen is presented physically. It is declared in machine.video, inline or as an external chip.

Structure
video
├── screen: width, height, color
├── color
│   ├── palette
│   ├── levels: red, green, blue
│   ├── tone: base, levels
│   └── alpha
├── planes: enabled
├── objects: sprites
└── output: scale, smoothing

Screen

Logical screen
FieldType / valuesDefaultBehavior in v0.3.0
screen.widthInteger ≥ 1640Width of the logical screen and render texture.
screen.heightInteger ≥ 1480Height of the logical screen and render texture.
screen.colorColor stringblackClear color; passes through Machine color processing.
Presentation scale
Logical screen
320 × 180
    ↓ output.scale = 3
Window
960 × 540

Scale does not modify logical coordinates or dimensions. The example corresponds to a window with that effective scale; execution options can override scale or select fullscreen. Video resolution also does not redefine the logical World extent used by delimit and bounds.

Screen and output
machine:
  video:
    screen:
      width: 320
      height: 180
      color: black
    output:
      scale: 3
      smoothing: false

Color

Requested color and effective color
Visual requests a color
        ↓
Video Chip determines which color it can represent
        ↓
Effective color

The requested color belongs to JSON Visual. Video projects it onto Machine capabilities. The screen's clear color is also processed. Colors are expressed as names supported by FLX or as hexadecimal strings "#RGB" and "#RRGGBB".

Effective precedence
valid nonempty palette
    ↓ if absent
configured tone
    ↓ if absent
declared levels
    ↓ if absent
original color

The three models are not chained: the first available one is used according to this precedence. alpha is applied independently of the chosen model.

color.palette

Color list. By default there is no active palette; an empty list does not activate the model either. With an active nonempty palette, the color closest to the requested color by RGB distance is selected. Takes priority over tone and levels.

Limited palette
machine:
  video:
    color:
      palette: ["#000000", "#FFFFFF", "#FF4040"]

color.levels

Independent per-channel quantization
FieldType / valuesDefaultBehavior in v0.3.0
color.levels.redInteger ≥ 00Number of red channel levels when the levels block is declared.
color.levels.greenInteger ≥ 00Number of green channel levels.
color.levels.blueInteger ≥ 00Number of blue channel levels.

These are levels, not bits. A value of 2 allows two levels in that channel. Both 0 and 1 produce a zero channel in the current implementation. Omitting the entire levels block leaves this model inactive; declaring it with an omitted channel leaves that channel at its default of 0. It is therefore advisable to declare all three color axes explicitly.

RGB levels
machine:
  video:
    color:
      levels:
        red: 4
        green: 4
        blue: 2

color.tone

Tonal range
FieldType / valuesDefaultBehavior in v0.3.0
color.tone.baseColor stringNo baseColor from which the tonal range is derived.
color.tone.levelsInteger ≥ 1 if declaredNo active rangeNumber of colors in the range. Needs a base and a valid number of levels to activate.

Tone restricts the effective color to a range derived from the base. It is not a free-form palette: the range is generated from base and levels. Use quoted hexadecimal colors in YAML to make them unambiguous.

Tonal range
machine:
  video:
    color:
      tone:
        base: "#9BBC0F"
        levels: 4

color.alpha

Boolean, default true. With false, the processor forces opaque output. With true, it preserves the received color's alpha, even when projecting it onto a palette or tonal range.

Opaque output
machine:
  video:
    color:
      alpha: false

Output

Physical presentation
FieldType / valuesDefaultBehavior in v0.3.0
output.scaleInteger ≥ 11Requested scale factor for windowed presentation.
output.smoothingBooleanfalsefalse uses point filtering; true uses bilinear.

smoothing: false retains hard pixel scaling suitable for pixel art. The filter applies to the output texture; it does not change the game's logical coordinates.
