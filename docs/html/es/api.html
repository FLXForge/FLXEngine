FLX Documentation

FLX API

Esta sección documenta las funciones JavaScript expuestas por FLX al runtime.

FLX está en desarrollo activo. Algunas funciones pueden cambiar durante las versiones 0.x.

Constantes

FLX expone constantes globales para trabajar con componentes logicos de direccion de forma legible. Los scripts no deben depender de su representacion numerica.

Dirección

  • UP: componente logico arriba.
  • DOWN: componente logico abajo.
  • LEFT: componente logico izquierda.
  • RIGHT: componente logico derecha.
  • NEGATIVE: componente logico negativo.
  • POSITIVE: componente logico positivo.
  • STOP: movimiento neutro o detenido.

RuntimeObject

Los objetos recibidos por las funciones de scripting son instancias de RuntimeObject.

Un RuntimeObject representa una entidad viva dentro del runtime y contiene tanto datos definidos mediante JSON como estado generado durante la ejecución.

RuntimeObject
function motion(ship) {

    ship.x += 10;

    console.log(ship.id);
}

id

Identificador único de la instancia dentro del runtime.

A diferencia de name, cada objeto generado recibe un identificador exclusivo.

id
console.log(ship.id);

name

Nombre lógico del objeto.

Habitualmente proviene de la definición JSON.

name
console.log(ship.name);

local

Estado persistente asociado a una instancia concreta.

Los valores almacenados en object.local permanecen mientras el objeto exista.

local
ship.local["timer"] += delta();

group

Grupo lógico asociado al objeto.

Puede utilizarse para clasificar entidades o para futuros sistemas de filtrado.

Posición y tamaño

  • x: posición horizontal.
  • y: posición vertical.
  • width: ancho.
  • height: alto.

Movimiento

  • speed: velocidad actual.
  • originSpeed: velocidad inicial.
  • velocityX: velocidad horizontal.
  • velocityY: velocidad vertical.
  • rotationSpeed: velocidad angular actual.

Origen

  • originX: posición inicial X.
  • originY: posición inicial Y.

angle

La propiedad angle representa la rotación actual del objeto en grados.

FLX utiliza la siguiente convención:

  • 0: arriba.
  • 90: derecha.
  • 180: abajo.
  • 270: izquierda.

accelerate(object, intent)

Aplica aceleracion usando la declaracion mechanics del objeto y lo mueve durante el mismo frame. intent es opcional y por defecto vale 1.

accelerate
accelerate(ship);
accelerate(ship, input_direction(ship, direction(0), VERTICAL));

Configuración utilizada

  • mechanics.motion.acceleration: tasa de aceleracion.
  • mechanics.motion.speed.limit: velocidad viva maxima.
  • angle: direccion actual en mecanicas polares.
  • velocityX y velocityY: velocidad acumulada.

apply_speed(object, value)

Aplica una velocidad viva sin cambiar la declaracion JSON. Si mechanics.motion.speed.limit es mayor que cero, FLX limita el valor solicitado a ese maximo. En mecanicas polares cambia la velocidad polar propia del objeto; la velocity heredada o acumulada en velocityX/velocityY permanece separada. En mecanicas directas, el movimiento por eje sin aceleracion usa esta velocidad viva.

apply_speed
apply_speed(ball, ball.speed + 5);

restore_speed(object)

Restaura la velocidad viva a mechanics.motion.speed.start. No reconstruye la velocity lineal acumulada.

restore_speed
restore_speed(ball);

advance(object)

Avanza el objeto usando su estado de mecanicas actual.

En objetos polares, advance() usa angulo y velocidad vivos. Si la velocidad viva esta en cero, puede reactivar el movimiento desde mechanics.motion.speed.start. Cualquier velocity lineal acumulada o heredada se suma una sola vez como contribucion separada.

advance
function motion(ship) {
    advance(ship);
}

reflect_x(object)

Refleja la componente horizontal del movimiento vivo del objeto.

reflect_x
reflect_x(ball);

reflect_y(object)

Refleja la componente vertical del movimiento vivo del objeto.

reflect_y
reflect_y(ball);

console.log(...values)

Envía mensajes al logger interno de FLX.

console.log
console.log("Ship position:", ship.x, ship.y);

delta()

Nota: FLX limita delta() a un maximo seguro de 1 / 30 segundos para evitar saltos grandes al mover la ventana, pausar el sistema o recuperar el foco.

Retorna el tiempo transcurrido, en segundos, desde el frame anterior.

Permite crear movimientos, temporizadores y comportamientos independientes de la velocidad de ejecución.

timer
function motion(spawner) {

    spawner.local["timer"] += delta();

    if (spawner.local["timer"] > 3) {
        spawn(spawner, "asteroid");
        spawner.local["timer"] = 0;
    }
}

Draw_text(x, y, text, size, color)

Dibuja texto en pantalla usando las coodenadas definidas en screen.

Las coordenadas son expresadas en FLX como coordenadas de resolución. El motor aplica la configuración de escalada de forma automática.

timer
draw_text( 10, 10, "HELLO ");
draw_text( 40, 10, "WORLD!", 15);
draw_text( 10, 30, "READY", 10, "#ffffff");

*size es opcional, por defecto es 10. color es opcional y usa blanco por defecto.

draw_pixel(x, y, color)

Dibuja un pixel inmediato en pantalla usando coordenadas logicas FLX. El motor aplica internamente la escala de salida del chip de video.

Es una funcion de dibujo de overlay, igual que draw_text(). No crea runtime objects, no colisiona y en esta version se dibuja por encima de los objetos del mundo.

pixels
function draw(space) {
    draw_pixel(4, 10);
    draw_pixel(10, 10, "white");
    draw_pixel(20, 20, "#ffcc00");
}

color es opcional y usa blanco por defecto. Acepta colores con nombre de FLX y valores hexadecimales. El color final se proyecta mediante el chip de video activo.

draw_line(x, y, x1, y1, color)

Dibuja una linea inmediata en pantalla usando coordenadas logicas FLX. El motor aplica internamente la escala de salida del chip de video.

Es una funcion de dibujo de overlay. No crea runtime objects y no colisiona.

line
draw_line(10, 10, 40, 10);
draw_line(10, 20, 40, 40, "#ffcc00");

color es opcional y usa blanco por defecto. El color final se proyecta mediante el chip de video activo.

draw_rectangle(x, y, width, height, color)

Dibuja el contorno de un rectangulo inmediato en pantalla usando coordenadas logicas FLX. El motor aplica internamente la escala de salida del chip de video.

Es una funcion de dibujo de overlay. No crea runtime objects y no colisiona.

rectangle
draw_rectangle(8, 8, 40, 20);
draw_rectangle(60, 8, 30, 30, "green");

color es opcional y usa blanco por defecto. El color final se proyecta mediante el chip de video activo.

fade_on(color)

Inicia un desvanecimiento de pantalla completa desde transparente hasta opaco. La superposicion se dibuja por encima del mundo y por encima del texto dibujado con draw_text().

El parametro color es opcional. Si no se indica, se usa negro. Se admiten colores con nombre y colores hexadecimales como #000 y #000000. El color final se proyecta mediante el chip de video activo.

fade_on
fade_on();
fade_on("black");
fade_on("#000000");

La transicion dura actualmente un segundo y queda completamente cubierta al finalizar.

fade_off(color)

Inicia un desvanecimiento de pantalla completa desde opaco hasta transparente. Al terminar, la superposicion queda inactiva.

El parametro color es opcional y sigue las mismas reglas de color que fade_on().

fade_off
fade_off();
fade_off("black");
fade_off("#000000");

Los parametros de duracion e intensidad no forman parte de la API todavia. Quedan planteados como ampliaciones futuras.

fade_set(alpha, color)

Establece inmediatamente el alpha del fundido. 0 significa pantalla descubierta y 1 pantalla completamente cubierta. El valor se limita entre 0 y 1.

fade_set
function born(title) {
    fade_set(1);
    fade_off();
}

fade_set(0, "black");

El parametro color es opcional y usa negro por defecto.

fade_active()

Devuelve true mientras hay una transicion de fundido en curso. Devuelve false cuando el overlay esta estable.

fade_done()

Devuelve true cuando no hay ninguna transicion de fundido en curso. Sirve para continuar una transicion de escena de forma segura.

fade_alpha()

Devuelve el alpha actual del fundido.

transicion segura
function action(title) {
    if (input_pressed(title, button(0))) {
        title.local["leaving"] = 1;
        fade_on();
    }

    if (title.local["leaving"] == 1 && fade_done()) {
        // cargar siguiente escena
    }
}

follow_x(object, targetName)

Mueve un objeto horizontalmente hacia otro objeto. El objetivo se resuelve internamente por nombre. Solo modifica la posicion X del objeto.

follow_x
follow_x(cursor, "ball");

Configuracion utilizada

  • object: objeto que se mueve.
  • targetName: nombre logico de la instancia seguida.

follow_y(object, targetName)

Mueve un objeto verticalmente hacia otro objeto. El objetivo se resuelve internamente por nombre. Solo modifica la posicion Y del objeto.

follow_y
follow_y(enemy, "ball");

Configuración utilizada

  • object: objeto que se mueve.
  • targetName: nombre logico de la instancia seguida.

attach(object)

Activa las reglas de attach declaradas en JSON para el objeto. El objeto sigue solo a su parent original; no crea una nueva relacion de parent.

attach
attach(ball);

detach(object)

Desactiva las reglas de attach. El objeto conserva su posicion y angulo actuales.

detach
if (attach_active(ball) && input_pressed(ball, button(0))) {
    detach(ball);
    ball.angle = -45;
}

attach_active(object)

Devuelve si el objeto esta unido actualmente a su parent original.

carry(object, carrier)

Aplica al objeto el desplazamiento del carrier durante el frame actual. No cambia parent, attach, offset, ownership ni collision.

carry
function collision(player, platform) {
    carry(player, platform);
}

Input

Input lee controles logicos declarados en el archivo input.mapping del proyecto y limitados por el Input Chip activo.

Input
const EXIT = button(0);
const FIRE = button(0);
const MOVE = direction(0);

if (input_pressed(system(), EXIT)) {
    exit();
}

move_vertical(player, input_direction(player, MOVE, VERTICAL));

if (input_pressed(player, FIRE)) {
    spawn(player, "laser");
}
  • button(index): descriptor de boton logico.
  • direction(index): descriptor de direccion logica.
  • player(index): sujeto explicito de jugador.
  • system(): sujeto de sistema.
  • input_pressed(subject, button): true en el frame en que se pulsa un boton mapeado.
  • input_down(subject, button): true mientras un boton mapeado esta pulsado.
  • input_released(subject, button): true en el frame en que se suelta un boton mapeado.
  • input_pressed(subject, direction, component), input_down(...) e input_released(...): consulta un componente de direccion como UP, LEFT, NEGATIVE o POSITIVE.

kill(object)

Marca un objeto para ser destruido.

El objeto no se elimina inmediatamente, sino al final del frame actual. Esto evita modificar la lista de objetos mientras el runtime la está procesando.

Antes de la eliminación definitiva, el runtime ejecutará la fase dead(object). Esa fase no puede cancelar la destrucción. Escribir object.alive desde JavaScript se ignora; usa kill(object) como API explícita de destrucción.

kill
function collision(object, other) {
    kill(object);
}

show(object)

Vuelve a hacer visible un runtime object. La visibilidad solo afecta al dibujado: action, motion, collision, timers y state time siguen ejecutándose.

show
show(player);

hide(object)

Oculta un runtime object sin destruirlo. Los objetos ocultos no dibujan su shape declarativa ni ejecutan su callback JavaScript draw(object). Escribir object.visible desde JavaScript se ignora.

hide
hide(player);

keep_only(object)

Marca para destruccion todos los runtime objects vivos excepto el objeto exacto pasado como parametro. El objeto indicado se conserva, pero sus hijos no se conservan automaticamente.

Los objetos eliminados por keep_only() siguen el flujo normal de dead() y cleanup. El runtime no se modifica inmediatamente mientras los scripts estan iterando.

transicion de escena
function action(game) {
    if (global["startLevel"] == 1) {
        keep_only(game);
        spawn(game, "level1");
    }
}

exit()

Solicita el cierre ordenado del proyecto actual. El runtime termina el bucle principal y despues libera recursos normalmente.

exit
function action(menu) {
    if (input_pressed(system(), button(0))) {
        exit();
    }
}

save(name, key, value)

Guarda un boolean, number o string en un archivo binario saves/<name>.flxsave. Guardar una clave no elimina las demas claves del mismo archivo.

save
save("progress", "pong_completed", true);
save("progress", "score", 12500);
save("settings", "music", false);

load(name, key, defaultValue)

Carga un valor guardado. Si el archivo no existe, la clave no existe, el archivo esta corrupto o el tipo guardado no coincide con defaultValue, FLX devuelve defaultValue.

load
let completed = load("progress", "pong_completed", false);
let score = load("progress", "score", 0);
let music = load("settings", "music", true);

Los archivos de guardado no son JSON ni texto plano. Incluyen version de formato, entradas tipadas, ofuscacion ligera y un checksum simple para detectar ediciones casuales o corrupcion.

move_horizontal(object, intent)

Desplaza el objeto horizontalmente usando sus mecanicas declaradas y una intencion normalizada en el rango -1..1.

move_horizontal
move_horizontal(tofu, input_direction(tofu, direction(0), HORIZONTAL));

move_vertical(object, intent)

Desplaza el objeto verticalmente usando sus mecanicas declaradas y una intencion normalizada en el rango -1..1.

move_vertical
move_vertical(tofu, input_direction(tofu, direction(0), VERTICAL));

input_direction(subject, direction, axis)

Devuelve intencion direccional normalizada para una direccion logica: -1, 0 o 1 en la implementacion digital actual. RIGHT y UP son positivos; LEFT y DOWN son negativos. En una direccion 4way, HORIZONTAL lee solo LEFT/RIGHT y VERTICAL lee solo UP/DOWN. En una direccion 2way, la intencion positiva/negativa puede proyectarse sobre cualquiera de los dos ejes.

input_direction
const MOVE = direction(0);

move_horizontal(tofu, input_direction(tofu, MOVE, HORIZONTAL));
move_vertical(tofu, input_direction(tofu, MOVE, VERTICAL));

system() no es un subject valido para input_direction().

ray(source, angle, distance)

Lanza un rayo invisible desde un runtime object y devuelve el impacto compatible mas cercano.

El rayo nace en source.position, usa coordenadas logicas FLX y sigue la misma convencion de angulo que advance(). No dibuja nada en pantalla.

ray
function motion(tank) {
    let sight = ray(tank, tank.angle, 200);

    if (sight.hit && sight.group == "player") {
        spawn(tank, "bullet");
    }
}

Valor devuelto

  • Sin impacto: { hit: false, group: "" }
  • Con impacto: { hit: true, group, distance, x, y }

Reglas de colision

  • El filtro de grupos sale de source.collision.with.
  • El objeto impactado no necesita collision.active = true.
  • Los objetos invisibles pueden ser detectados si su collision es valida.
  • Se ignoran el propio source, objetos muertos y tipos de collision no soportados.
  • Esta version soporta colisiones circle y box.

probability(chance, base)

Retorna true de forma aleatoria en función de la probabilidad indicada.

Si no se especifica base, el valor por defecto es 100.

Por ejemplo:

  • probability(30) → aproximadamente 30 de cada 100 llamadas.
  • probability(20, 1000) → aproximadamente 20 de cada 1000 llamadas.
probability
if (probability(5)) {
    spawn(object, "enemy");
}

if (probability(1, 1000)) {
    spawn(object, "rare_enemy");
}

play_sound(object, id)

Reproduce un sonido declarado en el bloque sounds del objeto.

El parametro id identifica la declaracion de sonido que pertenece a ese objeto.

play_sound
if (input_pressed(ship, button(0))) {
    play_sound(ship, "laser");
    spawn(ship, "laser");
}

Configuracion utilizada

  • object: objeto que posee la declaracion de sonido.
  • id: nombre del sonido declarado en JSON.

play_music(object, id)

Reproduce musica generada declarada en el bloque music del objeto. Si ya hay otra cancion sonando, se sustituye.

play_music
function born(game) {
    play_music(game, "theme");
}

Configuracion utilizada

  • object: objeto que posee la declaracion de musica.
  • id: nombre de la cancion declarada en JSON.

La musica usa voices.music del Audio Chip. Los canales sobrantes se ignoran con un warning.

stop_music()

Detiene la musica generada actual.

pause_music()

Pausa la musica actual, o la reanuda si ya estaba pausada.

music_active()

Devuelve true mientras hay musica generada activa.

music_paused()

Devuelve true cuando la musica actual esta pausada.

random(min, max)

Retorna un valor aleatorio comprendido entre min y max.

Resulta útil para variaciones de movimiento, generación procedural y comportamiento dinámico.

random
asteroid.angle = random(0, 360);

asteroid.speed = random(20, 80);

Parámetros

  • min: valor mínimo.
  • max: valor máximo.

rotate(object, direction)

Rota el objeto usando sus mecanicas de rotacion declaradas, rotationSpeed vivo y el tiempo de frame.

rotate
rotate(ship, LEFT);
rotate(ship, RIGHT);

spawn(object, childName)

Crea una instancia de un hijo declarado en el bloque children del objeto.

El parámetro childName identifica qué definición hija debe instanciarse.

Los hijos con spawn: "manual" esperan hasta que se llama a spawn(). Los hijos con spawn: "auto" nacen cuando el padre entra en el mundo, pero spawn() tambien puede crear otra instancia mas tarde.

El objeto generado hereda la posición y orientación necesarias para aplicar correctamente dicho offset.

spawn
if (input_pressed(ship, button(0))) {
    spawn(ship, "laser");
}

Configuración utilizada

  • object: objeto desde el que se ejecuta el spawn.
  • childName: nombre del hijo declarado en el JSON.

Internamente, los objetos generados no se insertan inmediatamente en el mundo.

FLX utiliza una cola de spawn para evitar modificar la colección de objetos mientras el runtime la está recorriendo.

state_to(object, stateName)

Solicita una transicion para un objeto que declara states en JSON. La transicion se valida contra la lista next del estado actual. 

if (state_active(game, "title") && input_pressed(game, button(0))) {
    state_to(game, "playing");
}
  • state_current(object): devuelve el estado actual, o "" si el objeto no tiene maquina de estados.
  • state_active(object, "name"): comprueba el estado actual. Los objetos sin maquina de estados siempre devuelven false.
  • state_entered(object): true solo durante el primer frame completo de runtime despues de que el objeto entra en su estado actual.
  • state_time(object): segundos transcurridos desde la entrada en el estado actual. El primer frame completo devuelve 0.

Los estados no ejecutan callbacks automaticos. Los scripts siguen decidiendo cuando ocurren las transiciones y que hace cada estado. state_to no tiene alias heredado.

play_timer(object, name, duration?)

Inicia, reanuda o redefine un temporizador nombrado propiedad del objeto. El runtime actualiza los temporizadores automaticamente y se destruyen junto con su propietario. Un temporizador terminado permanece observable como done hasta que se reproduzca otra vez, se elimine con stop_timer(), o se destruya su propietario. 

play_timer(paddle, "gun", 5);

if (timer_active(paddle, "gun")) {
    attach(ball);
}

pause_timer(paddle, "gun");
play_timer(paddle, "gun");
stop_timer(paddle, "gun");
  • play_timer(object, "name"): reanuda un temporizador pausado o reproduce uno terminado desde su duracion conocida.
  • play_timer(object, "name", duration): crea o reajusta un temporizador usando duracion total y conserva el tiempo transcurrido si ya existe.
  • pause_timer(object, "name"): pausa un temporizador en marcha sin eliminarlo.
  • stop_timer(object, "name"): elimina el temporizador inmediatamente. Stop no es done.
  • timer_active(object, "name"): true mientras el temporizador esta en marcha o pausado.
  • timer_paused(object, "name"): true solo mientras el temporizador esta pausado.
  • timer_done(object, "name"): true solo tras finalizacion natural.
  • timer_left(object, "name"): segundos restantes, o 0 cuando esta ausente, detenido o terminado.

position(object, x, y)

Coloca el objeto inmediatamente en la posicion logica indicada. No cambia velocidad, angulo, timers ni estado local.

position
position(ball, 160, 90);

position_origin(object)

Coloca el objeto en su origen efectivo de runtime. Para restaurar tambien la velocidad viva, llama explicitamente a restore_speed(object).

position_origin
position_origin(ball);
restore_speed(ball);
