FLX Documentation

Roadmap

FLX se desarrolla de forma incremental y práctica.

Cada juego permite poner a prueba las capacidades existentes, combinarlas en situaciones reales y descubrir qué necesita evolucionar antes de avanzar.

Principio de desarrollo

FLX evoluciona a partir de necesidades encontradas al construir juegos reales.

Antes de añadir una nueva capacidad al engine, se intenta resolver el problema combinando las capacidades que ya existen. Cuando una limitación impide hacerlo de forma razonable, esa limitación se convierte en candidata a evolución del runtime.

De esta forma, las nuevas funcionalidades nacen del uso del engine y no de intentar anticipar todas las características que podría necesitar.

FLX v0.3.0 · Consolidación de la base

FLX v0.3.0 consolida la primera base estable del engine.

Pong, Asteroids, Arkanoid, Invaders y Tank han servido para desarrollar, revisar y unificar el modelo con el que se construyen los mundos de FLX.

Esta versión establece una base común para:

  • declaración, composición y creación de objetos;
  • representación visual y dibujo inmediato;
  • movimiento, orientación e inercia;
  • input y controles lógicos;
  • colisiones y consultas espaciales;
  • estado, temporizadores y ciclo de vida;
  • relaciones entre objetos;
  • sonido y música;
  • machines y configuración del entorno;
  • scripting y API JavaScript;
  • CLI, diagnostics y validación del proyecto.

El objetivo de esta versión no es cerrar las posibilidades de FLX, sino disponer de una base coherente sobre la que construir y experimentar.

Direcciones futuras

A partir de v0.3.0, FLX continuará evolucionando mediante el desarrollo de nuevos juegos y la incorporación progresiva de nuevas capacidades.

Estas líneas representan direcciones de exploración, no compromisos con una versión concreta.

Máquinas y nuevas generaciones

Las machines permiten expresar las capacidades y restricciones del entorno sobre el que se ejecuta un mundo FLX.

Su evolución permitirá explorar progresivamente nuevas formas de construir juegos y representar distintas generaciones de sistemas 2D.

Scroll, espacios y cámara

El movimiento del mundo más allá de una única pantalla abre una nueva etapa para FLX.

El desarrollo de scroll y, cuando sea necesario, de un modelo de cámara permitirá explorar escenarios mayores y nuevas relaciones entre las coordenadas del mundo, la pantalla y la representación.

Representación y animación

La representación visual continuará evolucionando a partir de las primitivas y capacidades actuales.

Entre las áreas de exploración se encuentran nuevas formas declarativas de representar imágenes, animación y transformaciones, manteniendo la separación entre el objeto, su representación y su comportamiento.

Herramientas

FLX podrá incorporar herramientas que faciliten la creación y edición de sus declaraciones sin convertirlas en un requisito para desarrollar un proyecto.

Los archivos del proyecto seguirán siendo utilizables directamente y las herramientas deberán trabajar sobre ese mismo modelo declarativo.

Deuda técnica conocida

La base de v0.3.0 está consolidada, pero existen áreas internas que podrán revisarse a medida que el engine continúe evolucionando.

  • Añadir validación tipada después de resolver referencias, de forma que los bloques reutilizados puedan comprobarse contra el tipo de recurso FLX esperado antes de parsearlos.
  • Revisar la detección de ciclos para que las distintas formas de composición mediante like ofrezcan una protección equivalente.
  • Continuar simplificando y centralizando internamente la resolución de recursos cuando aparezcan casos que justifiquen esa refactorización.
  • Ampliar diagnostics y las herramientas de inspección del runtime cuando los nuevos juegos hagan necesarias nuevas formas de observar su estado.
