collisions

Mapa opcional de nombres a colliders, o referencia al mapa completo. Sin collisions no se declaran colliders. Cada entrada puede ser un objeto inline o una referencia FLX /archivo:miembro. La geometría de colisión es independiente de visual.

collisions
{
  "group": "player",
  "size": {
    "width": 24,
    "height": 24
  },
  "collisions": {
    "body": {
      "type": "ellipse",
      "with": [
        "enemy",
        "wall"
      ]
    }
  }
}

Collider

Objeto sin campos obligatorios en el schema. Un collider vacío toma los defaults, pero solo será efectivo si sus dimensiones resueltas son positivas.

  • type — string: box | ellipse. Default del runtime: box. Rectángulo orientado o elipse.
  • enabled — boolean. Default del runtime: true. Habilitación inicial.
  • size — objeto. Opcional; cada eje omitido toma Object.size. width y height, si se declaran, son números > 0.
  • offset — objeto. Default: x 0, y 0. Desplazamiento local; cada eje numérico es opcional.
  • angle — number. Default del runtime: 0. Grados sumados al ángulo del objeto.
  • with — array de strings no vacíos y únicos. Default: vacío. Grupos consultados activamente.
  • states — array no vacío de strings no vacíos y únicos. Opcional; sin filtro. Estados efectivos en los que está disponible el collider.

size de collider

Los ejes se resuelven por separado. Si falta un eje propio y no hay tamaño lógico del Object, ese eje vale 0 y el collider no es efectivo. Una representación visible no aporta automáticamente dimensiones al collider.

Collider con tamaño propio
{
  "collisions": {
    "body": {
      "type": "box",
      "size": {
        "width": 16,
        "height": 24
      }
    }
  }
}

offset y angle

El centro es la posición del objeto más el offset rotado por el ángulo del objeto. El ángulo efectivo suma object.angle + collider.angle. El offset de collider no es el offset de creación.

Geometría desplazada
{
  "size": {
    "width": 32,
    "height": 32
  },
  "collisions": {
    "sensor": {
      "offset": {
        "x": 0,
        "y": -20
      },
      "size": {
        "width": 12,
        "height": 8
      },
      "angle": 45,
      "with": [
        "enemy"
      ]
    }
  }
}

with

Cada nombre se compara con group del otro objeto. Un array vacío u omitido no inicia detecciones desde ese collider, aunque el collider puede participar como objetivo de otro que sí lo incluya en with. El filtro es direccional: el collider objetivo no necesita declarar el grupo del origen. La pertenencia a una entidad mediante component no sustituye a estos filtros ni suprime por sí sola los callbacks entre sus objetos.

Collider pasivo
{
  "group": "wall",
  "size": {
    "width": 16,
    "height": 64
  },
  "collisions": {
    "body": {
      "type": "box"
    }
  }
}

states de collider

Filtra por el estado efectivo: máquina propia o, para un component sin ella, la que encuentre en su cadena de parents. Si hay filtro y no existe estado efectivo, el collider no está disponible. El filtro se combina con enabled y dimensiones positivas; no sustituye a Object.states.

Collider limitado por estado
{
  "size": {
    "width": 20,
    "height": 20
  },
  "states": {
    "initial": "idle",
    "idle": {
      "next": [
        "active"
      ]
    },
    "active": {
      "next": [
        "idle"
      ]
    }
  },
  "collisions": {
    "hit": {
      "with": [
        "enemy"
      ],
      "states": [
        "active"
      ]
    }
  }
}

La detección de una colisión no aplica por sí misma una respuesta física: no separa objetos, modifica velocidades ni produce rebotes automáticamente. Los callbacks de colisión y las consultas pertenecen a FLX API.
