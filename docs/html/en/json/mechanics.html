mechanics

Object or block reference with movement and rotation rules. Scripts apply intent through the API; the declaration does not replace behavior. Without this block, defaults are retained: direct, zero speeds and accelerations, zero inertia and unquantized movement.

mechanics
{
  "mechanics": {
    "type": "polar",
    "motion": {
      "speed": {
        "start": 90,
        "limit": 150
      },
      "acceleration": 120,
      "inertia": 0.99
    },
    "rotation": {
      "angle": 45,
      "speed": 180
    }
  }
}

type

String: direct or polar; default direct. Direct uses horizontal/vertical axis rules. Polar uses the object's angle for oriented movement. In the polar vector, 0° points up and 90° points right.

motion

Optional object; all its fields are optional.

  • speed — number or start/limit object. Default: start 0, limit 0. Initial speed and limit. The numeric form sets start and leaves limit at 0.
  • acceleration — number. Default: 0. Time-based acceleration rate. With 0, intent directly applies the live speed; with a positive value, speed evolves progressively.
  • inertia — number from 0 to 1. Default: 0. Velocity persistence when movement intent is no longer applied.
  • step — number ≥ 0. Default: 0. Quantizes the applied displacement. Zero keeps displacement continuous.
  • diagonal — string: independent | vector. Default: independent. independent integrates axes separately; vector normalizes diagonal movement to avoid the magnitude increase from combining axes.
  • horizontal / vertical — override object. Optional. Support speed, acceleration, inertia and step, with the same types.

speed

The object form supports numeric start (default 0) and numeric limit ≥ 0 (default 0). A limit of 0 means unlimited. If a positive limit is below start, the parser warns and raises it to start. Linear speed is integrated over time in position units per second; rotation speed is integrated in degrees per second.

Shorthand speed and explicit limit
{
  "mechanics": {
    "motion": {
      "speed": {
        "start": 100,
        "limit": 160
      }
    },
    "rotation": {
      "speed": 180
    }
  }
}

horizontal / vertical

An undeclared axis field takes the common motion rule. If speed is declared as a partial object, omitted members start from the common rule during parsing; a numeric form resets limit to 0. These overrides describe per-axis rules: they do not declare additional root properties.

Per-axis override
{
  "mechanics": {
    "type": "direct",
    "motion": {
      "speed": {
        "start": 80,
        "limit": 120
      },
      "acceleration": 100,
      "horizontal": {
        "speed": {
          "limit": 90
        }
      }
    }
  }
}

inertia and step

Time-based retention uses inertia^delta for values between 0 and 1; the endpoints yield 0 and 1. Its application depends on the integration branch and whether movement intent is present. step rounds each integrated displacement to multiples of the step: it does not, by itself, define a grid of absolute positions. For rotation, the step is expressed in degrees.

rotation

  • angle — number. Default: 0. Initial live angle in degrees.
  • speed — number or start/limit object. Default: start 0, limit 0. Angular speed and limit; the shorthand form is equivalent to start with limit 0.
  • acceleration — number. Default: 0. Time-based angular acceleration.
  • inertia — number from 0 to 1. Default: 0. Angular integration persistence.
  • step — number ≥ 0. Default: 0. Angular quantization; 0 is continuous.
rotation
{
  "mechanics": {
    "rotation": {
      "angle": 90,
      "speed": {
        "start": 180,
        "limit": 240
      },
      "acceleration": 90,
      "inertia": 0.5,
      "step": 0
    }
  }
}

To receive angle or velocity from the parent, use inherit. To react to World boundaries, use bounds.
