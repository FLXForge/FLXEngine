FLX Documentation

Philosophy

FLX was born from a simple idea: getting results quickly without fighting the engine.

Too often, simple ideas end up buried under configuration, complex tooling or architectures that are difficult to understand.

FLX aims to reduce that friction.

The goal is to build a prototype, a game or an interactive experience using familiar tools, clear structures and a straightforward learning curve.

Built Around Standards

FLX avoids unnecessary proprietary systems.

Projects rely on common and accessible technologies:

  • JSON for structured data
  • JavaScript for scripting
  • Standard asset formats
  • Simple and readable structures

The intention is not to hide how the engine works, but to allow developers to understand and control what is happening.

High-Level and Low-Level Access

FLX provides high-level helpers to solve common behaviors quickly.

At the same time, it allows developers to work at a lower level whenever a project requires more specific behavior.

There are recommended structures and conventions, but no closed paths.

Small, Clear and Direct

FLX is especially designed for:

  • Prototypes
  • Game jams
  • Arcade games
  • Small 2D projects
  • Experimental ideas

FLX is still evolving during the 0.x versions. Some structures and systems may change over time.
