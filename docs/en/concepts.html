FLX Documentation

Core Concepts

FLX organizes projects through data structures, objects, scripts and clearly defined lifecycles.

Project

Every FLX project starts from a main file using the .flx extension.

This file defines the general project structure:

  • Main
  • Scripts
  • Configuration
  • Assets
project.flx
name:Asteroids
version:1.0
flxEngineVersion:0.0.1
main:game.json

Main

The main file acts as the runtime entry point.

From it, objects, scripts and execution logic are organized.

The main structure can represent:

  • A level
  • A menu
  • A loading screen
  • A specific project state
  • A presentation
  • A narrative sequence
  • Anything the developer can imagine...

Object

Objects represent active elements inside the runtime.

An object can:

  • Be rendered
  • Move
  • Collide
  • Execute scripts
  • Store data

Object structures are commonly defined through JSON.

ship.json
{
    "name": "Ship",

    "shape": {
        "type": "triangle"
    },

    "motion": {
        "maxSpeed": 180
    }
}

Scripts

FLX uses JavaScript to define behaviors.

Scripts have access to the runtime context and can react to different lifecycle stages.

player.js
function action(self) {
    if (Key.up()) {
        accelerate(self);
    }
}

Lifecycle

During execution, FLX processes a series of stages during each iteration of the main loop.

  1. Data initialization
  2. Runtime startup
  3. Input processing
  4. Logic execution
  5. Motion processing
  6. Collision handling
  7. Rendering

Scripts can react to these stages through specific functions.

lifecycle.js
function start(self) {}
function action(self) {}
function motion(self) {}
function collision(self, other) {}
function draw(self) {}
function end(self) {}
