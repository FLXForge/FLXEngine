FLX Documentation

Conceptos básicos

FLX organiza los proyectos mediante estructuras de datos, objetos, scripts y ciclos de vida claramente definidos.

Proyecto

Todo proyecto FLX parte de un archivo principal con extensión .flx.

Este archivo define la estructura general del proyecto:

  • Principal (main)
  • Scripts
  • Configuración
  • Recursos
project.flx
name:Asteroids
version:1.0
flxEngineVersion:0.0.1
main:game.json

Principal (Main)

El principal es el punto de entrada del runtime.

Desde él se organizan objetos, scripts y lógica de ejecución.

El principal puede utilizarse para representar:

  • Un nivel
  • Un menú
  • Una pantalla de carga
  • Un estado concreto del proyecto
  • Una presentación
  • Una narración
  • Y lo que el desarrollador imagine...

Objeto

Los objetos representan elementos activos dentro del runtime.

Un objeto puede:

  • Dibujarse
  • Moverse
  • Colisionar
  • Ejecutar scripts
  • Contener datos

La estructura de un objeto se define normalmente mediante JSON.

ship.json
{
    "name": "Ship",

    "shape": {
        "type": "triangle"
    },

    "motion": {
        "maxSpeed": 180
    }
}

Tipos de shape

FLX proporciona distintos tipos básicos de representación visual.

  • block: utiliza origin como esquina superior izquierda.
  • rectangle: utiliza origin como centro.
  • triangle: utiliza origin como centro.
  • line: utiliza origin como centro.

Los objetos pueden utilizar colores declarados directamente desde JSON.

shape.json
"shape": {
    "type": "triangle",
    "color": "WHITE"
}

Scripts

FLX utiliza JavaScript para definir comportamientos.

Los scripts tienen acceso al contexto del runtime y pueden reaccionar a distintos momentos del ciclo de vida.

player.js
function action(self) {
    if (Key.up()) {
        accelerate(self);
    }
}

Movimiento y runtime

FLX combina un sistema clásico basado en speed con un sistema avanzado basado en aceleración e inercia.

Las funciones de movimiento utilizan automáticamente la convención angular FLX.

  • advance(): desplaza el objeto usando su dirección actual.
  • rotate(): modifica angle usando rotationSpeed.
  • bounce_x(): invierte la dirección horizontal.
  • bounce_y(): invierte la dirección vertical.

Los valores velocityX y velocityY representan velocidades runtime internas.

Estos valores son afectados por:

  • acceleration
  • inertia
  • advance()

Los scripts se cargan una única vez y son cacheados mediante rutas normalizadas.

Las instancias creadas mediante spawn reutilizan scripts ya cargados.

Ciclo de vida

Durante la ejecución, FLX procesa una serie de etapas en cada iteración del bucle principal.

  1. Inicialización de datos
  2. Inicio del runtime
  3. Lectura de inputs
  4. Ejecución de lógica
  5. Procesamiento de movimiento
  6. Gestión de colisiones
  7. Dibujado

Los scripts pueden reaccionar a estas etapas mediante funciones específicas.

lifecycle.js
function start(self) {}
function action(self) {}
function motion(self) {}
function collision(self, other) {}
function draw(self) {}
function end(self) {}

Los siguientes apartados profundizan en cada uno de estos sistemas.

Sistema de coordenadas y ángulos

FLX utiliza un sistema de coordenadas 2D con origen en la esquina superior izquierda de la pantalla.

  • x crece hacia la derecha.
  • y crece hacia abajo.
  • Subir implica reducir y.
  • Bajar implica aumentar y.

Los ángulos siguen la convención FLX:

  • 0°: arriba.
  • 90°: derecha.
  • 180°: abajo.
  • 270°: izquierda.
  • Los ángulos positivos giran en sentido horario.
rotation
rotate(ship, RIGHT);
advance(ship);
