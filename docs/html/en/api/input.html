Input

An input query combines Subject + Control + Query. The subject identifies who receives input, the control identifies which logical capability is queried, and the query determines how its state is observed.

Three responsibilities
Machine/Input → logical capabilities
Input Mapping → physical devices
API/Input     → logical query

See Machine · Input for capabilities and mapping. A RuntimeObject acts as a subject through its control.player declaration; control is not a public property of the JavaScript view. Player indices start at 1; button and direction indices start at 0.

Subjects and controls

player()

Signatures
player(playerIndex: number): InputPlayerSubject;

Constructs an explicit player subject. playerIndex starts at 1; the player must exist in Machine/Input for its queries to be valid.

playerIndex: number
Player index starting at 1.

Returns: InputPlayerSubject.

JavaScript example
const subject = player(1);

Related: InputPlayerSubject, system().

system()

Signatures
system(): InputSystemSubject;

Returns the subject for global system controls. Only supports buttons; it has no directions.

Returns: InputSystemSubject.

JavaScript example
if (input_pressed(system(), button(0))) exit();

Related: InputSystemSubject, player().

button()

Signatures
button(index: number): InputButton;

Returns the logical button descriptor index, starting at 0. Does not represent a physical key or query its state. The index must be within the subject's capabilities in Machine.

index: number
Logical index starting at 0.

Returns: InputButton.

JavaScript example
const FIRE = button(0);

Related: InputButton, input_pressed().

direction()

Signatures
direction(index: number): InputDirection;

Returns the logical direction descriptor index, starting at 0. Its valid components depend on the 2way or 4way type declared in Machine.

index: number
Logical index starting at 0.

Returns: InputDirection.

JavaScript example
const MOVE = direction(0);

Related: InputDirection, input_direction().

Queries

input_pressed()

Signatures
input_pressed(subject: InputButtonSubject, control: InputButton): boolean;
input_pressed(subject: InputDirectionSubject, control: InputDirection, component: number): boolean;

Returns true on the frame when the control becomes active. subject is an explicit player or a RuntimeObject with control.player; buttons also support system. For a button, subject + control is enough; for a direction, you must add a compatible component: UP/DOWN/LEFT/RIGHT for 4way or NEGATIVE/POSITIVE for 2way. A subject or control outside the capabilities does not produce an active query.

subject: InputButtonSubject | InputDirectionSubject
Subject compatible with the overload used: RuntimeObject or player for directions; RuntimeObject, player or system for buttons.
control: InputButton | InputDirection
Logical descriptor compatible with the overload used.
component: number
Constant compatible with the direction type.

Returns: boolean.

JavaScript example
if (input_pressed(object, button(0))) {
  console.log("Button 0");
}
if (input_pressed(player(1), direction(0), LEFT)) {
  console.log("Left component, 4way direction");
}

Related: player(), button(), direction().

input_direction()

Signatures
input_direction(subject: InputDirectionSubject, control: InputDirection, axis: number): number;

Returns logical intent -1, 0 or +1 for the axis specified by HORIZONTAL or VERTICAL. In 4way, LEFT/RIGHT correspond to X and UP/DOWN to Y; in 2way, NEGATIVE/POSITIVE project onto either axis. LEFT, UP and NEGATIVE produce -1; RIGHT, DOWN and POSITIVE produce +1. Neutral returns 0. These are result values, not the numeric values of the constants. Does not support system.

subject: InputDirectionSubject
Explicit player or instance with control.player.
control: InputDirection
Logical direction descriptor.
axis: number
HORIZONTAL or VERTICAL.

Returns: number.

JavaScript example
move_horizontal(object, input_direction(object, direction(0), HORIZONTAL));

Related: input_down(), HORIZONTAL, VERTICAL.

Input types

InputButton

Logical button descriptor, with a readonly index starting at 0. Obtain the descriptor through button(). The optional markers in the type file distinguish descriptors; you do not need to construct or modify them manually.

Usage
const control = button(0);

InputDirection

Logical direction descriptor, with a readonly index starting at 0. Obtain the descriptor through direction(). The optional markers in the type file distinguish descriptors; you do not need to construct or modify them manually.

Usage
const control = direction(0);

InputPlayerSubject

Explicit player subject, with a readonly index starting at 1. Obtain the descriptor through player(). The optional markers in the type file distinguish descriptors; you do not need to construct or modify them manually.

Usage
const subject = player(1);

InputSystemSubject

Unique subject for system buttons. Includes a readonly index; its public use is system(), not selecting players through that index. Obtain the descriptor through system(). The optional markers in the type file distinguish descriptors; you do not need to construct or modify them manually.

Usage
const subject = system();

InputButtonSubject

Type
type InputButtonSubject =
  RuntimeObject | InputPlayerSubject | InputSystemSubject;

Subjects supported by button queries. RuntimeObject requires control.player. Related: input_pressed(), player(), system().

InputDirectionSubject

Type
type InputDirectionSubject = RuntimeObject | InputPlayerSubject;

Subjects supported by direction queries. System is excluded. Related: input_direction(), direction().

Constants

Use symbolic names; their internal numeric values are not part of the contract. The -1/+1 signs described here belong to the result of input_direction.

UP

Type
const UP: number;

Up component of a 4way direction. In a vertical axis query it produces intent -1.

Related: input_direction().

DOWN

Type
const DOWN: number;

Down component of a 4way direction. On the vertical axis it produces intent +1.

Related: input_direction().

LEFT

Type
const LEFT: number;

Left component of a 4way direction. On the horizontal axis it produces intent -1.

Related: input_direction().

RIGHT

Type
const RIGHT: number;

Right component of a 4way direction. On the horizontal axis it produces intent +1.

Related: input_direction().

STOP

Type
const STOP: number;

Neutral/stopped movement. Can express neutral intent in a movement operation; does not replace a button or direction descriptor.

Related: input_direction().

NEGATIVE

Type
const NEGATIVE: number;

Negative component of a 2way direction. input_direction projects it as -1.

Related: input_direction().

POSITIVE

Type
const POSITIVE: number;

Positive component of a 2way direction. input_direction projects it as +1.

Related: input_direction().

HORIZONTAL

Type
const HORIZONTAL: number;

Horizontal axis selector for input_direction. In 4way it queries LEFT/RIGHT.

Related: input_direction().

VERTICAL

Type
const VERTICAL: number;

Vertical axis selector for input_direction. In 4way it queries UP/DOWN.

Related: input_direction().
