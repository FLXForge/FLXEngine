FLX Documentation

Core Concepts

FLX organizes projects through simple data structures, objects, transformations and clearly defined execution rules.

This section describes the fundamental concepts that are part of every FLX project.

Project

Every FLX project begins with a main file using the .flx extension.

This file acts as the project's entry point.

Asteroids.flx
name:Asteroids
version:1.0
flxEngineVersion:0.1.0
main:game.json

From this file, the runtime loads the main structure, resources and required configuration.

Main

The main structure is the root of the runtime.

It organizes objects, resources and execution logic.

Depending on the project, it may represent:

  • A level
  • A menu
  • A loading screen
  • A presentation
  • A narrative sequence
  • A specific application state

FLX does not impose a specific interpretation.

Objects

Objects represent elements that exist within the runtime.

An object may:

  • Be rendered
  • Move
  • Collide
  • Store data
  • Execute behavior through scripts

Objects are typically described using JSON.

A definition may be written entirely or built by reusing another definition through like.

ship.json
{
    "name": "Ship",

    "shape": {
        "type": "triangle"
    },

    "motion": {
        "maxSpeed": 180
    }
}

Reuse and Composition

FLX allows new definitions to be built from existing ones.

This capability is based on the like system, which allows configurations to be reused while overriding only the required fields.

DeepSpaceLeft
{
    "name": "DeepSpaceLeft",

    "like": "asteroid/deep_space",

    "origin": {
        "x": 5,
        "y": 5
    }
}

This feature makes it possible to build entire families of objects from a single base definition.

Full details are described in JSON Reference.

Children and Spawns

FLX distinguishes between objects that exist when the runtime starts and objects that may appear later.

  • children: objects that enter the world when the scene is loaded.
  • spawns: reusable definitions used to create new instances during execution.

This separation helps maintain a clear structure between initial content and dynamic content.

Shape Types

FLX provides several basic visual representation types.

Type Origin
block Top-left corner
rectangle Center
triangle Center
line Center
polygon Center
text Text

Colors can be declared directly from JSON.

shape.json
"shape": {
    "type": "triangle",
    "color": "WHITE"
}

Polygons allow irregular shapes to be defined through lists of points.

polygon
"shape": {
    "type": "polygon",

    "points": [
        { "x": 0, "y": -16 },
        { "x": 12, "y": -8 },
        { "x": 16, "y": 8 },
        { "x": -8, "y": 14 }
    ]
}

Shape and Collision

In FLX, visual representation and collision are independent systems.

The shape block defines how an object is rendered, while the collision block defines how it interacts with other objects in the runtime.

In many cases both definitions may be similar, but they are not required to match.

shape + collision
{
    "shape": {
        "type": "polygon"
    },

    "collision": {
        "type": "circle",
        "radius": 12
    }
}

This separation allows collision to remain simple and efficient while visual representation can be as detailed as necessary.

Coordinate System

FLX uses a 2D coordinate system with its origin in the top-left corner of the screen.

  • x grows to the right.
  • y grows downward.
  • Moving up decreases y.
  • Moving down increases y.

Angular System

FLX uses its own angular convention.

  • 0° points upward.
  • 90° points right.
  • 180° points downward.
  • 270° points left.
  • Positive angles rotate clockwise.
rotation
rotate(ship, RIGHT);
advance(ship);

Movement

FLX combines a classic speed-based system with an acceleration and inertia-based system.

Common movement-related properties include:

  • speed
  • velocityX
  • velocityY
  • acceleration
  • inertia
  • rotationSpeed

Movement functions automatically follow the FLX angular convention.
