FLX Documentation

Core Concepts

FLX organizes projects through data structures, objects, scripts and clearly defined lifecycles.

Project

Every FLX project starts from a main file with the .flx extension.

This file defines the general project structure:

  • Main
  • Scripts
  • Configuration
  • Resources
project.flx
name:Asteroids
version:1.0
flxEngineVersion:0.0.1
main:game.json

Main

The main structure is the runtime entry point.

Objects, scripts and runtime logic are organized from it.

The main structure can represent:

  • A level
  • A menu
  • A loading screen
  • A specific project state
  • A presentation
  • A narrative
  • Anything the developer can imagine...

Object

Objects represent active elements inside the runtime.

An object can:

  • Be rendered
  • Move
  • Collide
  • Execute scripts
  • Contain data

Object structure is usually defined through JSON.

ship.json
{
    "name": "Ship",

    "shape": {
        "type": "triangle"
    },

    "motion": {
        "maxSpeed": 180
    }
}

Shape Types

FLX provides several basic visual representation types.

  • block: uses origin as top-left corner.
  • rectangle: uses origin as center.
  • triangle: uses origin as center.
  • line: uses origin as center.

Objects can use colors declared directly from JSON.

shape.json
"shape": {
    "type": "triangle",
    "color": "WHITE"
}

Scripts

FLX uses JavaScript to define behaviors.

Scripts have access to the runtime context and can react to different lifecycle stages.

player.js
function action(self) {
    if (Key.down(KEY_UP)) {
        accelerate(self);
    }
}

Movement and Runtime

FLX combines a classic speed-based system with an advanced acceleration and inertia-based system.

Movement functions automatically use the FLX angular convention.

  • advance(): moves the object using its current direction.
  • rotate(): modifies angle using rotationSpeed.
  • bounce_x(): reverses horizontal direction.
  • bounce_y(): reverses vertical direction.

velocityX and velocityY represent internal runtime motion values.

These values are affected by:

  • acceleration
  • inertia
  • advance()

Scripts are loaded only once and cached using normalized paths.

Spawned instances reuse already loaded scripts.

Lifecycle

During execution, FLX processes a series of stages on every main loop iteration.

  1. Data initialization
  2. Runtime start
  3. Input reading
  4. Logic execution
  5. Movement processing
  6. Collision management
  7. Rendering

Scripts can react to these stages through specific functions.

lifecycle.js
function start(self) {}
function action(self) {}
function motion(self) {}
function collision(self, other) {}
function draw(self) {}
function end(self) {}

The following sections explore each of these systems in more depth.

Coordinate and Angle System

FLX uses a 2D coordinate system with the origin located at the top-left corner of the screen.

  • x grows to the right.
  • y grows downward.
  • Moving up decreases y.
  • Moving down increases y.

Angles follow the FLX convention:

  • 0°: up.
  • 90°: right.
  • 180°: down.
  • 270°: left.
  • Positive angles rotate clockwise.
rotation
rotate(ship, RIGHT);
advance(ship);
