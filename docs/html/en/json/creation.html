Creation · JSON Reference

Index | Project | Object | Composition | Visual | Creation | Mechanics | Collision | Audio

Creation brings together declarations that determine which children a parent can create, when they are created, and how they relate to it spatially or receive movement and orientation. Creation rules are declared in the parent; spawn, component, offset, attach and inherit describe the child.

children

Map of child names to inline objects or reference strings. Without this block, no children are declared. Each inline value uses Object; a string is equivalent to an Object with like. A name identifies the reusable declaration, not a single runtime instance.

children
{
  "children": {
    "ship": "objects/ship",
    "marker": {
      "origin": {
        "x": 80,
        "y": 40
      }
    },
    "laser": {
      "like": "objects/laser",
      "spawn": "manual"
    }
  }
}

spawn

String: auto or manual; default auto. In individual mode, an auto child enters with its parent, while a manual child waits for a call to spawn(parent, "child"). The call can also create additional instances of an auto child. Grid and iterator apply their specific rules. This is not a timer or a condition for appearing.

Manual child
{
  "children": {
    "bullet": {
      "spawn": "manual",
      "offset": {
        "x": 0,
        "y": -12
      }
    }
  }
}

component

Boolean; default false. Marks a child as part of its parent's logical entity. Ray queries exclude the querying object's logical entity; killing the parent removes descendants joined by a chain of components. A component without its own state machine looks for effective state in that chain. The root Object cannot declare component: true.

Component does not automatically enable spatial following: that requires declaring attach.

Component attached to its parent
{
  "children": {
    "turret": {
      "component": true,
      "offset": {
        "x": 0,
        "y": -10
      },
      "attach": {
        "born": true,
        "position": true
      }
    }
  }
}

creation

Object or block reference of the parent. mode selects individual, grid or iterator. If the block or the individual form's mode is omitted, individual is used. Each mode has a different structure; their fields are not combined.

individual

Only supports mode, which is optional. Materializes an initial instance of each auto child. Position follows the rules for offset/origin.

Individual creation
{
  "children": {
    "marker": {}
  },
  "creation": {
    "mode": "individual"
  }
}

grid

  • mode — string: grid. Required. Selects a grid.
  • rules.rows / rules.columns — integer ≥ 1. Both required. Number of rows and columns.
  • rules.cellWidth / rules.cellHeight — number > 0. Both required. Spacing between cell origins.
  • pattern — array of strings or array of rows of strings. Required. Names of children occupying cells. Use a nonempty pattern; the runtime rejects a grid without an effective pattern.
grid — linear pattern
{
  "children": {
    "a": {
      "size": {
        "width": 30,
        "height": 14
      }
    },
    "b": {
      "spawn": "manual"
    }
  },
  "creation": {
    "mode": "grid",
    "rules": {
      "rows": 2,
      "columns": 3,
      "cellWidth": 32,
      "cellHeight": 16
    },
    "pattern": [
      "a",
      "b"
    ]
  }
}

A linear pattern is traversed by row and repeated. In a row-based pattern, the outer rows repeat, and each row repeats its columns. An empty row produces no child in its cells. Names used must correspond to declared children.

grid — row-based pattern
{
  "children": {
    "a": {},
    "b": {}
  },
  "creation": {
    "mode": "grid",
    "rules": {
      "rows": 2,
      "columns": 3,
      "cellWidth": 32,
      "cellHeight": 16
    },
    "pattern": [
      [
        "a"
      ],
      [
        "b"
      ]
    ]
  }
}

The position is parent.position + (column × cellWidth, row × cellHeight) + child.offset. Ignores child.origin; the offset is not rotated with the parent's angle in this mode. Manual children do not appear automatically. spawn(parent, "child") creates all cells assigned to that name, not a free instance.

iterator

  • mode — string: iterator. Required. Selects sequential creation.
  • pattern — nonempty array of strings. Required. Names of existing children with spawn: "auto". Does not support a row-based pattern.
  • rules.concurrent — integer ≥ 1. Default: 1. Maximum number of instances created by this iterator that can coexist.
  • rules.repeat — boolean. Default: false. Restarts pattern traversal when the end is reached.
iterator
{
  "children": {
    "enemy": {}
  },
  "creation": {
    "mode": "iterator",
    "rules": {
      "concurrent": 1,
      "repeat": false
    },
    "pattern": [
      "enemy",
      "enemy"
    ]
  }
}

The iterator produces entries as slots become available. rules is optional. Does not support manual spawn(parent, "child") on the iterator parent. Its creation uses individual positioning. creation_active(object) lets you query whether it is still active; individual and grid return false.

offset

Optional object with numeric x and y; each axis is 0 when omitted. In individual/iterator, if the block exists, the child is born at the parent's position plus the offset rotated by the parent's current angle, ignoring origin. Without offset, a declared origin is preserved; if origin is also absent, it is born at the parent's position.

offset
{
  "offset": {
    "x": 0,
    "y": -14
  }
}

Declaring offset: {} is significant: it applies a zero offset and takes priority over origin. In grid, the governing formula is that of the cell.

attach

Optional inline object with boolean flags. Always uses the original parent; it does not reassign parents or declare dynamic hierarchies.

  • born — boolean. Default: false. Born attached if true.
  • position — boolean. Default: false. Enables X and Y following.
  • x / y — boolean. Default to position. Each explicit axis overrides position for that axis.
  • angle — boolean. Default: false. Synchronizes the angle without rotating the following offset.
attach
{
  "attach": {
    "born": true,
    "position": true,
    "y": false,
    "angle": true
  }
}

Initial attach preserves the separation established when the child is created. A later attach uses the separation at that moment as the reference for followed axes; detach suspends following without modifying the original parent relationship. See inherit.live.angle for declarative angle synchronization.

inherit

Object or block reference. Receives live state from the original parent, not its declarative Mechanics rules. When omitted, the three modes are none.

  • creation.angle — string: none | copy. Default: none. Copies the angle when the child is created.
  • creation.velocity — string: none | copy | compose. Default: none. copy copies live linear velocity; compose adds the parent's velocity to the child's own velocity at creation, without changing its declared polar speed.
  • live.angle — string: none | copy. Default: none. Continuously synchronizes the angle with the original parent.
inherit
{
  "inherit": {
    "creation": {
      "angle": "copy",
      "velocity": "compose"
    },
    "live": {
      "angle": "none"
    }
  }
}

Static declaration reuse belongs to like; velocity and rotation rules belong to Mechanics.
