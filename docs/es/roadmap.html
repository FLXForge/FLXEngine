FLX Documentation

Roadmap

FLX se desarrolla de forma incremental y práctica.

Cada ejemplo añade nuevas capacidades al runtime, ayuda a validar arquitectura real y permite detectar mejoras necesarias antes de avanzar.

Esta sección funciona como diario de desarrollo y hoja de dirección general del proyecto.

Desarrollado

Ejemplo Pong

Primer ejemplo funcional utilizado para construir y validar la estructura base del engine.

Sistemas implementados

  • Estructura base del engine
  • Ciclo de vida inicial
  • API de movimiento
  • Colisiones básicas
  • Rebote horizontal y vertical
  • Enemigo IA base
  • Sistema de reaparición (to_origin())
  • Consola de logs
  • Soporte JSON y JavaScript
  • JSON Schemas
  • Definiciones TypeScript (.d.ts)

En desarrollo

Ejemplo Asteroids

Segundo ejemplo del runtime.

Actualmente utilizado para validar:

  • Sistema de formas (shape).
  • Sistema motion basado en JSON.
  • Rotación y convención angular FLX unificada también en Pong.
  • Nuevas funciones de API y evolución del runtime scripting.
  • Sistema de wrap screen y comportamiento bounds.
  • Documentación HTML viva y sincronizada con el desarrollo real.
  • Soporte de color real desde JSON.
  • Nuevo tipo shape.type = line.
  • Sistema de input escalable: Key.down(KEY_*) y Key.pressed(KEY_*).
  • Constantes KEY_* expuestas a JavaScript.
  • Sistema probabilístico: probability(chance, base).
  • Spawns declarativos definidos directamente en JSON.
  • Prefabs cargados y cacheados sin instanciación inmediata.
  • Instanciación runtime mediante spawn(self, "laser").
  • Creación dinámica de objetos desde prefabs.
  • Offsets locales rotados según el ángulo del objeto.
  • Carga y caché de scripts de prefab mediante ScriptEngine.
  • Sistema de disparo funcional desde la nave.

Actualmente en desarrollo

  • Spawn de objetos (asteroides)
  • UI y texto
  • Lifecycle más sólido
  • Contexto game / level
  • Señales y comunicación entre objetos

Fase posterior

Tras completar los tres ejemplos principales, FLX entrará en una fase de normalización y mejora general.

El objetivo será:

  • Unificar arquitectura y nomenclatura
  • Refinar APIs
  • Reducir duplicidades
  • Mejorar consistencia de runtime
  • Hacer los ejemplos más completos y atractivos

Deuda técnica y mejoras pendientes

  • Normalizar Pong al nuevo schema shape/motion.
  • Revisar si program sigue siendo el nombre definitivo.
  • Centralizar funciones del wrapper JavaScript para evitar modificar múltiples puntos por cada nuevo lifecycle.
  • Refactorizar el wrapper JS mediante un sistema de registro centralizado de funciones.
  • Normalizar rutas JSON igual que scripts.
  • Mejorar warnings: no avisar cuando un lifecycle opcional no exista.
  • Los lifecycle opcionales ausentes deberían permanecer silenciosos.
  • Definir lifecycle más sólido: gameStart, start, action, motion, collision, draw, end/dead.
  • Definir destrucción runtime: kill(), lifecycle dead/end.
  • Definir correctamente lifetime, temporizadores y gestión de delta.
  • Definir sistema completo de spawn / prefabs / templates.
  • Implementar spawn queue segura: evitar push_back directo durante iteración de objetos.
  • Implementar correctamente motion.inherit = live.
  • Definir contexto game/level y persistencia entre niveles.
  • Explorar una capa de input semántico (Control.*) por encima de Key.
  • Separar y documentar correctamente block, rectangle y triangle.
  • Mejorar colisiones overflow-aware.
  • Futuro: colisiones wrap-aware utilizando radios y offsets.
