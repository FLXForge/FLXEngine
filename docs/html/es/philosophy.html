Documentación FLX

Filosofía

FLX nace de una idea sencilla: obtener resultados sin luchar contra las herramientas.

Con demasiada frecuencia, las ideas simples terminan enterradas bajo configuraciones complejas, arquitecturas difíciles de comprender o flujos de trabajo que exigen aprender la herramienta antes de poder desarrollar el proyecto.

FLX intenta reducir esa fricción.

Por qué existe FLX

FLX está pensado para quienes quieren construir algo rápidamente, comprender cómo funciona y conservar el control sobre lo que están creando.

Ya sea un prototipo, una game jam, un juego completo o una herramienta interactiva, la intención es la misma:

Construir sin luchar contra el motor.

Simplicidad mediante comprensión

FLX no intenta ocultar cómo funciona internamente.

Tampoco intenta reemplazar C++, ni abstraer todos los detalles del runtime.

La idea es diferente:

utilizar estructuras sencillas y predecibles para que el comportamiento pueda comprenderse, modificarse y ampliarse con facilidad.

La simplicidad no proviene de esconder complejidad.

Proviene de organizarla de forma clara.

Datos, funciones y runtime

FLX está construido alrededor de tres conceptos fundamentales:

Mental model
Objetos -> Datos

Scripts -> Funciones

Runtime -> Conecta ambos

Los objetos describen qué existe.

Los scripts describen qué ocurre.

El runtime coordina la interacción entre ambos.

Este modelo permite construir comportamiento complejo utilizando estructuras relativamente simples.

Basado en estándares

FLX evita sistemas propietarios innecesarios.

Los proyectos utilizan tecnologías ampliamente conocidas:

  • JSON para datos estructurados
  • JavaScript para scripting
  • Formatos estándar para recursos
  • Archivos de texto legibles y editables

El objetivo es que los desarrolladores puedan utilizar las herramientas con las que ya están familiarizados.

Alto y bajo nivel

FLX proporciona funciones de alto nivel para resolver rápidamente comportamientos comunes.

Pero también permite trabajar directamente sobre los datos cuando se necesita un comportamiento más específico.

Existen convenciones recomendadas, pero no caminos cerrados.

Pequeño, claro y directo

FLX está especialmente orientado a:

  • Prototipos
  • Game jams
  • Juegos arcade
  • Proyectos 2D pequeños y medianos
  • Ideas experimentales

No intenta ser la solución para todos los problemas.

Intenta ser una herramienta clara para resolver bien algunos de ellos.

Lo que FLX no pretende ser

FLX no intenta competir con motores generalistas de gran escala.

No intenta ocultar el funcionamiento del runtime detrás de capas de abstracción cada vez más complejas.

Y no intenta sustituir el conocimiento técnico por automatización.

FLX busca que el desarrollador entienda qué ocurre, por qué ocurre y cómo modificarlo.
