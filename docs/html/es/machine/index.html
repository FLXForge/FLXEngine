Una Machine define las capacidades y restricciones del entorno en el que se ejecuta un proyecto FLX. Describe las posibilidades de ejecución del proyecto; las entidades y el comportamiento se declaran en otras capas.

Separación de responsabilidades
Los objetos declaran qué existe.
Los scripts declaran qué hace.
La Machine declara qué puede hacer el mundo.

Tres chips

Machine
Machine
├── Video
├── Audio
└── Input
  • Video — pantalla lógica, capacidades de color y presentación física.
  • Audio — voces disponibles, síntesis y fidelidad del audio.
  • Input — jugadores, botones lógicos y controles direccionales.

Machine no describe el juego: no contiene objetos, canciones, acciones como «disparar» ni comportamientos. Establece las capacidades con las que trabajan esas declaraciones.

Selección desde el proyecto

Entrada del manifiesto .flx
machine=machines/asteroidsMachine.yml

La ruta se resuelve respecto al directorio del manifiesto .flx, no respecto a su path de contenido JSON. Si el proyecto no selecciona una Machine propia, utiliza la Default Machine interna. Véase Project.

Estructura canónica

Machine parcial con los tres chips
machine:
  video:
    screen:
      width: 320
      height: 240
  audio:
    voices:
      music: 3
      sound: 1
  input:
    players:
      count: 1

La forma canónica utiliza la raíz machine:. El loader también admite los bloques video, audio e input directamente en la raíz del archivo como formato alternativo. Las propiedades públicas de esta referencia son las capacidades de esos tres chips.

Chips inline y externos

Cada chip puede ser un mapa YAML inline o un string con la ruta de un archivo externo. Las rutas de chips se resuelven respecto al archivo Machine que las declara; escriba la extensión del recurso.

Machine con Video inline
machine:
  video:
    screen:
      width: 320
      height: 240
Machine con Video externo
machine:
  video: chips/video/retro.yml
chips/video/retro.yml — relativo al archivo Machine
video:
  screen:
    width: 320
    height: 240

El archivo externo debe contener un mapa con la raíz del chip correspondiente: video:, audio: o input:. Puede mezclar chips inline y externos en una misma Machine.

Machine parcial y defaults

La carga parte de una definición interna por defecto y superpone los campos declarados. Omitir un chip conserva sus capacidades por defecto: no declarar audio no desactiva el audio. Cuando se declara players.controls.directions, la lista indicada sustituye la dirección por defecto. Las reglas específicas de otros bloques, como color.palette, se detallan en la referencia de cada chip.

Defaults principales
ChipDefinición inicial
Video640 × 480; clear color black; output.scale: 1; output.smoothing: false.
Audio8 voces de música y 16 de sonido; modo shared; overflow replace_oldest; modelo open.
Input2 botones de sistema; 1 jugador; 4 botones por jugador; una dirección 4way, con simultaneous: last y buffer: 0.

Los defaults completos y los rangos se detallan en cada chip. Un valor cero tiene significado propio donde se admite; no equivale a omitir el campo.

Formato admitido y capacidad efectiva

Que una propiedad se acepte y almacene no implica que tenga ya un comportamiento aplicado o diferenciado. Esta referencia distingue capacidades efectivas, valores que comparten implementación y propiedades todavía sin efecto funcional. Los detalles de cada caso están en Video, Audio e Input.

Los ejemplos muestran valores válidos y usan true/false para booleanos. El loader aplica avisos y fallback a defaults en varios campos inválidos; las capacidades Input no soportadas generan diagnóstico de error. No debe deducirse soporte de una propiedad sólo porque un archivo pueda cargarse.
