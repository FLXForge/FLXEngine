FLX Documentation

Examples

FLX examples are complete games built with the same tools available to any project.

Each explores a different combination of objects, mechanics and behaviors, from Pong's fundamental rules to Tank's perception and decision-making.

You can use them as a reference, take them apart to understand how they work, or simply run them to see what you can build with FLX.

Pong

Two paddles. One ball. Where it all began.

Pong is the simplest starting point for a complete FLX project.

With just a few objects, it combines player controls, direct and polar movement, collisions, bounces, sound and a basic AI that follows the ball's position.

What you can learn

  • Basic FLX project structure
  • Player input and direct movement
  • Polar movement through advance()
  • Collisions and resolution through CollisionContact
  • Bounces with reflect_x() and reflect_y()
  • Sound generated by the object itself
  • Basic AI through object lookup and following

Asteroids

Inertia, composition and survival in the void.

Asteroids shows how to combine polar movement, acceleration, inertia and rotation to build objects whose movement retains its own dynamics.

The ship, asteroids, shots, trail and fragments use the lifecycle and object creation to build more complex behaviors from simple elements. The example also combines local and global state, timers and immediate drawing.

What you can learn

  • Polar movement, acceleration and inertia
  • Rotation and angular velocity
  • Object creation and lifecycle
  • Local and global state
  • Timers and effects of limited duration
  • Composition and reusable definitions
  • Immediate drawing combined with world objects
  • Visual effects built from simple objects

Arkanoid

Bounces, power-ups and emergent rules.

Arkanoid shows how to build more complex game rules by combining objects, states, timers and creation.

Bricks are generated in a grid, the ball can remain attached to the paddle, and power-ups temporarily modify its behavior and properties during play.

What you can learn

  • Object creation through grids
  • Composition and reuse through like
  • Object states and lifecycle
  • Attaching and detaching through attach() and detach()
  • Timers and effects of limited duration
  • Power-ups and dynamic property modification
  • Probabilistic object creation
  • Collisions filtered by groups

Invaders

Many enemies. One formation.

Invaders shows how many independent objects can be part of a larger structure and share its movement.

The fleet creates invaders in a grid and moves the formation as a whole, while each invader retains its own behavior and can create its own shots. The example also combines global state, timers and immediate drawing to build the game's rules and interface.

What you can learn

  • Formation creation through grids
  • Composing objects into larger structures
  • Coordinated movement of groups of objects
  • Manual projectile creation through spawn()
  • Timers to limit actions
  • Global state shared between objects
  • Immediate drawing for interface elements
  • Probabilistic behaviors

Tank

See, remember and decide.

Tank shows how to build autonomous behaviors from the information an object can obtain about its surroundings.

The enemy tank uses rays to detect the player and obstacles, remembers the last observed position, and combines local state and timers to search, pursue, fire or avoid a wall.

What you can learn

  • Polar movement and rotation
  • Perceiving the environment through ray()
  • Local state as object memory
  • Timers to maintain decisions over time
  • Autonomous behaviors based on perception
  • Obstacle detection and avoidance
  • Projectile creation and behavior
  • Recreating objects through iterators
