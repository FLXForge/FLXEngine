How FLX Thinks

Before learning JSON, APIs or lifecycles, it is worth understanding the central idea behind FLX.

FLX does not try to simplify C++.

It tries to make runtime behavior scriptable.

Mental model
Objects -> Data

Scripts -> Functions

Runtime -> Connects both

Objects Contain Data

An object describes something that exists inside the runtime.

It may contain position, size, velocity, visual appearance or any other property.

Objects do not contain behavior.

They contain state.

Scripts Contain Functions

A script is a collection of JavaScript functions.

Those functions describe what happens to objects throughout their lifetime.

Scripts do not belong to objects.

They are shared resources that may be used by many objects simultaneously.

ship.js
function action(ship) {
    accelerate(ship);
}

The Runtime Connects Both

During execution, the runtime invokes functions and provides the objects they should operate on.

Scripts describe behavior.

Objects store state.

The runtime coordinates the interaction between both.

Shared State and Individual State

The same script may be used by hundreds of objects.

This means different scopes of information exist.

  • Function scope
  • Script scope
  • Object scope
  • Global scope (future)

Understanding this distinction is one of the keys to understanding FLX.

Living Objects

FLX treats objects as entities that are born, exist and eventually disappear.

Lifecycle
born()

action()
motion()
collision()

kill()

dead()

cleanup()

This terminology is intentional.

The lifecycle is part of the runtime mental model.
