FLX Documentation

Introduction

A small declarative 2D engine

Define structures with JSON and behavior with JavaScript, and let the runtime do the rest.

The FLX philosophy: data, functions and runtime

FLX is built around a very simple idea:

Mental model
Objects -> Data

Scripts -> Functions

Runtime -> Connects both

Objects define what exists.

Scripts define what happens.

The runtime connects both during execution.

ship.json
{
  "$schema": "https://flxforge.github.io/FLXEngine/schemas/object.schema.json",

  "size": {
    "width": 18,
    "height": 24
  },

  "visual": {
    "color": "white",
    "representation": [
      {
        "primitive": "triangle",
        "mode": "outline"
      }
    ]
  },

  "mechanics": {
    "type": "polar",
    "motion": {
      "speed": { "limit": 180 },
      "acceleration": 120,
      "inertia": 0.99
    },
    "rotation": {
      "speed": { "start": 180 }
    }
  }
}

Data defines existence.

ship.js
/// <reference path="https://flxforge.github.io/FLXEngine/scripts/flx.d.ts" />

const MOVE = direction(0);

function action(ship) {
  const thrust = input_direction(ship, MOVE, VERTICAL);

  if (thrust > 0) {
    accelerate(ship, thrust);
  }
}

function motion(ship) {
  advance(ship);
}

Functions define behavior.

FLX does not try to move the engine into the script.

The runtime maintains the rules of the world; scripts express object behavior.

Each project also runs on a machine, which defines the characteristics of the environment in which that world exists.
