FLX Documentation

JSON Reference

This section documents the project manifest and JSON structures used by FLX to define runtime objects and their properties.

FLX is under active development. Some fields may change during 0.x versions.

Project Files

FLX separates project metadata from world data.

  • .flx: defines project metadata and compilation entry points.
  • object: defines an object that may contain other elements.
  • object: defines objects that can be rendered visually.

FLX Manifest

The .flx file is a properties-style manifest. It points to the root object, Machine and input mapping. Runtime options such as debug flags or fullscreen mode belong to the CLI or host environment, not to the project manifest.

game.flx
name=Asteroids
version=1.0.0
engine=0.2.0
path=asteroids
root=space
title=Asteroids
machine=machines/standard.yml
input.mapping=input/default.input
notes=FLX example with spawn and basic UI

Fields

  • name: project name. [ Optional ]
  • version: project version. [ Optional ]
  • engine: target FLX version. [ Optional ]
  • path: project content directory. [ Optional ]
  • root: root JSON object compiled as the world entry point. [ Required ]
  • title: window title. [ Optional ]
  • machine: YAML Machine definition used by the project. If omitted, FLX uses an internal default Machine. [ Optional ]
  • input.mapping: properties-style input mapping used by the logical input API. If omitted, mapped controls are not generated. [ Optional ]
  • notes: free project notes. [ Optional ]

The manifest parser rejects removed runtime fields such as screen.width, screen.height, screen.scale, window.mode and debug.*. Screen size and output scale come from the video chip. Runtime debug/window options are provided by the execution layer, for example flx run --window-mode=fullscreen --scale=3 project.flx.

A Machine describes available capabilities through chips such as video, audio and input. Screen size, background color and output scale now come from the video chip, not from the .flx manifest.

input/default.input
system.buttons.0=KEY_ESCAPE,KEY_LEFT_ALT+KEY_Q
system.buttons.1=KEY_ENTER,JOY1_START

players.1.directions.0.up=KEY_W,JOY1_UP
players.1.directions.0.down=KEY_S,JOY1_DOWN
players.1.directions.0.left=KEY_A,JOY1_LEFT
players.1.directions.0.right=KEY_D,JOY1_RIGHT
players.1.buttons.0=KEY_SPACE,JOY1_A

In .input files, commas separate alternatives and + joins simultaneous inputs. The mapping is validated against the Input Chip. Unknown tokens, players or buttons outside the chip limits are ignored with warnings.

FLX JSON References

JSON resources can use project-root references by starting a string with /. The leading slash is the FLX project content root declared by path in the manifest, not the operating system root.

whole JSON
"shape": "/ui/title_shape"
top-level key inside JSON
"note": "/music/notes:a"

/music/notes loads path/music/notes.json. /music/notes:a loads the same file and returns its top-level a entry. The .json extension is optional. Normal strings such as red, C4, square or player are not references. Invalid files, invalid JSON, missing keys and attempts to escape the project root are reported as errors.

machines/standard.yml
machine:
  name: standard
  video:
    screen:
      width: 640
      height: 480

The video chip currently supports: screen.width, screen.height, screen.color, color.palette, color.levels.red, color.levels.green, color.levels.blue, color.tone.base, color.tone.levels, color.alpha, planes.enabled, objects.sprites, output.scale and output.smoothing. Color models are applied when object definitions are loaded; they are not full-screen filters. Alpha, planes and sprite restrictions are declared but not enforced yet.

input chip
input:
  system:
    buttons: 2
  players:
    count: 1
    controls:
      directions:
        - type: 4way
          simultaneous: last
          buffer: 0
      buttons: 1

The input chip declares input capabilities only. It does not name semantic actions such as start, pause or fire. Player buttons, player directions and system buttons are separate budgets. If no Input Chip is declared, FLX uses a permissive internal chip. This iteration supports digital 2way and 4way directions.

In color.levels, each RGB channel accepts values from 0 upward. A value of 0 disables that channel. In color.tone.base, hexadecimal colors may be written quoted or unquoted, for example base: "#9BBC0F" and base: #9BBC0F.

The audio chip defines the sound capabilities of the Machine. It does not declare concrete sounds, songs, instruments or assets. voices.music limits generated music channels and voices.sound limits generated sound effects. In reserved mode those budgets are separate. In shared mode they form a single pool with voices.music + voices.sound voices.

audio chip
audio:
  voices:
    music: 3
    sound: 1
    mode: reserved
    overflow: replace_oldest

  synthesis:
    model: pulse
    texture: clean
    movement: simple
    noise: simple

  fidelity:
    resolution: low
    dynamics: limited
    space: mono

  resources:
    generated: true
    samples: false
    streams: false

  fileAudio:
    mode: off

voices.mode accepts shared, preferred and reserved. voices.overflow accepts ignore, replace_oldest, replace_newest, replace_lowest_priority and steal_from_music. Current generated sound effects all use the same priority. In shared mode, steal_from_music can pause a playing music voice so a sound effect can play, then resume the music when sound voices are free again.

synthesis, fidelity, resources and fileAudio are validated and stored in the Machine definition. Generated audio uses synthesis.model, synthesis.texture, synthesis.movement, synthesis.noise, fidelity.resolution and fidelity.dynamics to shape oscillator output. File audio fields are still validation-only and do not enable WAV, OGG or MP3 playback yet.

Root Object

The root object is special only because the manifest points to it. Its JSON uses the same schema as any other FLX object.

space.json
{
    "$schema": "https://flxforge.github.io/FLXEngine/schemas/object.schema.json",    "behavior": {
        "scripts": [ "scripts/game" ]
    },

    "children": {
        "level": "space/level"
    }
}

Children

The children field declares objects contained by another object.

children (reference)
"children": {
    "ball": "objects/ball"
}
children (inline)
"children": {
    "ship": {
        "like": "ship/ship",
        "origin": { "x": 160, "y": 90 }
    }
}
children (manual)
"children": {
    "laser": {
        "like": "ship/laser",
        "spawn": "manual",
        "offset": { "x": 0, "y": -14 }
    }
}

Each key in children is the logical instance name. A string value is syntactic sugar for an object with like.

Children use spawn: "auto" by default. That first instance enters the runtime with its parent. Children with spawn: "manual" wait until a script calls spawn(parent, "child"). The same function can also create another instance of an auto child later.

children defines what may exist, spawn defines when each child enters the runtime, and creation defines how the parent materializes those children.

Creation

The optional creation block controls how a parent creates its declared children. If it is omitted, FLX uses creation.mode = "individual".

individual creation
"creation": {
    "mode": "individual"
}
grid creation with linear pattern
"children": {
    "a": { "like": "brick_red" },
    "b": { "like": "brick_blue", "spawn": "manual" }
},
"creation": {
    "mode": "grid",
    "rules": {
        "rows": 2,
        "columns": 3,
        "cellWidth": 32,
        "cellHeight": 16
    },
    "pattern": ["a", "b"]
}
grid creation with row pattern
"creation": {
    "mode": "grid",
    "rules": {
        "rows": 2,
        "columns": 3,
        "cellWidth": 32,
        "cellHeight": 16
    },
    "pattern": [
        ["a"],
        ["b"]
    ]
}

In grid mode, the parent position is the grid origin. Each cell uses column * cellWidth and row * cellHeight. The child offset is applied inside the cell and the child origin is ignored.

A linear pattern is consumed in row-major order and repeats when it ends. A row pattern repeats its outer rows and each inner row repeats its columns. Manual children inside a grid do not appear automatically; calling spawn(parent, "child") creates every grid cell where the pattern references that child.

Sounds

The sounds field declares sounds owned by an object. Scripts can play them with play_sound(object, "id").

sounds
"sounds": {
    "beep": {
        "kind": {
            "source": {
                "type": "oscillator",
                "wave": "square"
            },
            "note": 880
        },
        "tone": {
            "material": {
                "brightness": 0.8,
                "roughness": 0.1,
                "noise": 0.0,
                "resonance": 0.0,
                "metal": 0.0
            },
            "envelope": {
                "attack": 0.0,
                "decay": 0.05,
                "sustain": 0.0,
                "release": 0.0
            },
            "space": {
                "mode": "mono",
                "width": 0.0,
                "echo": 0.0
            }
        },
        "duration": 0.08,
        "volume": 0.7
    }
}
sounds (reference)
"sounds": {
    "beep": "audio/beep"
}

kind defines the sound event. kind.source may use oscillator or noise in this implementation. kind.note accepts a musical note string such as C4, a frequency number such as 1200, an object such as { "frequency": 1200 }, or an explicit FLX reference such as /music/notes:a. If missing, FLX uses A4.

kind.slide is the total frequency change over the sound duration. kind.movement.type = "fall" or "rise" can map movement amount to slide when slide is not specified. "wobble" applies vibrato and "pulse" applies tremolo.

tone defines the character of the sound through material, envelope and space. Envelope is applied per generated sample. Material brightness, roughness, noise, resonance and metal add audible character. space.echo adds a small delay; stereo width is prepared in the data model but still rendered as mono by the current generator.

Supported waves are square, sine, triangle, saw , pulse and noise. source.duty controls pulse duty cycle from 0.05 to 0.95. square always uses duty 0.5.

Sound declarations are data. They can be inline, referenced as a JSON file, or composed with like.

Music

The music field declares generated songs owned by an object. Scripts can play them with play_music(object, "id"). Music uses the voices.music capacity from the Audio Chip and does not consume voices.sound.

music
"music": {
    "theme": {
        "tempo": 120,
        "loop": true,
        "channels": {
            "lead": {
                "instrument": {
                    "source": {
                        "type": "oscillator",
                        "wave": "square"
                    },
                    "tone": {
                        "material": {
                            "brightness": 0.8,
                            "roughness": 0.1,
                            "noise": 0.0,
                            "resonance": 0.2,
                            "metal": 0.0
                        },
                        "envelope": {
                            "attack": 0.0,
                            "decay": 0.05,
                            "sustain": 0.5,
                            "release": 0.03
                        },
                        "space": {
                            "mode": "mono",
                            "width": 0.0,
                            "echo": 0.0
                        }
                    },
                    "play": {
                        "legato": false,
                        "glide": 0.0,
                        "vibrato": 0.0
                    },
                    "range": {
                        "min": "C0",
                        "max": "B8"
                    }
                },
                "volume": 0.35,
                "length": "1/8",
                "notes": ["C4", "E4", "G4", "C5"]
            },
            "bass": {
                "wave": "triangle",
                "volume": 0.25,
                "length": "1/4",
                "notes": ["C3", "-", "G2", "-"]
            }
        }
    }
}

A channel may declare instrument inline or as an explicit reference such as /music/instruments:lead_square. Instruments use the same source and tone model as sounds, plus play and range. In this first implementation, legato, glide, and stereo width are loaded and validated but are prepared for later audible behavior. play.vibrato and tone.space.echo already affect generated music.

For very simple channels, wave may still be declared directly on the channel. FLX treats it as instrument.source.wave.

Each channel may declare its own length. If omitted, FLX uses 1/4. Accepted values are 1/1, 1/2, 1/4, 1/8 and 1/16. At tempo 120, 1/4 lasts 0.5 seconds, 1/8 lasts 0.25 seconds and 1/16 lasts 0.125 seconds.

- is silence. In a noise channel, x is a noise hit. Channels keep their JSON declaration order; if a song declares more channels than the Audio Chip exposes as voices.music, the extra channels are ignored with a warning.

States

The optional states block declares a lightweight state machine owned by the object. JSON defines only the state names and valid transitions; scripts decide when transitions happen.

states
"states": {
    "initial": "title",

    "title": {
        "next": ["playing"]
    },

    "playing": {
        "next": ["gameover", "next_level"]
    },

    "gameover": {
        "next": ["title"]
    }
}
states (reference)
"states": "logic/game_states"

Use state_to(object, "playing") to request a transition. Invalid declarations fail during compilation. Invalid runtime transitions are ignored and logged as warnings.

When states is present, initial is required and must name a declared state. A state with no next list, or with an empty one, is terminal. Cycles are valid. A self-transition is valid only when the state explicitly includes itself in next.

JSON Composition (like)

FLX allows JSON definitions to be reused through the like field.

This feature makes it possible to build new configurations from existing ones while overriding only the required fields.

like
{"like": "asteroid/deep_space",

"origin": {
    "x": 5,
    "y": 5
}
 

}

The runtime first loads the definition referenced by like and then overrides the fields declared in the current JSON.

Composition is performed recursively, allowing only the necessary parts to be modified.

Fields

  • like: path to the base definition used for composition.

Important: like does not implement inheritance.

Its purpose is to reuse and compose data.

Object JSON

A object defines a group of objects. It is not rendered visually but may contain logic.

tofu.json
{
    "$schema": "https://flxforge.github.io/FLXEngine/schemas/object.schema.json",

    "collision": {
        "type": "box"
    },

    "children": {
        "laser": {
            "like": "objects/laser",
            "spawn": "manual"
        }
    }
}

Fields

  • $schema: schema path used for validation. [ Optional ]
  • collision: collision configuration associated with the object. [ Optional ]
  • children: child objects loaded with this object. [ Optional ]
  • manual children: children created later with spawn(). [ Optional ]
  • attach: rules used when the object follows its original parent. [ Optional ]
  • sounds: sound declarations owned by this object. [ Optional ]
  • music: generated music declarations owned by this object. [ Optional ]
  • states: lightweight state machine declaration. [ Optional ]

Object Capabilities

A object file defines an object that can be rendered visually.

An object may also be used as a logical controller without visual data.

If no visual information is defined, the object will still exist within the runtime but will not be rendered on screen.

tofu.json
{
    "$schema": "https://flxforge.github.io/FLXEngine/schemas/object.schema.json",    "origin": {
        "x": 157,
        "y": 87
    },

    "shape": {
        "type": "triangle",
        "color": "white",
        "size": {
            "width": 18,
            "height": 24
        }
    },

    "mechanics": {
      "type": "polar",
      "motion": {
        "speed": { "start": 0, "limit": 180 },
        "acceleration": 120,
        "inertia": 0.99
      },
      "rotation": {
        "speed": 180
      }
    },

    "bounds": {
      "mode": "wrap",
      "overflow": true
    },

    "children": {
        "laser": {
            "like": "objects/laser",
            "spawn": "manual",
            "offset": {
                "x": 0,
                "y": -12
            }
        }
    },

    "group": "paddle",
    "role": "player",

    "collision": {
      "type": "circle",
        "radius": 16
    },

    "behavior": {
        "scripts": [ "tofu" ]
    }
}

Fields

  • $schema: schema path used for validation. [ Optional ]
  • origin: object's initial position. [ Optional ]
  • shape: object's visual information. [ Optional ]
  • mechanics: movement and rotation rules, if any. [ Optional ]
  • inherit: live state inherited from the parent at creation time or while linked. [ Optional ]
  • bounds: object behavior when reaching screen boundaries. [ Optional ]
  • manual children: children created later with spawn(). [ Optional ]
  • attach: rules used when the object follows its original parent. [ Optional ]
  • sounds: sound declarations owned by this object. [ Optional ]
  • music: generated music declarations owned by this object. [ Optional ]
  • states: lightweight state machine declaration. [ Optional ]
  • control: optional input subject binding for this object. [ Optional ]
  • group: logical group associated with the object. [ Optional ]
  • role: optional role inside the object's group. [ Optional ]
  • collision: collision configuration associated with the object. [ Optional ]
  • behavior: scripts associated with the object. [ Optional ]

control.player binds an object to a player index. That lets scripts call input_down(object, ...) without hard-coding player(1) in behavior code.

group classifies what kind of object it is for collisions and queries. role refines the concrete purpose of that object inside the same group. For example, Pong can use group: "wall" with role: "top" or role: "bottom", without creating artificial groups such as wall_top and wall_bottom.

Attach

Defines how an object follows its original parent while it is attached. Attach never changes parent and never creates dynamic hierarchies.

attach
"attach": {
    "born": true,
    "position": true,
    "angle": false
}

Fields

  • born: starts the object attached when true. [ Optional, default false ]
  • position: follows parent X and Y. [ Optional ]
  • x: follows parent X. If declared, it overrides position for this axis. [ Optional ]
  • y: follows parent Y. If declared, it overrides position for this axis. [ Optional ]
  • angle: synchronizes the parent angle without rotating the offset. [ Optional ]

The runtime uses the original parent and the original offset captured when the object was created. The object starts detached unless born is declared as true.

Origin

Defines the object's initial position within the runtime.

origin
"origin": {
    "x": 157,
    "y": 87
}

Fields

  • x: X coordinate (relative to the coordinate system origin, top-left corner). [ Required ]
  • y: Y coordinate (relative to the coordinate system origin, top-left corner). [ Required ]

Shape

Defines the object's basic visual representation.

shape
"shape": {
    "type": "triangle",
    "color": "white",
    "size": {
        "width": 18,
        "height": 24
    }
}
text shape
"shape": {
    "type": "text",
    "content": "ARKANOID",
    "color": "white",
    "mode": "fill",
    "size": {
        "width": 260,
        "height": 60
    }
}

Fields

  • type: shape type to render. [ Optional ]
    • block: default solid block. Rotation mechanics are not applied.
    • rectangle: rectangle with support for rotation and oriented movement.
    • triangle: triangle with support for rotation and oriented movement.
    • circle: circle with support for rotation and oriented movement.
    • polygon: polygon defined by a list of points.
    • line: line defined by two points.
    • text: renderable text.
  • mode: rendering mode used to draw the shape. [ Optional ]
    • fill: the shape is rendered filled using the specified color.
    • outline: only the outline is rendered using the specified color.
  • content: visible string used when type is text. [ Optional ]
  • color: object color. [ Optional ]
  • layer: object draw order in the current world renderer. Lower values are drawn first. Objects with the same layer keep creation order. It is not a global video-layer system. [ Optional, default 0 ]
  • size: object size. [ Optional ]

A text shape is a world object. It uses origin, angle, bounds, collision and behavior like any other object. The engine calculates a font size that fits inside the logical size box.

With mode: "outline", text is drawn first in the selected color and then again in black at a smaller proportional size, leaving the selected color as the outline.

Size

Defines the object's size.

size
"size": {
    "width": 18,
    "height": 24
}

Fields

  • width: object width in pixels.
  • height: object height in pixels.

Polygon

Polygons allow irregular shapes to be defined using a list of local points.

polygon
"shape": {
    "type": "polygon",
    "color": "white",

 
"points": [
    { "x": 0, "y": -16 },
    { "x": 12, "y": -8 },
    { "x": 16, "y": 8 },
    { "x": -8, "y": 14 }
]
 

}

Each point is defined in local coordinates relative to the object's origin.

Mechanics

Defines movement and rotation rules. Mechanics is declarative: scripts apply intent through functions such as move_horizontal(), move_vertical(), advance(), accelerate() and rotate().

mechanics
"mechanics": {
    "type": "polar",
    "motion": {
        "speed": {
            "start": 90,
            "limit": 150
        },
        "acceleration": 120,
        "inertia": 0.99,
        "step": 0,
        "diagonal": "independent"
    },
    "rotation": {
        "angle": 45,
        "speed": 180,
        "acceleration": 0,
        "inertia": 0,
        "step": 0
    }
}

Fields

  • type: direct or polar. Default is direct.
  • motion.speed: number shorthand or object with start and limit. A limit of 0 means unlimited.
  • motion.acceleration: temporal acceleration rate. Default is 0.
  • motion.inertia: normalized persistence from 0 to 1. Default is 0.
  • motion.step: movement quantization. 0 means continuous.
  • motion.diagonal: independent or vector.
  • motion.horizontal and motion.vertical: optional per-axis overrides for speed, acceleration, inertia and step.
  • rotation.angle: initial live angle in degrees.
  • rotation.speed: rotation speed as number shorthand or { "start", "limit" }.
  • rotation.acceleration, rotation.inertia and rotation.step: rotational equivalents of the motion fields.

Inherit

Defines which live state a child receives from its original parent. It does not inherit declarative mechanics rules.

inherit
"inherit": {
    "creation": {
        "angle": "copy",
        "velocity": "compose"
    },
    "live": {
        "angle": "copy"
    }
}

Fields

  • creation.angle = "copy": copies the parent angle when the child is created.
  • creation.velocity = "copy": copies the parent live linear velocity when the child is created.
  • creation.velocity = "compose": adds the parent live linear velocity to the child's own linear velocity when it is created, without modifying its declared polar speed.
  • live.angle = "copy": keeps the child angle synchronized with the original parent.

Bounds

Defines the object's behavior when reaching screen boundaries.

bounds
"bounds": {
    "mode": "wrap",
    "overflow": true
},

Fields

  • mode: boundary behavior mode. [ Optional ]
    • none: no special behavior.
    • wrap: when reaching a boundary, the object appears on the opposite side while preserving its direction.
  • overflow: controls how boundary behavior is applied. [ Optional ]
    • true: the object begins appearing on the opposite side while progressively disappearing from the current side.
    • false: the object immediately reappears when reaching the boundary.

Manual Children

Manual children are declared inside children with spawn: "manual". They do not enter the world when the parent is loaded; scripts create them with spawn().

manual child
"children": {
    "laser": {
        "like": "ship/laser",
        "spawn": "manual",
        "offset": {
            "x": 0,
            "y": -12
        }
    }
}

The optional offset is local to the spawning object and uses the object's current rotation as reference.

If the parent uses creation.mode = "grid", spawn(parent, "child") follows the grid policy instead of creating one free instance. It creates every matching grid cell for that child.

Collision

Defines the collision associated with the object.

The collision(object, other) function is only executed when collision.active is set to true and the other object's group is included in collision.with.

Only active objects execute collision(object, other).

Objects listed in collision.with do not automatically execute their own collision handler unless they are also active and independently detect a matching collision.

collision
"collision": {
    "type": "circle",
    "active": "true",
    "with": [ "wall" ],
    "radius": 16
},

Fields

  • type: collision type. [ Optional ]
    • none: no collision. [ default ]
    • box: box collision.
    • circle: circular collision.
  • active: enables or disables collision processing for this object. [ Optional ]
  • with: list of groups this object can collide with. [ Optional ]
  • radius: collision radius when type is circle. [ Optional ]

Behavior

Defines the scripts associated with the object.

behavior
"behavior": {
    "scripts": [ "tofu" ]
}

Fields

  • scripts: list of JavaScript scripts associated with the object (file extension is not required). [ Required ]
