FLX Documentation

Cómo piensa FLX

Antes de aprender JSON, APIs o ciclos de vida, merece la pena comprender la idea central sobre la que está construido FLX.

FLX no intenta simplificar C++.

Intenta que el comportamiento del runtime pueda escribirse como script.

Mental model
Objetos -> Datos

Scripts -> Funciones

Runtime -> Conecta ambos

Los objetos contienen datos

Un objeto describe algo que existe dentro del runtime.

Puede tener posición, tamaño, velocidad, apariencia visual o cualquier otra propiedad.

Los objetos no contienen comportamiento.

Contienen estado.

Los scripts contienen funciones

Un script es un conjunto de funciones JavaScript.

Esas funciones describen qué ocurre con los objetos a lo largo de su vida.

Los scripts no pertenecen a los objetos.

Son recursos compartidos que pueden ser utilizados por muchos objetos simultáneamente.

ship.js
function action(ship) {
    accelerate(ship);
}

El runtime conecta ambos

Durante la ejecución, el runtime invoca funciones y les proporciona los objetos sobre los que deben trabajar.

Los scripts describen comportamiento.

Los objetos almacenan estado.

El runtime coordina la interacción entre ambos.

Estado compartido y estado individual

Un mismo script puede utilizarse desde cientos de objetos.

Esto significa que existen distintos ámbitos de información.

  • Ámbito de función
  • Ámbito de script
  • Ámbito de objeto
  • Ámbito global (futuro)

Comprender esta diferencia es una de las claves para comprender FLX.

Objetos vivos

FLX entiende los objetos como entidades que nacen, existen y desaparecen.

Lifecycle
born()

action()
motion()
collision()

kill()

dead()

cleanup()

Esta terminología no es accidental.

El ciclo de vida forma parte del modelo mental del runtime.
