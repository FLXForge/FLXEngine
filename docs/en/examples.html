FLX Documentation

Examples

FLX examples are not only visual demonstrations.

Each project exists to validate specific runtime systems, discover real-world problems and help define the engine architecture through practical use cases.

Each example represents a different stage in the evolution of FLX.

Complete

PONG

Two paddles. One ball. The beginning of everything.

Pong was the first example used to build the foundation of the runtime.

Although visually simple, it helped validate the lifecycle, basic movement, collisions, bouncing, scripting and the initial engine architecture.

What can be learned

  • Basic FLX project structure
  • Classic speed-based movement
  • Simple collisions
  • Input and scripting
  • Basic AI

In Development

Asteroids

Inertia, composition and survival in the void.

Asteroids represents the second major evolution phase of FLX.

While Pong helped validate the core architecture, Asteroids is helping define how objects are built, born, interact and disappear within the runtime.

This example has driven the creation of the complete lifecycle, prefabs, dynamic spawns, JSON composition through like, per-object local state and the engine's first polygonal shapes.

It is also helping validate the separation between visual representation and collision, allowing different collider types to coexist independently from the rendered shape.

More than a simple arcade clone, Asteroids has become the primary validation environment for FLX's current architecture.

What You Can Learn

  • Advanced motion system
  • Acceleration and inertia
  • FLX rotation and angular convention
  • Complete runtime lifecycle
  • Local state through object.local
  • Reusable spawns and prefabs
  • JSON composition through like
  • Point-defined polygons
  • Reusable spawners
  • Screen wrapping and boundary management
  • Separation between visual shape and collider
  • Collision visualization for debugging
  • circle and box colliders

Planned

ARKANOID

Bounces, power ups and emergent rules.

Arkanoid will be used to validate more complex systems related to state, levels and runtime control.

This example will help develop: timers, power ups, sound systems, spawn rules and dynamic state transitions.

What can be learned

  • State systems
  • Levels and progression
  • Power ups
  • Timers
  • Rule-based spawning
  • Sound management
