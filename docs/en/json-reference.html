FLX Documentation

JSON Reference

This section documents the project manifest and JSON structures used by FLX to define runtime objects and their properties.

FLX is under active development. Some fields may change during 0.x versions.

Project Files

FLX separates project metadata from world data.

  • .flx: defines project metadata and runtime configuration.
  • object: defines an object that may contain other elements.
  • object: defines objects that can be rendered visually.

FLX Manifest

The .flx file is a properties-style manifest. It points to the root object and contains runtime configuration.

game.flx
name=Asteroids
version=1.0.0
engine=0.2.0
path=asteroids
root=space
title=Asteroids
screen.width=640
screen.height=320
screen.scale=3
debug.collisions=false
debug.logs=false
notes=FLX example with spawn and basic UI

Fields

  • name: project name. [ Optional ]
  • version: project version. [ Optional ]
  • engine: target FLX version. [ Optional ]
  • path: project content directory. [ Optional ]
  • root: root JSON object loaded by the runtime. [ Required ]
  • title: window title. [ Optional ]
  • screen.width: internal reference width. [ Optional ]
  • screen.height: internal reference height. [ Optional ]
  • screen.scale: scale factor applied to rendering. [ Optional ]
  • debug.collisions: enables collision debug drawing. [ Optional ]
  • debug.logs: enables internal debug logs. [ Optional ]
  • notes: free project notes. [ Optional ]

Root Object

The root object is special only because the manifest points to it. Its JSON uses the same schema as any other FLX object.

space.json
{
    "$schema": "https://flxforge.github.io/FLXEngine/schemas/object.schema.json",    "behavior": {
        "scripts": [ "scripts/game" ]
    },

    "children": {
        "level": "space/level"
    }
}

Children

The children field declares objects contained by another object.

children (reference)
"children": {
    "ball": "objects/ball"
}
children (inline)
"children": {
    "ship": {
        "like": "ship/ship",
        "origin": { "x": 160, "y": 90 }
    }
}
children (manual)
"children": {
    "laser": {
        "like": "ship/laser",
        "spawn": "manual",
        "offset": { "x": 0, "y": -14 }
    }
}

Each key in children is the logical instance name. A string value is syntactic sugar for an object with like.

Children use spawn: "auto" by default. That first instance enters the runtime with its parent. Children with spawn: "manual" wait until a script calls spawn(parent, "child"). The same function can also create another instance of an auto child later.

children defines what may exist, spawn defines when each child enters the runtime, and creation defines how the parent materializes those children.

Creation

The optional creation block controls how a parent creates its declared children. If it is omitted, FLX uses creation.mode = "individual".

individual creation
"creation": {
    "mode": "individual"
}
grid creation with linear pattern
"children": {
    "a": { "like": "brick_red" },
    "b": { "like": "brick_blue", "spawn": "manual" }
},
"creation": {
    "mode": "grid",
    "rules": {
        "rows": 2,
        "columns": 3,
        "cellWidth": 32,
        "cellHeight": 16
    },
    "pattern": ["a", "b"]
}
grid creation with row pattern
"creation": {
    "mode": "grid",
    "rules": {
        "rows": 2,
        "columns": 3,
        "cellWidth": 32,
        "cellHeight": 16
    },
    "pattern": [
        ["a"],
        ["b"]
    ]
}

In grid mode, the parent position is the grid origin. Each cell uses column * cellWidth and row * cellHeight. The child offset is applied inside the cell and the child origin is ignored.

A linear pattern is consumed in row-major order and repeats when it ends. A row pattern repeats its outer rows and each inner row repeats its columns. Manual children inside a grid do not appear automatically; calling spawn(parent, "child") creates every grid cell where the pattern references that child.

Sounds

The sounds field declares sounds owned by an object. Scripts can play them with play_sound(object, "id").

sounds
"sounds": {
    "beep": {
        "wave": "square",
        "frequency": 880,
        "duration": 0.08,
        "volume": 0.7
    }
}
sounds (reference)
"sounds": {
    "beep": "audio/beep"
}

Supported waves are square, sine, triangle, saw and noise.

Sound declarations are data. They can be inline, referenced as a JSON file, or composed with like.

States

The optional states block declares a lightweight state machine owned by the object. JSON defines only the state names and valid transitions; scripts decide when transitions happen.

states
"states": {
    "initial": "title",

    "title": {
        "next": ["playing"]
    },

    "playing": {
        "next": ["gameover", "next_level"]
    },

    "gameover": {
        "next": ["title"]
    }
}
states (reference)
"states": "logic/game_states"

Use state(object, "playing") to request a transition. Invalid transitions are ignored and logged as warnings.

JSON Composition (like)

FLX allows JSON definitions to be reused through the like field.

This feature makes it possible to build new configurations from existing ones while overriding only the required fields.

like
{"like": "asteroid/deep_space",

"origin": {
    "x": 5,
    "y": 5
}
 

}

The runtime first loads the definition referenced by like and then overrides the fields declared in the current JSON.

Composition is performed recursively, allowing only the necessary parts to be modified.

Fields

  • like: path to the base definition used for composition.

Important: like does not implement inheritance.

Its purpose is to reuse and compose data.

Object JSON

A object defines a group of objects. It is not rendered visually but may contain logic.

tofu.json
{
    "$schema": "https://flxforge.github.io/FLXEngine/schemas/object.schema.json",

    "collision": {
        "type": "box"
    },

    "children": {
        "laser": {
            "like": "objects/laser",
            "spawn": "manual"
        }
    }
}

Fields

  • $schema: schema path used for validation. [ Optional ]
  • collision: collision configuration associated with the object. [ Optional ]
  • children: child objects loaded with this object. [ Optional ]
  • manual children: children created later with spawn(). [ Optional ]
  • attach: rules used when the object follows its original parent. [ Optional ]
  • sounds: sound declarations owned by this object. [ Optional ]
  • states: lightweight state machine declaration. [ Optional ]

Object Capabilities

A object file defines an object that can be rendered visually.

An object may also be used as a logical controller without visual data.

If no visual information is defined, the object will still exist within the runtime but will not be rendered on screen.

tofu.json
{
    "$schema": "https://flxforge.github.io/FLXEngine/schemas/object.schema.json",    "origin": {
        "x": 157,
        "y": 87
    },

    "shape": {
        "type": "triangle",
        "color": "white",
        "size": {
            "width": 18,
            "height": 24
        }
    },

    "motion": {
      "rotationSpeed": 180,
      "acceleration": 120,
      "inertia": 0.99,
      "maxSpeed": 180
    },

    "bounds": {
      "mode": "wrap",
      "overflow": true
    },

    "children": {
        "laser": {
            "like": "objects/laser",
            "spawn": "manual",
            "offset": {
                "x": 0,
                "y": -12
            }
        }
    },

    "group": "paddle",

    "collision": {
      "type": "circle",
        "radius": 16
    },

    "behavior": {
        "scripts": [ "tofu" ]
    }
}

Fields

  • $schema: schema path used for validation. [ Optional ]
  • origin: object's initial position. [ Optional ]
  • shape: object's visual information. [ Optional ]
  • motion: movement configuration, if any. [ Optional ]
  • bounds: object behavior when reaching screen boundaries. [ Optional ]
  • manual children: children created later with spawn(). [ Optional ]
  • attach: rules used when the object follows its original parent. [ Optional ]
  • sounds: sound declarations owned by this object. [ Optional ]
  • states: lightweight state machine declaration. [ Optional ]
  • group: logical group associated with the object. [ Optional ]
  • collision: collision configuration associated with the object. [ Optional ]
  • behavior: scripts associated with the object. [ Optional ]

Attach

Defines how an object follows its original parent while it is attached. Attach never changes parent and never creates dynamic hierarchies.

attach
"attach": {
    "born": true,
    "position": true,
    "angle": false
}

Fields

  • born: starts the object attached when true. [ Optional, default false ]
  • position: follows parent X and Y. [ Optional ]
  • x: follows parent X. If declared, it overrides position for this axis. [ Optional ]
  • y: follows parent Y. If declared, it overrides position for this axis. [ Optional ]
  • angle: synchronizes the parent angle without rotating the offset. [ Optional ]

The runtime uses the original parent and the original offset captured when the object was created. The object starts detached unless born is declared as true.

Origin

Defines the object's initial position within the runtime.

origin
"origin": {
    "x": 157,
    "y": 87
}

Fields

  • x: X coordinate (relative to the coordinate system origin, top-left corner). [ Required ]
  • y: Y coordinate (relative to the coordinate system origin, top-left corner). [ Required ]

Shape

Defines the object's basic visual representation.

shape
"shape": {
    "type": "triangle",
    "color": "white",
    "size": {
        "width": 18,
        "height": 24
    }
}
text shape
"shape": {
    "type": "text",
    "content": "ARKANOID",
    "color": "white",
    "mode": "fill",
    "size": {
        "width": 260,
        "height": 60
    }
}

Fields

  • type: shape type to render. [ Optional ]
    • block: default solid block. Rotation mechanics are not applied.
    • rectangle: rectangle with support for rotation and oriented movement.
    • triangle: triangle with support for rotation and oriented movement.
    • circle: circle with support for rotation and oriented movement.
    • polygon: polygon defined by a list of points.
    • line: line defined by two points.
    • text: renderable text.
  • mode: rendering mode used to draw the shape. [ Optional ]
    • fill: the shape is rendered filled using the specified color.
    • outline: only the outline is rendered using the specified color.
  • content: visible string used when type is text. [ Optional ]
  • color: object color. [ Optional ]
  • layer: draw order. Lower values are drawn first. Objects with the same layer keep creation order. [ Optional, default 0 ]
  • size: object size. [ Optional ]

A text shape is a world object. It uses origin, angle, bounds, collision and behavior like any other object. The engine calculates a font size that fits inside the logical size box.

With mode: "outline", text is drawn first in the selected color and then again in black at a smaller proportional size, leaving the selected color as the outline.

Size

Defines the object's size.

size
"size": {
    "width": 18,
    "height": 24
}

Fields

  • width: object width in pixels.
  • height: object height in pixels.

Polygon

Polygons allow irregular shapes to be defined using a list of local points.

polygon
"shape": {
    "type": "polygon",
    "color": "white",

 
"points": [
    { "x": 0, "y": -16 },
    { "x": 12, "y": -8 },
    { "x": 16, "y": 8 },
    { "x": -8, "y": 14 }
]
 

}

Each point is defined in local coordinates relative to the object's origin.

Motion

Defines properties related to object movement.

motion
"motion": {
    "inherit": "creation",
    "speed": 90,
    "angle": 45,
    "rotationSpeed": 180,
    "acceleration": 120,
    "inertia": 0.99,
    "maxSpeed": 180
}

Fields

  • inherit: defines how the spawned object inherits movement. [ Optional ]
    • none: does not inherit movement.
    • creation: inherits the initial movement at spawn time.
  • speed: movement speed used by helpers such as advance().
  • angle: movement and rotation angle in degrees.
  • rotationSpeed: rotation speed.
  • acceleration: acceleration applied to the object.
  • inertia: movement preservation factor.
  • maxSpeed: maximum speed.

Bounds

Defines the object's behavior when reaching screen boundaries.

bounds
"bounds": {
    "mode": "wrap",
    "overflow": true
},

Fields

  • mode: boundary behavior mode. [ Optional ]
    • none: no special behavior.
    • wrap: when reaching a boundary, the object appears on the opposite side while preserving its direction.
  • overflow: controls how boundary behavior is applied. [ Optional ]
    • true: the object begins appearing on the opposite side while progressively disappearing from the current side.
    • false: the object immediately reappears when reaching the boundary.

Manual Children

Manual children are declared inside children with spawn: "manual". They do not enter the world when the parent is loaded; scripts create them with spawn().

manual child
"children": {
    "laser": {
        "like": "ship/laser",
        "spawn": "manual",
        "offset": {
            "x": 0,
            "y": -12
        }
    }
}

The optional offset is local to the spawning object and uses the object's current rotation as reference.

If the parent uses creation.mode = "grid", spawn(parent, "child") follows the grid policy instead of creating one free instance. It creates every matching grid cell for that child.

Collision

Defines the collision associated with the object.

The collision(object, other) function is only executed when collision.active is set to true and the other object's group is included in collision.with.

Only active objects execute collision(object, other).

Objects listed in collision.with do not automatically execute their own collision handler unless they are also active and independently detect a matching collision.

collision
"collision": {
    "type": "circle",
    "active": "true",
    "with": [ "wall" ],
    "radius": 16
},

Fields

  • type: collision type. [ Optional ]
    • none: no collision. [ default ]
    • box: box collision.
    • circle: circular collision.
  • active: enables or disables collision processing for this object. [ Optional ]
  • with: list of groups this object can collide with. [ Optional ]
  • radius: collision radius when type is circle. [ Optional ]

Behavior

Defines the scripts associated with the object.

behavior
"behavior": {
    "scripts": [ "tofu" ]
}

Fields

  • scripts: list of JavaScript scripts associated with the object (file extension is not required). [ Required ]
